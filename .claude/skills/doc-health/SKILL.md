## 왜 이 스킬이 있나

문서 = 어시스턴트의 장기기억인데, **문서도 부패한다**. 해결된 이슈가 "미해결"로 남아 감사가 허위 재발견을 하고(반성문 #63-④ 문서-현실 드리프트), 낡은 정보를 믿고 일하면 사고가 난다. 사람(PO)이 아니라 이 루틴이 주 1회 잡는다. (2026-07-05 PO 승인)

## 검진 대상 (살아있는 문서 — 이 목록 밖 archive/·계획서류는 건드리지 마라)

- `CLAUDE.md` / `DESIGN.md`
- `docs/PROJECT_CONTEXT.md` (최상단 핸드오프 2~3블록만)
- `docs/KNOWN_ISSUES.md`
- `docs/PO_PREFERENCES.md` (활성 취향)
- `docs/LAUNCH_GATES_PO.md`
- `docs/POSTMORTEMS.md` (최근 5건 + 🔁 재발 집계)
- `docs/TEST_ACCOUNTS.md`
- `docs/KHIDI_중간보고_베이스.md` (§일정·성과지표 부분)
- `src/lib/manuals/index.js` (백오피스 설명서 — `updated` 날짜가 해당 화면 최근 변경보다 심하게 뒤처졌는지)

## 검사 항목 (각각 실제 근거 대조 — 문서만 읽고 판단 금지)

1. **문서 간 모순**: 같은 사실을 두 문서가 다르게 서술 (예: 한쪽은 "비활성", 다른 쪽은 "운영 중").
2. **문서-현실 드리프트**: "미해결·예정·대기"로 남은 항목이 실제론 이미 해결/변경됨 — `git log --oneline --since` + 해당 코드/화면을 실제 확인해 대조. 반대 방향(문서엔 "해결"인데 코드에 없음)도 확인.
3. **죽은 참조**: 문서가 가리키는 파일 경로·npm 스크립트·라우트가 실제 존재하는지 (`ls`/`grep`/`package.json` 대조).
4. **기한 지난 항목**: "MM/DD까지"·"~요일 확인" 류가 이미 지났는데 결과 기록이 없는 것.
5. **반성문 재발률 집계**: `POSTMORTEMS.md`의 「🔁 재발」 표시 개수 ÷ 전체 건수. 재발 건은 뚫린 가드가 보강됐는지 확인.

## 처리 원칙

- **사실 교정**(이미 해결된 항목 닫기, 죽은 참조 수정, 날짜 현행화) → 직접 고쳐서 PR (문서만 = 저위험 자동머지 대상).
- **판단 필요**(방향이 바뀐 건지, 항목을 버릴 건지) → 고치지 말고 `AskUserQuestion` 버튼으로 PO에게 (한 번에 최대 2~3건만 — 몰아서 다 물으면 PO가 안 누른다).
- 확신 없는 건 건드리지 말고 로그에 "확인 필요"로만 남겨라.

## 마무리 (필수)

`docs/audit/DOC_HEALTH_LOG.md` **최상단**에 엔트리 추가:

```
## YYYY-MM-DD 검진
- 스캔: N개 문서 / 발견: 모순 N·드리프트 N·죽은참조 N·기한경과 N
- 교정: (고친 것 1줄씩) / 보류: (PO 판단 대기)
- 반성문 재발률: N/NN건 (🔁 표시 기준)
```

이 날짜를 세션 시작 훅(`session-orient.sh`)이 읽어 7일 지나면 리마인드한다 — **로그를 안 남기면 검진이 안 된 것으로 취급된다.**

보고는 3줄 요약(발견/교정/보류)으로 짧게.
