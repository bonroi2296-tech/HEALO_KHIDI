## 현재 상태 (자동 수집)
- 브랜치: !`git rev-parse --abbrev-ref HEAD`
- 최근 커밋 8개: !`git log --oneline -8`
- 미커밋 변경: !`git status --short`
- 최근 5커밋에서 바뀐 파일: !`git diff --name-only HEAD~5 2>/dev/null | head -25`
- 직전 핸드오프 이후 커밋: !`git rev-list --count $(git log -1 --format=%H --grep=핸드오프 2>/dev/null)..HEAD 2>/dev/null`

## 할 일

위 git 상태 + 이번 세션 대화를 근거로, **`docs/PROJECT_CONTEXT.md` 최상단에 새 핸드오프 블록을 추가(또는 갱신)**하라.

⚠️ **새 핸드오프 파일을 만들지 마라.** `PROJECT_CONTEXT.md`가 단일 진실 공급원(single source of truth)이다. 흩어진 핸드오프는 다음 세션을 혼란시킨다(과거 사고 원인).

핸드오프 블록은 다음 7개 섹션으로:

1. **이번 세션 한 일** — 기능/파일 단위 + 배포·머지·PR 상태(번호 포함)
2. **왜 그렇게 했는지** — 커밋 메시지에 안 남는 결정 배경·근거
3. **안 끝났거나 보류** — 무엇 / 왜 보류 / 풀리려면 뭐가 필요
4. **주의·함정** — 반쯤 하다 만 것, 건드리면 깨지는 것, 헷갈리기 쉬운 것
5. **다음 세션이 먼저 할 일** — 우선순위 순서로
6. **검증 상태** — CI/빌드/check:content 통과 여부. **검증 못 한 건 솔직히 "검증 못 함"이라 명시**(됐어요 남발 금지)
7. **다음 세션 첫 프롬프트** — PO가 다음 세션 시작 시 **그대로 복붙할 수 있는 지시문**을 인용블록(>)으로 1개. 5번(먼저 할 일)을 PO 말투의 명령형으로 압축 + "먼저 PROJECT_CONTEXT 최상단 읽어"를 첫 줄에. PO가 비개발자라 매번 "뭐라고 시키지?"를 고민 안 하게 — 핸드오프가 끝나면 이 복붙용 프롬프트를 채팅에도 그대로 보여줘라.

### ⚠️ A. 미검증 항목 자동 승격 (필수)
6번(검증 상태)에 **"런타임 미검증 / 직접 클릭 안 함 / 검증 못 함"** 으로 적은 게 있으면,
그것들을 **5번(다음 세션이 먼저 할 일)의 1번 항목**으로 끌어올려라 — *"⚠️ 직전 미검증분 먼저 확인: …"* 형태로.
이유: 미검증이 다음 세션에서 묻히는 게 가장 흔한 사고. 검증 부채는 맨 위에서 갚는다.

### 🎯 G. PO 취향·선호 누적 (필수 — 이번 대화 분석)
이번 세션 대화에서 **PO가 드러낸 취향·선호·성향**(고정 규칙 CLAUDE.md엔 아직 없는 것)을 찾아내라. 예:
- 특정 디자인/카피/이미지에 대한 호불호("이건 별로", "이게 낫다")
- 일하는 방식 선호(옵션 나열 vs 추천 1개, 설명 길이, 확인 빈도)
- "일단 됐다 / 그건 나중 / 이건 중요" 같은 우선순위·종료 신호
- 반복적으로 강조하거나 짜증낸 지점

찾았으면 **`docs/PO_PREFERENCES.md`의 「활성 취향」(`<!-- ACTIVE:START -->`~`END`) 안에 날짜와 함께 1건씩 추가/갱신**하라.
- **중복 금지**: 이미 있는 항목이면 새로 적지 말고, 더 구체화됐을 때만 갱신.
- **고정 규칙과 분리**: CLAUDE.md/말투훅에 이미 있는 건 적지 마라(중복).
- **승격**: 같은 취향이 3회 이상 확정되면 한 줄로 "→ CLAUDE.md 승격 후보"라 표시(다음에 사람이 올림).
- 새 취향이 없으면 건드리지 마라(억지로 만들지 말 것).

### E. PR·CI 상태 자동 수집 (6번 보강)
6번(검증 상태)을 적을 때, **열린 PR과 CI(자동검사) 통과 여부를 기억에 의존하지 말고 확인**해 적어라.
GitHub MCP 도구(`list_pull_requests`, `pull_request_read`로 CI status)를 쓸 수 있으면 열린 PR 번호·CI 초록 여부를 사실대로 기재. 못 쓰는 환경이면 "PR/CI 상태 미확인"이라 솔직히 표기.

규칙:
- 날짜는 **절대 표기**(상대 표기 금지 — "어제" X, "2026-06-17" O).
- PO는 비개발자 → **쉬운 한국어 + 용어 병기**(합치기=머지, 작업본=브랜치 등).
- 기존 최상단 핸드오프가 이미 있으면, 날짜가 더 최신인 새 블록을 그 위에 추가한다(과거 블록은 보존).

### F. 마무리 검사·회전 (필수 — 다 쓴 뒤)
핸드오프 블록을 다 쓰면 **반드시 아래 2개를 돌려라**:
1. `npm run check:handoff` — 7칸·절대날짜·상대표기 자동 검사. 실패하면 고쳐서 통과시킨다.
2. `npm run handoff:rotate` — 핸드오프가 3개 이상 쌓였으면 가장 오래된 걸 `docs/archive/`로 자동 보관(본문 군살 방지). 2개 이하면 자동으로 아무것도 안 함.

다 끝나면 **변경 요약 3줄만** 채팅에 보고(핸드오프 갱신/PO취향 추가분/검사·회전 결과).

### H. ⭐ 마지막 출력 = 복붙 프롬프트 (필수·절대 생략 금지)
**핸드오프 응답의 맨 끝**에는, 7번 섹션에 쓴 **"다음 세션 첫 프롬프트"를 인용블록(>)으로 채팅에 그대로 다시 띄워라.**
- 이건 PR 머지·CI 대기 등 다른 후속 동작이 있어도 **건너뛰지 마라.** PO가 매번 직접 짚는 일이 반복돼 이 규칙이 생겼다(2026-06-19).
- 위치: 그 응답의 **가장 마지막 블록**(PO가 스크롤 안 해도 바로 복사하게). "이거 다음 세션에 그대로 붙여" 한 줄 + 인용블록.
- 핸드오프가 여러 턴(머지 대기 등)에 걸쳐 끝나면, **최종 "마무리됐다"고 말하는 그 응답**에 반드시 포함.
