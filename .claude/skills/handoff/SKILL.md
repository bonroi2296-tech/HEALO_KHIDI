## 현재 상태 (자동 수집)
- 브랜치: !`git rev-parse --abbrev-ref HEAD`
- 최근 커밋 8개: !`git log --oneline -8`
- 미커밋 변경: !`git status --short`
- 최근 5커밋에서 바뀐 파일: !`git diff --name-only HEAD~5 2>/dev/null | head -25`

## 할 일

위 git 상태 + 이번 세션 대화를 근거로, **`docs/PROJECT_CONTEXT.md` 최상단에 새 핸드오프 블록을 추가(또는 갱신)**하라.

⚠️ **새 핸드오프 파일을 만들지 마라.** `PROJECT_CONTEXT.md`가 단일 진실 공급원(single source of truth)이다. 흩어진 핸드오프는 다음 세션을 혼란시킨다(과거 사고 원인).

핸드오프 블록은 다음 6개 섹션으로:

1. **이번 세션 한 일** — 기능/파일 단위 + 배포·머지·PR 상태(번호 포함)
2. **왜 그렇게 했는지** — 커밋 메시지에 안 남는 결정 배경·근거
3. **안 끝났거나 보류** — 무엇 / 왜 보류 / 풀리려면 뭐가 필요
4. **주의·함정** — 반쯤 하다 만 것, 건드리면 깨지는 것, 헷갈리기 쉬운 것
5. **다음 세션이 먼저 할 일** — 우선순위 순서로
6. **검증 상태** — CI/빌드/check:content 통과 여부. **검증 못 한 건 솔직히 "검증 못 함"이라 명시**(됐어요 남발 금지)

규칙:
- 날짜는 **절대 표기**(상대 표기 금지 — "어제" X, "2026-06-17" O).
- PO는 비개발자 → **쉬운 한국어 + 용어 병기**(합치기=머지, 작업본=브랜치 등).
- 기존 최상단 핸드오프가 이미 있으면, 날짜가 더 최신인 새 블록을 그 위에 추가한다(과거 블록은 보존).
- 다 쓰면 **변경 요약 3줄만** 채팅에 보고.
