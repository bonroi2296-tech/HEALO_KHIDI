## A. RAG 품질 (책 #2155) — 효과÷품 순
1. **프롬프트 규칙 2개** (코드 거의 0, 즉시·안전) — `generateReply.ts` 시스템 프롬프트에:
   - 답변 문장마다 **출처 강제표기**(`[출처N]`) → 환각↓·검증성↑.
   - 검색 무관 시 **"정보 없음 → 코디 연결"**(억지 답변 금지, 의료 안전 필수).
   - 근거: RAFT 패턴. 파인튜닝 없이 프롬프트만으로 차용.
2. **RAG 품질 자동평가 (LLM-judge)** — gemini로 답변을 **충실성(faithfulness=환각여부)·관련성·정확성·충분성** 1~5점. 샘플 50건 주간 배치. `rag_query_events`에 점수컬럼 확장. **KHIDI "AI 품질" 정성 근거 + 환각 모니터링.**
3. **크로스 인코더 리랭킹** (품질 향상 제일 큼) — `safeSearch.ts`에서 후보 `match_count` 4→12~20 확대 → `BAAI/bge-reranker-v2-m3`(다국어=우리 6개 언어 커버)로 재채점 → Top-3~4만 LLM에. 무거운 모델이라 **별도 추론 엔드포인트**(HF Inference API 등). **3-Tier 결과를 한 풀로 합쳐 리랭킹**하면 소스 우열을 의미기반 통합 정렬.
4. (나중, 2번 측정 후) **HyDE**(짧은 질의→가상답변 생성→그걸로 검색, aiGuard 상한 주의 조건부) / **청킹 overlap 100자** 추가(재인덱싱 1회) / **BGE-M3 다국어 임베딩** 교체 검토.

## B. 에이전트·운영·보안 (책 #19414)
- **MCP 토큰 폭탄 경고**: 같은 작업 CLI ~1.4K vs MCP ~44K 토큰(스키마 로딩). → **환자 대면 채팅엔 MCP 도구 스키마 직접 노출 금지.** 서버 API(service_role 경유)를 얇은 함수도구로 감싸 노출. MCP는 **어드민/내부 운영 에이전트에만.**
- **백그라운드 리뷰 → 자동 축적**: 우리 `consultation/[id]/summarize`가 출발점. 상담 종료 후 별도 잡이 요약 + 반복 질문 패턴을 재사용 절차로 축적(저장=Supabase+pgvector). 메인 흐름 막지 않는 **큐 분리**가 핵심.
- **3단계 점진 로딩**: 병원/암종 카탈로그를 통째로 컨텍스트에 넣지 말고 요약 인덱스(Level0)→필요 시 상세 fetch. gemini-flash 토큰비 절감.
- **보안 보강** (SECURITY_CHECKLIST와 대조):
  - **시크릿/PII 출력단 마스킹** — Vercel 로그·AI 응답에 환자 PII·키 누출 차단 레이어.
  - **프롬프트 인젝션 살균** — 환자가 붙여넣는 텍스트·업로드 문서가 시스템 프롬프트 오염 못 하게(`ignore previous instructions`·zero-width·숨김HTML 탐지).
  - **위험작업 승인 → 감사로그** — 어드민 환자정보 변경 등. KHIDI "ICT 체계 구축" 증빙으로도.
- **크론 + `[SILENT]` 패턴**: 유치전환 대시보드(`/admin/khidi/conversion`)에 **"목표 페이스 미달일 때만 알림"**. KHIDI 지표 자동 감시.
- **Kanban 멀티에이전트** — "멀티에이전트 도입 검토"의 결론: **작업이 독립 조각으로 잘 쪼개질 때만 이득.** 실시간 통역상담 X, **배치성에 적합**: 환자 N명 문서 번역·요약 / 카탈로그 6개 언어 정합성 검사 / 콘텐츠 잔재 전수스캔. 오케스트레이터=추론강한 모델, 워커=gemini-flash로 **모델 슬롯 분리**. 보드=Supabase 테이블 + 원자적 claim.
