## 3. 권리별 처리 방법
### 열람 (Art.15 / §35)
- 해당 user의 PII를 **복호화해서**(`*_encrypted` 컬럼은 AES-256-GCM) 정리해 본인에게 제공.
- 범위: 식별·연락정보, 건강정보, 상담·문의 이력, 동의 기록, 처리목적·보유기간·수신자(처리방침 §5 참조).

### 정정 (Art.16 / §36)
- 백오피스에서 해당 값 수정. 암호화 컬럼은 재암호화 저장. 병원에 이미 제공된 정보면 정정 사실을 수신처에도 통지.

### 삭제 / 탈퇴 / 동의철회 (Art.17 / §36) — **핵심**
1. [ ] **법정 보존의무 확인 먼저** — 결제·거래기록 5년(전자상거래법), 소비자분쟁 3년. 해당분은 **삭제 보류**(법적 근거로 보존), 본인에게 그 사유·기간 고지.
2. [ ] 보존의무 없는 PII → **익명화**: 이름·이메일·연락처·여권번호·건강정보 등 식별·민감 컬럼을 `NULL` 또는 `'[삭제됨]'`로. 통계·매칭 카운트용 비식별 레코드는 식별불가 형태로 남길 수 있음.
3. [ ] 계정 **비활성(ban)** 처리(`/admin/users`).
4. [ ] **제3자 제공분 통지**: 이미 병원·파트너에 넘어간 정보가 있으면 삭제 요청을 전달(가능 범위).
5. [ ] **완전 물리삭제를 명시 요구** + 법정 보존의무 없음 → **PO 승인 후** 하드삭제(되돌릴 수 없음, CLAUDE.md상 PO 확인 필수 항목).
6. [ ] 사후관리 중인 환자의 삭제 요청 = 관계 종료 의사 → 사후관리 중단하고 처리(본인 의사 우선).

> ⚠️ 지금은 전용 익명화 버튼이 없다. 실제 요청 시 **Supabase에서 해당 user의 PII 컬럼을 직접 익명화**(service_role)하고 결과를 기록한다. **요청이 반복되기 시작하면** `/admin/users`에 "정보삭제(익명화)" 액션을 추가한다(업그레이드 경로). — 그 전까진 수동이 충분(YAGNI).

### 처리정지 (Art.18 / §37)
- 마케팅·알림 등 해당 처리만 중단. 계정·기록은 유지.

### 이동 (Art.20)
- 본인 제공 데이터를 기계판독 형식(JSON/CSV)으로 내보내 제공.
