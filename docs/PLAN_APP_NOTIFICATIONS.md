# 기획 — 앱 알림 · 오프라인 · 알림 탭 이동 (2026-07-28)

> 남은 3건(KNOWN_ISSUES 3·5·6번)의 설계. **결론: 새로 만들 게 거의 없다.**

## 0. 진단 — 세 개가 아니라 한 가지 병이다

조사해보니 알림 체계는 **이미 완성돼 있다.**

| 이미 있는 것 | 어디 |
|---|---|
| 알림 저장소 | `notifications` 테이블 |
| 발신 함수 (다국어 문구·우선순위·이동주소 포함) | `src/lib/notifications/inApp.ts` `sendInAppNotification()` |
| 환자에게 가는 사건 정의 | `consultation_scheduled` · `consultation_invite` · `consultation_reminder` · `survey_request` · `followup_due` · `cost_estimate_issued` · `opinion_arrived` … |
| 폰 알림 기반 (토큰 등록·발송 함수) | `src/lib/push/registerPush.ts` · `src/lib/push/fcm.ts` · `device_tokens` |
| 정기 작업 6개 | 설문 발송 · 침묵환자 감지 · KPI · 자동화 … |

**빠진 건 딱 하나 — 이 둘이 서로 연결돼 있지 않다.** 앱내 알림은 쌓이는데 폰은 울리지 않는다.
`fcm.ts` 를 부르는 곳은 **테스트용 API 하나뿐**이다.

→ 그래서 기획의 핵심은 «무엇을 새로 알릴까» 가 아니라 **«이미 정해둔 알림을 폰까지 내보내는 선 하나를 잇는 것»** 이다.

## 1. 폰 알림 — 「한 곳에 얹기」

### 설계

`sendInAppNotification()` **안에서** 푸시도 같이 쏜다. 이 함수 하나만 고치면 위에 나열한 **모든 사건이 자동으로** 폰 알림이 된다. 호출부는 한 줄도 안 건드린다.

```
sendInAppNotification()
  ├─ notifications 테이블에 저장   (지금 있는 것)
  └─ 폰 알림 발송                  (새로 잇는 선)  ← 여기만 추가
```

### 무엇을 폰까지 보낼까 — 새 분류를 만들지 않는다

알림에는 **이미 `priority` 값이 있다**(`urgent` · `high` · `normal` · `low`). 새 목록을 만들면 사건이 늘 때마다 또 갱신해야 하고 반드시 빠뜨린다. 그래서:

| 우선순위 | 폰 알림 | 예 |
|---|---|---|
| `urgent` · `high` | **보냄** | 상담 예약됨 · 상담 곧 시작 · 의견서 도착 · 견적 발행 |
| `normal` · `low` | 앱 안 종 아이콘만 | 시스템 안내 · 통계 요약 |

직원용 알림(새 문의·AI 품질 등)은 **받는 사람이 직원 계정**이라 환자 폰에는 애초에 안 간다. 별도 차단 불필요.

### 조용 시간 — 의료 서비스라 반드시 필요

환자는 카자흐스탄·러시아에 있고 **한국보다 3~6시간 느리다.** 한국 낮에 보낸 알림이 현지 새벽일 수 있다.

- 수신자 **현지 22:00~08:00** 은 참았다가 아침 8시에 보낸다.
- **예외: `urgent`** (상담이 곧 시작 등)는 즉시.
- 현지 시각은 **사용할 언어로 추정**한다(전용 항목을 새로 만들지 않는다): `ru`→UTC+3 · `kz`→UTC+5 · `zh`→UTC+8 · `ja`·`ko`→UTC+9 · `en`→UTC+0.

### KHIDI 중간평가(8/27)와의 연결 — 이게 이 기획의 존재 이유

알림을 «기능»이 아니라 **점수**에 붙인다.

| 알림 | 무슨 일이 일어나나 | 어느 지표 |
|---|---|---|
| 상담 24시간 전 · 30분 전 | 안 나타나는 일이 줄어든다 | **사전상담·사후관리 120건** |
| 상담 끝난 직후 만족도 설문 | 응답 표본이 생긴다 (지금은 거의 0) | **환자 만족도 90점** |
| 의견서·견적·코디 답변 도착 | 기다리다 이탈하는 걸 막는다 | **외국인환자 유치 12건** |

### ⚠️ 먼저 확인할 것 — 리마인드가 실제로 도는지 불확실

`app/api/cron/consultation-reminders`(30분 전 알림)와 `dispatch-reminders` 는 **`vercel.json` 의 정기 실행 목록에 없다.**
`docs/CRON_STATUS.md` 는 이 둘을 **외부 스케줄러(cron-job.org)** 에 등록해 돌린다고 적어놨는데, 거기 적힌 주소가 **`healo-khidi.vercel.app`(2026-06-22 에 폐기한 옛 도메인)** 이다.

- 문서가 낡은 것일 수도, 정말 안 돌고 있는 것일 수도 있다. **어시는 그 계정을 볼 수 없다.**
- 만약 안 돌고 있다면 → **상담 리마인드가 아예 안 나가고 있다**는 뜻이고, 그게 노쇼의 숨은 원인일 수 있다.
- 해결 방향: 외부 스케줄러에 의존하지 말고 **`vercel.json` 정기 작업으로 옮긴다**(Pro 플랜이라 분 단위 가능). 그러면 주소 바뀔 때 같이 따라간다.

## 2. 오프라인 — 설정 1줄 + 화면 1장

지금은 인터넷이 끊기면 **하얀 화면**이다. 라이브 로드 구조라 보여줄 게 아무것도 없다.

앱 껍데기에 **`server.errorPath`** 라는 항목이 있다 — 「불러오기에 실패하면 이 로컬 파일을 대신 띄워라」. 그래서:

- `public/offline.html` 한 장 (앱 안에 같이 포장되는 파일)
- `capacitor.config.ts` 에 `errorPath: 'offline.html'` 한 줄

### 화면에 담을 것

1. 로고 + **6개 언어** 한 장에 (브라우저 언어로 자동 선택)
2. 「인터넷 연결을 확인해주세요」
3. **[다시 시도]** 버튼
4. 우리 도메인 표기 — 브라우저로도 접속할 수 있게

### 담지 않을 것 (정직하게)

- **예약된 상담 시각·지난 대화는 못 보여준다.** 라이브 로드라 앱 안에 저장된 게 없다. 있는 척하면 거짓말.
- **「24시간 연락 가능」 류 문구 금지** (1인 운영 — 지킬 수 없는 약속). 응급은 현지 공식 응급번호로 안내.

## 3. 알림 탭 이동 — 이미 답이 있다

`sendInAppNotification` 에는 **`link` 항목이 이미 있다**(예: 상담 예약 알림 → `/patient/consultations`). 새로 설계할 게 없다.

- 폰 알림을 보낼 때 그 `link` 를 같이 실어 보낸다.
- 앱에서 알림을 누르면 그 주소로 이동시킨다(`pushNotificationActionPerformed`).
- 라이브 로드라 **앱 = 웹**이므로 그냥 그 주소로 옮기면 끝.

⚠️ **선행 조건**: 로그인이 안 된 상태에서 알림을 누르면 로그인 화면으로 튕긴다 → **로그인 막힘(1·15번) 수리가 먼저 검증돼야** 이 기능이 의미를 갖는다.

## 4. 순서와 크기

| 순 | 무엇 | 크기 | 왜 이 순서 |
|---|---|---|---|
| 1 | **리마인드가 실제로 도는지 확인 + 정기작업을 `vercel.json` 으로 이관** | 작음 | 이게 안 돌면 아래를 다 해도 알림 자체가 없다 |
| 2 | `sendInAppNotification` 에 폰 알림 발송 잇기 (+조용 시간) | 중간 | 한 곳만 고치면 전 사건이 켜진다 |
| 3 | 알림 탭 이동 | 작음 | 2번에 딸린 것 |
| 4 | 오프라인 화면 | 작음 | 독립적, 언제 해도 됨 |

**전부 웹·서버 쪽이라 4번(설정 1줄)만 빼면 앱 재빌드가 필요 없다.**
