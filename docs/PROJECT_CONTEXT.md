**2. 왜 그렇게 했는지**

- **원 숙제만 보지 않고 동종 스윕**: #870이 `siteUrl()`을 만들고도 설문·리마인더 cron만 이주시켜 나머지 4개 사용자 링크가 origin/env로 새는 채 남아 있었다(포스트모템 "유사 이슈 전수 확인"). 초대 링크는 리마인더보다 더 중요(환자 첫 입장 경로).

- **수수료**: PO "환자한테 돈 일절 안 받는다" 확정 → FAQ가 정반대 고지라 오도. 약관 배상상한은 "환자가 낸 수수료"에 묶여 환자 0이면 상한 0 되는 모순.
- **약관 배상 = Bookimed식 채택**: PO 요청으로 벤치마크. 우리와 동일 모델(환자 무료·병원 커미션)인 Bookimed(업계 1위)는 금액 상한을 안 걸고 중개자 면책에 의존. 한국 약관규제법상 "0 상한/전부 면책"은 무효 위험이라 고의·중과실 예외는 유지.
