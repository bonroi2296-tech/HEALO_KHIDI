**2. 왜 그렇게 했는지**

- **파일 업로드를 PO 손에 넘긴 이유(어시 한계)**: 어시 도구는 ①세션에 공유된 경로만 업로드 가능(다운로드 폴더 ✗) ②**합계 10MB 미만**만 가능한데 AAB 가 55MB 다. 브라우저는 화면조작 도구에서 **「보기 전용」** 등급이라 윈도우 파일 선택창도 못 만진다. **다운로드는 어시가 할 수 있어서** 파일을 받아 검증까지 해두고 PO 에겐 「고르기」만 시켰다.
- **서비스 계정을 끝까지 못 간 이유**: Play 사용자 초대(권한 부여)와 Codemagic 설정 페이지 이동이 **안전 분류기에 막힌다**(권한·비밀키 영역). 우회하지 않고 남겨뒀다.
- **테스터를 「직접 계정 12개 만들기」로 안 한 이유**: 구글이 **같은 기기의 여러 계정을 잡아내고**, 걸리면 **14일을 처음부터 다시** 한다 → 빨라지는 게 아니라 늦어진다. 8/27 KHIDI 중간평가 일정과 정면충돌.
- **국내(크몽)를 해외 업체보다 우선한 이유**: ①크몽이 대금을 보관했다 지급(먹튀 방지) ②**세금계산서** → 사업비 증빙이 깔끔(해외 Stripe 결제는 $25 영수증 때 이미 고생) ③후기가 실제 구매자만 작성 가능.
- **앱 파일을 「모아서 하루 한 번」 올리기로 한 이유(PO 결정)**: 앱 파일 1회 갱신 = 빌드→다운로드→업로드→게시가 한 세트라 사람 손이 매번 든다. **실서비스 배포를 오후 3시 창구로 묶은 것과 같은 원리.**
- **최적화 수정을 기다리지 않고 대행을 먼저 붙여도 되는 근거**: 이 앱은 **라이브로드**(`server.url=https://healwith.co.kr`)라 화면·속도 수정은 **앱을 다시 안 올려도 반영**된다. 14일 시계는 「빌드」가 아니라 「테스터가 참여 상태를 유지한 기간」으로 센다 → **14일을 기다리는 시간이 아니라 고치는 시간으로 쓸 수 있다.**

- **"병원 매칭 마켓플레이스" 아님 → "연속 케어 컨시어지"**: 제휴 병원이 면력한방병원 3곳(진단·면역·재활, 수술 X) + 협진 대학병원 4곳(수술·항암)뿐. 100개 중 1개 고르는 게 아니라 **진단→수술 연계→면역·재활을 쭉 잇는** 모델. 그래서 홈·AI챗·치료여정의 "매칭" 표현을 "케어 경로/상담 배정"으로 톤다운함. (`/care-journey` 페이지가 이 스토리)
