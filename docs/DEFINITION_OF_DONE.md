# Definition of Done — "완성이란 무엇인가" (판단 기준 SoR)

> **왜 이 문서가 있나 (2026-07-15, OKKY "Codex 72시간 사이클" 칼럼에서 착안)**
> 칼럼의 핵심: AI 시대 개발자의 일은 "정밀한 지시(프롬프트) 작성"에서 **"명확한 목표 + 판단 기준 + 반복 루프 설계"**로 옮겨간다. 병목은 이제 **인간의 Attention** 하나뿐이다.
> 우리 프로젝트를 이 렌즈로 보면: `사고 → 부검(POSTMORTEMS) → check:content 룰 추가`라는 **Worker 루프(고치기)**는 이미 세계적 수준인데, **"완성 판정(Manager)"은 아직 사람(PO)의 눈=스크린샷**이다. 그래서 같은 부류의 미완성이 계속 PO에게 발견된다.
>
> **이 문서 = 그 Manager의 채점표다.** 지금까지 가드는 전부 NEGATIVE("옛 브랜드 넣지 마")뿐이었다. 여기선 **POSITIVE**로 "완성이려면 이래야 한다"를 명문화한다.
>
> - 기계판독용 단일 SoR = [`src/lib/completeness/rubric.js`](../src/lib/completeness/rubric.js) — **이 문서와 그 파일은 반드시 함께 움직인다** (`npm run check:completeness`가 둘의 드리프트를 막는다).
> - 이걸 읽고 대상(변경 diff·화면)을 평가하는 **완성도 감사 루프** = [`.claude/skills/completeness-audit`](../.claude/skills/completeness-audit/SKILL.md) (`/completeness-audit`).
> - 기록 = [`docs/audit/COMPLETENESS_LOG.md`](audit/COMPLETENESS_LOG.md).

## 어떻게 쓰나

- **개발 중**: 화면/기능을 "다 했다" 하기 전에 해당 유형의 `done` 조건을 스스로 대조한다.
- **감사 루프(Manager)**: `semantic` 항목을 의미로 평가해 미달을 열거하고, Worker가 전수 수정한다.
- **CI(정적 게이트)**: `auto` 항목은 대개 이미 있는 `check:*` 가드가 지킨다. `check:completeness`는 이 채점표 **자체의 무결성**(부패·문서 드리프트·죽은 참조)을 지킨다.
- **판정 방식 표기**: `auto`(기계 정적 판정) · `semantic`(의미로 봐야 함 = 감사 루프 몫) · `manual`(실기기·실메일 등 사람 1회 확인 불가피 — 정직하게).

## 반복 미완성 7유형 × 완성 조건

각 유형은 `docs/POSTMORTEMS.md`의 실제 사고 부류에서 승격됐다. `id`는 rubric.js와 1:1 대응.

### 유형 1 — i18n/다국어 누락 · `DoD-1-i18n-parity` · verify: auto
공개 화면은 6개어 전부에서 완결된다.
- 활성 6개 언어(ko·en·ru·kz·zh·ja)가 같은 i18n 키 집합 (누락 0)
- 렌더 텍스트에 하드코딩 한글 누출 0
- 렌더 언어는 `useLang()`(서버 initialLang 주입)로 결정 — SSR이 항상 en으로 굳지 않음
- 근거: #3 → #67 → #81(재발 사슬), #2·#30·#38·#39
- **구멍(축 C)**: 스캔이 폴더 화이트리스트에 한정 → 그 밖 컴포넌트 누출. 폴더 화이트리스트 제거가 후속.

### 유형 2 — 조용한 성공으로 위장한 실패 · `DoD-2-no-silent-success` · verify: semantic
성공 보고는 실제 동작으로 뒷받침된다 (빌드통과 ≠ 동작).
- 성공을 상태코드·DB 실측으로 확인 (화면상 OK 만으로 '됐다' 금지)
- try/catch·폴백이 실패를 조용히 삼키지 않음 (실패 시 로그/센트리로 드러남)
- "수행했다"고 보고한 변경이 실제 diff/커밋에 존재 (보고 ↔ 코드 일치)
- 근거: #35(메타), #52·#55·#33·#54·#48·#58·#59·#63

### 유형 3 — 문서-현실 드리프트 · `DoD-3-doc-reality-sync` · verify: semantic *(골격 첫 타깃)*
코드를 고치면 장부(문서 SoR)도 같은 변경에서 닫힌다.
- 이슈 해결 시 KNOWN_ISSUES.md 항목을 같은 작업에서 '종결'로 닫음
- 핸드오프의 '보류·검증 못 함'이 실제 코드 현실과 일치
- 문서가 가리키는 경로·npm 스크립트·라우트가 실재 (죽은 참조 0)
- 근거: #63 → #74 → #75(재발), #90
- **구멍**: 자동 감지 없음 — `/doc-health`가 주간·수동. 감사 루프가 이 로직을 상시 루프화하는 게 이번 골격의 핵심.

### 유형 4 — 옛 브랜드/stale 콘텐츠 잔재 · `DoD-4-content-freshness` · verify: auto
고객이 보는 콘텐츠에 옛 잔재·시효 지난 정보가 없다.
- 옛 브랜드/도메인/이메일 잔재 0
- 시효 걸린 문구(비자·'~까지'·재직 명단)가 만료되지 않음
- 지어낸 후기·근거 없는 수치가 라이브에 없음
- 근거: #1·#4·#49·#66·#57·#11·#46·#56

### 유형 5 — 죽은 링크 → 404 · `DoD-5-no-dead-links` · verify: auto
화면·알림의 모든 링크는 실재하는 라우트로 간다.
- 목록→상세 동적 링크의 `[id]` 라우트 실재
- 알림/딥링크가 파라미터까지 읽는 화면으로 감 (막다른길 0)
- 네비게이션 대상이 존재 (클릭 시 404 0)
- 근거: #31 → #73 → #83(재발 사슬), #37
- **구멍(축 C)**: 가드가 코드 패턴·notifications link 문자열만 봄. 서버 모듈 변수 조립 링크는 통로 밖.

### 유형 6 — cron/KPI 조용한 0 · `DoD-6-cron-nonzero` · verify: semantic
cron/KPI는 잘못된 가정으로 조용히 0을 내지 않는다.
- 실재 테이블·컬럼 참조 (없는 컬럼 → 조용한 0)
- 암호화 컬럼은 집계 전 복호화
- 한 가정(inquiry_id↔patient_id 등)을 고치면 같은 가정 쓰는 **모든 소비자 전수 반영**
- 근거: #7 → #12 → #13 → #14(4연쇄), #8·#35
- **구멍(축 C)**: schema-refs가 테이블 레벨만 — 컬럼 레벨·복호화·소비자 전수는 미검사.

### 유형 7 — UI 반쪽/시각 회귀 · `DoD-7-visual-integrity` · verify: semantic *(골격 첫 타깃)*
렌더 결과가 잘림·깨짐 없이 완결된다 (사람 눈 없이 실측).
- 텍스트 잘림 0 ('Full Profile'→'Fu…' 류 없음)
- 백오피스 액션(노드)을 만들면 상태전파 엣지 전부 배선 (반쪽 백오피스 금지)
- 지도·이미지가 CSP/핫링크로 회색박스 되지 않음
- 근거: #89·#79·#32·#86·#18·#85·#60
- **구멍**: content-clip-sweep가 공개 화면·영어(최장) 위주 — 로그인 뒤편 백오피스·ru/kz 변형 미스캔.
