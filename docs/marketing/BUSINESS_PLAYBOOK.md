# healwith 비즈니스 고도화 플레이북

> 코드/기능이 아니라 **돈 버는 엔진**을 구체화. GROWTH_PLAN(유입 4트랙)의 실행 레이어.
> 3개 엔진: ① 운영 전환(평가 숫자) ② 에이전시 영업(수요) ③ 수익·정산(실매출).
> 작성 2026-06-20 · 평가까지 D-약 68일

---

## 0. 지금 위치 (현실 숫자)
- 누적 문의 11건 / 최근 30일 3건 / 유치(admitted) 4건(일부 데모 의심) / 상담세션 완료 12건.
- 평가 목표: 유치 **12** · 사전상담+사후관리 **120** · 만족도 **90**.
- **격차**: 유치 +8, 상담/사후 +108, 만족도 설문 가동.
- 결론: **수요(문의)가 말랐고, 들어온 문의를 끝까지 굴리는 운영도 아직 없다.** 이 둘을 엔진화한다.

## 1. 단위경제 (Unit Economics) — "1명 데려오면 얼마 남나"

> 의사결정의 기준자. 광고·에이전시에 얼마까지 써도 되는지가 여기서 나온다.

**가정(보수적, 실측으로 교정 필요):**
| 항목 | 값 | 출처/근거 |
|---|---|---|
| 환자 1명 평균 치료비 | **$10,000~20,000** | 진단+수술·항암(상급종합)+면역·재활 합산 추정 |
| 우리 유치수수료율 | **10~25%** (중앙 15%) | 업계 norm(리서치 검증) |
| → 유치 1명당 우리 수수료(gross) | **$1,500~3,000** | 치료비 × 15% |
| 에이전시 분배 | 우리 수수료의 **30~50%** | PO 방침 |
| → 에이전시 통한 순이익(net) | **$750~2,100** | 우리 50~70% |
| → 직접 유입(에이전시 없음) 순이익 | **$1,500~3,000** | 분배 없음 |

**CAC(유치 1명 획득비용) 상한:**
- 광고: CPL $25 × (리드→유치 8%) = **유치당 ~$300** → 순이익($750~2,100) 대비 **크게 남음**.
- 에이전시: 분배가 곧 CAC. 환자 안 오면 0(성과형) → 리스크 낮음.
- **판단: 유치 1명당 $300~700까지 마케팅비 써도 흑자.** 광고·에이전시 둘 다 경제성 OK.

**8/27까지 시나리오 (유치 8명 추가 가정):**
- 수수료 gross 8 × $2,000(중앙) = **$16,000** + 사후 재방문·패키지 별도.
- **더 큰 돈 = KHIDI 잔금 30%** (정부출연금 70,000천원의 30% ≈ **2,100만원** 교부) — 평가 통과가 곧 현금.
- → **평가 숫자 = 가장 큰 단기 현금.** 그래서 1차 목표가 평가 숫자인 게 경제적으로도 맞음.

## 2. 엔진 ① 운영 전환 플레이북 (상담 120·만족도 90을 실제로 쌓기)

> 문의 1건이 들어온 순간부터 "누가 언제 무엇을" 하는 표준 절차. 이게 없으면 들어온 문의가 샌다.

**상태 흐름 (각 단계가 평가 카운트로 적재):**
```
문의 접수 → ① 사전상담(원격, 다회) → 견적 → 비자 → ② 유치(치료) → ③ 사후관리(다회) → 만족도 설문
   inquiries        consultation_sessions(완료)        outcome=admitted    consultation_sessions(완료)     satisfaction
```

**SLA·담당 (코디 운영 기준):**
| 단계 | 언제 | 누가 | 카운트되는 지표 |
|---|---|---|---|
| 문의 접수 | 즉시 | 시스템 | (깔때기 진입) |
| 1차 응답 | **24시간 내** | 코디 | — |
| 사전상담 세션 | 환자당 **여러 번**(기록 필수) | 코디/의사 | **사전상담 ↑** |
| 견적·비자 | 사전상담 후 | 코디 | — |
| 유치 확정 | 치료 시작 시 outcome=admitted | 코디 | **유치 ↑** |
| 사후관리 세션 | 치료 후 **여러 번** | 코디/의사 | **사후관리 ↑** |
| 만족도 설문 | 상담/치료/사후 3시점 | 시스템(`/survey/[token]`) | **만족도 ↑** |

**핵심 운영 규칙:**
- **모든 접촉을 세션으로 기록**하라(전화·메신저 상담도). 상담 120은 유치 안 돼도 세션 다회로 쌓인다.
- 유치 1명 = 사전5+사후5 ≈ 10세션 → **유치 12면 상담 120 자동 충족.** 둘은 한 몸.
- 만족도는 **응답률**이 관건 → 설문 링크를 상담 직후 바로 발송(시간 끌면 응답 급감).
- 매주 `/admin/khidi/conversion`·`kpi-dashboard`로 카운트 점검. 데모 시드는 평가 전 제거.

**[PO 액션]** 코디(현지 직원 포함)에게 이 SLA를 1장으로 공유 + 주 1회 카운트 리뷰.

## 3. 엔진 ② 에이전시 영업 2주 스프린트 (유치 4→12의 현실 경로)

> 키트(제안서·콜드메일·타겟리스트·수수료)는 완성됨(`agency-outreach/`). 이건 "실제 보내기" 실행 플랜.

**왜 에이전시인가**: 솔로가 환자 1명씩 모으는 건 불가능. 에이전시 1곳 = 환자 묶음. 성과형 수수료라 리스크 0.

**2주 스프린트:**
| 일자 | 할 일 | 산출 |
|---|---|---|
| D1 | 데모 에이전시 계정 1개 발급(`/agency` 시연용) + 제안서 PDF화 | 시연 준비 |
| D1~2 | 타겟 10곳 연락처 재확인(자사 사이트) — Health Travel·Korea Vision·Medmost 우선 | 연락처 확정 |
| D2 | 1차 콜드 발송(러시아어 메일+메신저) 10곳 | 발송 10 |
| D5 | 무응답 팔로업 | 발송 +10 |
| D7 | 응답처 15분 콜(데모 시연 + 수수료 협의) | 콜 N건 |
| D10 | 관심처에 수수료 조건서 + 첫 거래 소액고정 제안 | 계약 협상 |
| D14 | 1~2곳 파일럿 합의 → 첫 환자 의뢰 받기 | **파일럿 계약** |

**목표**: 2주 안에 **에이전시 1~2곳 파일럿** + 첫 환자 의뢰 1~3건. (유치까진 시차 있으니 8월 전 착수가 마지노선.)

**[PO 액션]** D1 데모계정·PDF는 개발/운영 필요(내가 스펙 줌). 발송·콜은 PO. 수수료 최종% 협의는 PO.

## 4. 엔진 ③ 수익·정산 모델 (돈이 실제로 들어오는 길 — 지금 비어있음)

> 유치돼도 **수수료를 어떻게 받느냐**가 안 풀려 있음. 이게 실매출의 진짜 블로커.

**문제**: 러시아 직접 결제 불가(제재). 카자흐는 가능하나 환자 직접 송금 신뢰 낮음.

**설계(권장 흐름):**
```
환자 → (치료비) → 병원에 직접 결제/청구   ← 환자 부담은 병원이 안내
                         │
병원 → (유치수수료 15%) → healwith         ← 우리 매출(B2B, 국내 정산이라 깔끔)
                         │
healwith → (수수료의 30~50%) → 에이전시      ← 성과 확정 후 분배
```

**핵심 원칙:**
- **환자→우리 직접 결제 피하고, 수수료는 병원→우리(B2B)로 받는다.** 국내 세금계산서로 정산 → 정부과제 회계와도 정합.
- 환자 치료비는 **병원 직접청구** + 필요시 **카자흐 허브**(현지 에이전시/파트너가 수납 대행).
- 에이전시 분배는 **유치 확정 시 절반 + 치료 완료 시 절반**(노쇼 리스크 분산).

**[PO 액션]**: ① 병원(면력·협진 상급종합)과 **수수료 계약서**에 "유치수수료 %·정산주기" 명문화. ② 변호사·세무 자문으로 정부과제 회계와 충돌 없는지 확인(유치업자 등록 건과 함께 — `DEEP_RESEARCH` 참고).
