## 1. 이 서비스가 뭔가 (1분 이해)

**HEALO(healwith.co.kr)** = 카자흐스탄·러시아·CIS 지역의 **암 환자**를 **한국의 종양(암) 병원**과 이어주는 **의료관광 플랫폼**이다.

- **환자(해외)**: 우리 사이트에서 병원·치료를 보고 → AI 상담 또는 사람 상담 → 문의 한 번으로 한국 병원과 연결 → 필요하면 화상(영상) 상담까지.
- **우리(운영)**: 관리자 화면에서 문의·환자·병원·상담·AI 품질을 관리한다.
- **정부과제**: 이 사업은 **KHIDI(한국보건산업진흥원)** 정부지원과제다. 그래서 "실적"과 "평가"가 중요하다(2번).

**서비스 주소:** https://healwith.co.kr (실서비스) · 관리자 화면은 `/admin`

**더 자세한 서비스 이해가 필요하면** 클로드에게: `docs/대표님_서비스_이해_매뉴얼.md 읽고 이 서비스 구조 쉽게 설명해줘.`

- **평가 방식:** 그날 발표 20분 + 질의응답 10분 / 장소: 메디컬코리아지원센터(서울역).

  - 사전상담·사후관리 **120건**
  - 환자 만족도 **90점**
  - + 정성평가(ICT 체계 구축, 양·한방 협진모델)
- **이 숫자들은 시스템이 자동으로 센다:** 관리자 화면 `/admin/khidi/conversion` (유치 전환 대시보드)가 자동 집계 = **그게 곧 점수**다.

> ⚠️ **역할 분담(중요):** 클로드가 만드는 건 **"실적이 자동으로 쌓이는 판(시스템)"**이다. **실제 환자·파트너를 데려오는 건 사람(당신·에이전시)의 영업·발품**이다. 소프트웨어가 실환자를 만들어내진 못한다. 그리고 **가짜 숫자·가짜 후기·가짜 실적은 절대 금지**(정부 증빙은 실데이터라야 한다).

## 3. 당신의 역할 vs 클로드의 역할 (분담)

| | **당신(운영자)이 하는 일** | **클로드가 하는 일** |
|---|---|---|
| 개발 | ❌ 안 함 | ✅ 코드 작성·수정·검사·배포 전부 |
| 지시 | ✅ "이런 결과를 원한다" 말로 시킴 | ✅ 그걸 어떻게 만들지 판단·구현 |
| 결정 | ✅ 돈·삭제·보안·큰 방향만 | ✅ 나머지 기술 결정은 알아서 |
| 영업/파트너 | ✅ 실제 환자·병원·에이전시 확보 | ❌ 못 함(판만 깔아줌) |
| 외부 콘솔 | ✅ 비번 입력·결제 등 최종 클릭 | ❌ 비번은 절대 안 만짐 |

**핵심:** 당신은 **"무엇을 원하는지"만 명확히** 하면 된다. "어떻게"는 클로드가 한다. 사업 방향·우선순위(어디에 힘을 쏟을지)는 **당신이 정하고**, 클로드는 제안·견제는 하되 방향을 마음대로 몰지 않는다.

## 4. 🎯 클로드에게 오더 내리는 법 (이 문서의 핵심)

### 4-1. 어떻게 말하면 되나

**원하는 "결과"를 일상어로 말하면 된다.** 개발 용어를 쓸 필요 없다.

| ✅ 좋은 오더 (결과가 분명) | ❌ 나쁜 오더 (너무 모호) |
|---|---|
| "환자 문의 목록에서 국적이 안 보여, 보이게 해줘" | "개선해줘" |
| "AI 상담 답변이 너무 딱딱해, 좀 더 친절하게" | "버그 고쳐줘" |
| "병원 상세 페이지 사진이 깨졌어, 고쳐줘" | "더 좋게 만들어줘" |
| "카자흐어로 봤을 때 이 문구가 안 번역됐어" | "이것저것 손봐줘" |

**모호하게 시켜도 된다 — 단, 클로드가 되물으면 버튼으로 답하면 된다.** 클로드는 당신이 두루뭉술하게 시키면 스스로 코드를 훑어 판단하고, 방향이 갈리는 진짜 갈림길만 **선택 버튼**으로 물어보게 되어 있다. (당신은 타이핑 말고 클릭으로 답하면 됨.)

### 4-2. 클로드가 나한테 물어볼 때

클로드는 질문을 **누르는 버튼**으로 띄운다(예: "머지하기 / 더 작업 / 오늘 여기까지"). 화면에 나온 선택지를 누르기만 하면 된다. **답이 명백하면 아예 안 묻고 알아서 하고 사후 보고**한다.

### 4-3. "자율주행" 시키는 법 (길게 맡기고 싶을 때)

바쁘거나 세세히 못 챙길 때, 이 템플릿으로 길게 맡길 수 있다:

> **"이거 자율주행으로: [원하는 것]. 완성 기준은 네가 정하고 스스로 검증까지 해. 충분히 써서 끝까지. 돈·삭제·방향 바뀌는 것만 나한테 물어봐."**

이러면 클로드가 몇 시간이든 알아서 만들고 검증하고 보고한다. 단 **안전 3종(돈·되돌리기 어려운 것·보안)은 여전히 멈춰서 물어본다** = 자율주행이지 폭주가 아니다.

### 4-4. ✅ 클로드가 "알아서" 하는 것 (당신이 걱정 안 해도 됨)

이 프로젝트는 웬만한 안전장치가 **자동**으로 걸려 있다. 아래는 클로드가 사람 확인 없이 처리한다:

- **작은 수정**(오타·번역·문구·색 미세조정·명백한 버그)은 자동 검사(CI)만 통과하면 **알아서 실서비스에 반영**.
- **자동 검사**: 코드 올릴 때마다 기계가 문법·안전·콘텐츠(옛 브랜드 잔재·번역 누락 등)를 검사한다.
- **독립 리뷰**: 자동 반영 전에 **다른 검토용 AI**가 코드를 한 번 더 본다(작성자=검토자 함정 방지).
- **버그가 나면**: 원인 + 재발방지(같은 실수 다신 안 나게 하는 검사 룰 추가)까지 한 세트로 처리하고 `docs/POSTMORTEMS.md`에 반성문을 남긴다.
- **보고는 하루 1번**: 틈틈이 안 귀찮게 하고, 하루치를 "된 것 + 당신이 정할 것 1~2개"로 묶어 보고한다.

### 4-5. 🛑 당신이 반드시 "멈춰서" 결정해야 하는 것

클로드는 **아래 4가지는 절대 혼자 진행하지 않고 당신에게 물어본다.** 당신은 이것만 판단하면 된다:

1. **💰 돈** — 유료 서비스 결제, 비용 발생. (소액이면 "이거 얼마 나가요" 알려만 주고, 큰돈이면 확인받는다.)
2. **🗑️ 되돌리기 어려운 것** — 데이터·계정·기록 **삭제**, DB에서 뭔가 지우는 것. (원칙: 우리는 하드 삭제 안 하고 "비활성" 처리한다.)
3. **🔐 보안·개인정보** — 암호화, 로그인/권한, 환자 개인정보(PII) 흐름을 바꾸는 것.
4. **🎨 큰 화면/디자인/카피 변경** — 큰 UI나 전체 톤이 바뀌는 건 막지 않고 **미리보기 링크를 만들어** 준다 → 당신이 눈으로 보고 결정.

> **판별 기준 한 줄:** *"잘못되면 그냥 고치면 되는 일이냐, 아니면 사고냐?"* 사고 쪽이면 클로드가 당신에게 묻는다.

### 4-6. 비번·시크릿(비밀 값)은 채팅에 절대 붙이지 마라

클로드는 **비밀번호·API 키를 절대 만지지 않는다.** 그런 값이 필요하면 **당신이 콘솔(Vercel·Supabase 등)에 직접 입력**하는 방식으로 안내한다. 실수로 채팅에 비번을 붙였다면 그건 "유출"로 간주하고 바꿔야 한다.

## 6. 세션을 어떻게 이어가나 (핸드오프 = 기억의 핵심)

이 프로젝트의 가장 중요한 습관: **클로드는 세션(대화창)이 바뀌면 이전 대화를 기억하지 못한다.** 그래서 **`docs/PROJECT_CONTEXT.md`** 라는 파일 하나에 "지금까지 뭘 했고 왜 그랬고 다음에 뭘 할지"를 계속 쌓는다.

- **새 세션 시작** → "PROJECT_CONTEXT.md 최상단 읽어" → 클로드가 어제까지의 상황을 이어받는다.
- **세션 끝** → `/handoff` → 오늘 한 일이 그 파일 맨 위에 저장된다.
- **중요한 결정을 내렸을 때**(방향·정책 확정, 배포 완료)는 세션 도중이라도 "이거 핸드오프에 지금 기록해줘"라고 하면 즉시 저장한다. (세션이 중간에 죽으면 "왜 그렇게 결정했는지"가 통째로 날아가기 때문.)

**이게 왜 중요한가:** 당신이 바뀌어도, 클로드 세션이 바뀌어도, 이 파일만 읽으면 누구든 "어디까지 왔는지"를 알 수 있다. **인수인계 파일을 새로 만들지 말 것** — 흩어지면 혼란만 커진다. 무조건 이 파일 하나로.

## 9. 🚨 사고가 났을 때 (긴급 대응)

당신은 원인을 몰라도 된다. **클로드에게 상황을 그대로 말하면** 클로드가 진단·수리한다.

- **"사이트가 안 열려요 / 화면이 깨졌어요"** → 클로드에게: `healwith.co.kr이 [증상]. 원인 찾아서 고쳐줘.` (스크린샷을 붙이면 더 좋음)
- **"AI가 이상한 답을 해요"** → 화면 캡처와 함께: `AI 상담이 이런 답을 했어, 문제 있는지 봐줘.` (의료 서비스라 AI 품질은 특히 중요하게 다룬다)
- **"뭔가 지워진 것 같아요 / 데이터가 이상해요"** → **아무것도 만지지 말고** 클로드에게 바로 상황 설명. 삭제·복구는 위험한 영역이라 클로드가 신중히 확인하며 진행한다.
- **개인정보 유출 의심** → `docs/SECURITY_BREACH_RUNBOOK.md`가 있다. 클로드에게 `보안 사고 의심돼, SECURITY_BREACH_RUNBOOK 따라 대응해줘.`

**황금 규칙:** 잘 모르겠고 위험해 보이면 → **직접 손대지 말고 클로드에게 상황을 그대로 설명**하라. 클로드는 "검증 못 한 건 솔직히 말한다"는 규칙이 있어서, 확실하지 않으면 "이건 확인 못 했다"고 말한다.

## 10. 자주 쓰는 말 사전 (개발용어 → 쉬운 말)

클로드는 개발 용어를 쓰되 **쉬운 말을 병기**하게 되어 있다. 그래도 미리 알아두면 편하다:

| 개발 용어 | 쉬운 말 | 뜻 |
|---|---|---|
| PR (풀 리퀘스트) | 합치기 신청서 | "이 수정을 본판에 넣자"는 신청 |
| CI | 자동 검사 | 코드 올릴 때 기계가 자동으로 하는 검사 |
| 머지(merge) | 본판에 합침 | 수정을 실제 코드에 반영 |
| 배포(deploy) | 실서비스 반영 | 사용자가 보는 진짜 사이트에 올림 |
| 브랜치(branch) | 작업본 | 본판을 안 건드리고 따로 작업하는 사본 |
| 커밋/푸시(commit/push) | 저장 올리기 | 수정을 저장소에 기록·업로드 |
| 프리뷰(preview) | 미리보기 | 실서비스 반영 전 임시로 보는 링크 |
| 핸드오프(handoff) | 인수인계 | 다음 세션이 이어가게 상황 저장 |
| RLS | 데이터 접근 잠금 | DB에서 아무나 못 보게 막는 보안 |
| PII | 환자 개인정보 | 이름·연락처 등 민감 정보 |
