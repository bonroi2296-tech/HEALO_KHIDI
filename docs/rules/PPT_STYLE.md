# PPT 표준 깔 (BeyondK 톤) — 발표자료 만들 때 이 규격으로

> **트리거**: PPT·발표자료·제안서 슬라이드·피치덱을 만들 때 **무조건** 이 문서대로.
> 출처: `비욘드케이컴퍼니소개(내부_경영지원).pdf` (2026-07-31 PO 지시 — "앞으로 PPT 는 이 깔로").
> 원본에서 폰트·색·판형을 실제로 추출한 값이라 눈대중이 아니다.
>
> ## ⛔ 먼저 읽어라 — **이 규격은 이미 코드로 박혀 있다**
> **`scripts/ppt/beyondk_style.py`** 가 아래 값을 전부 담고 있다. 새 발표자료는 **그 모듈을 import 해서** 만든다.
> 아래 색·크기를 손으로 다시 옮겨 적어 python-pptx 코드를 새로 짜지 마라 — **매번 조금씩 다른 깔이 나온다.**
> 이 문서는 «왜 그 값인가»를 설명하는 곳이고, **집행하는 곳은 코드다.**
> 쓰는 법은 아래 [§5 코드로 만든다](#5-코드로-만든다-실제-집행부) 참고.

## 0. 판형

- **960 × 540 pt = 13.333 × 7.5 in (16:9)**. python-pptx 기본 4:3 이므로 반드시 지정.
- 좌우 안전 여백 **72pt**, 상단 kicker 시작 **좌 78pt / 상 36pt**.
- 여백을 무서워하지 마라. 원본은 슬라이드 절반이 빈칸인 장이 태반이다.

## 1. 폰트

**에스코어 드림 9종 설치 완료 (2026-07-31, 상업용 무료).** 아래 이름을 그대로 써라 — 무게마다 **글꼴 이름이 따로**다(굵게 표시 대신 이름으로 무게를 고른다).

| 용도 | 쓸 글꼴 이름 | 원본 |
|---|---|---|
| 큰 제목·챕터 표지·강조 | `에스코어 드림 8 Heavy` | HG꼬딕씨 P80g / SCDream 8Heavy |
| 소제목·표 안 강조 | `에스코어 드림 7 ExtraBold` | HG꼬딕씨 P60g / SCDream 7ExtraBold |
| 표 머리행 | `에스코어 드림 5 Medium` | — |
| 본문 | `에스코어 드림 4 Regular` | HG꼬딕씨 P40g / SCDream 4Regular |
| kicker·캡션·가는 글씨 | `에스코어 드림 3 Light` | HG꼬딕씨 P20g / SCDream 3Light |

- 설치 위치: `%LOCALAPPDATA%\Microsoft\Windows\Fonts` (사용자 전용 — 관리자 권한 불필요, 지우면 그대로 되돌아감). 원본: [에스코어 글꼴나눔](https://s-core.co.kr/company/font/)
- **HG꼬딕씨는 유료**(마켓히읗 6종 묶음 99,000원)라 안 샀다. 에스코어 드림으로 대체해도 톤이 거의 같아 굳이 살 필요 없다.
- 다른 PC(외부 공유용)에서 열 때 깨지면 → PDF 로 내보내거나 그 PC에도 에스코어 드림을 깔면 된다.
- 글자 크기(원본 실측): 본문 **11~12pt**, 부제 11pt, kicker 9pt, 표 10~11pt, 제목 **24pt**, 챕터 표지 28pt.
  → **크게 키우지 마라.** 이 톤의 정체성은 "작은 글씨 + 큰 여백"이다.

## 2. 색 — **원본이 쓴 색 ≠ 우리가 쓸 색**

> **여기가 이 문서에서 제일 헷갈리는 칸이다. 두 개를 갈라서 봐라.**
> 비욘드케이 원본 PDF 는 강조색으로 **라임 `#D9FE55`** 를, 도형 채움으로 **연녹 계열**을 썼다.
> 우리는 **그 구조·여백·타이포는 그대로 따라 하되, 색만 우리 브랜드 teal 로 바꿔 쓴다** (PO 지시).
> 즉 라임은 «폐기된 실수»가 아니라 **우리가 참고한 원본의 색**이다 — 기록으로 남긴다.
> 실제로 칠할 때 쓰는 건 오른쪽 «우리가 쓸 색» 칸이고, 그게 `beyondk_style.py` 에 박혀 있는 값이다.

| 이름 | 원본(비욘드케이)이 쓴 색 | **우리가 쓸 색** | 모듈 상수 | 쓰는 곳 |
|---|---|---|---|---|
| 먹 | `#000000` | `#000000` | `BLACK` | 제목, 강조 텍스트, 챕터 표지 배경 |
| 흰 | `#FFFFFF` | `#FFFFFF` | `WHITE` | 기본 배경, 챕터 표지 글자 |
| 패널 회색 | `#F2F2F2` | `#F2F2F2` | `PANEL` | 본문 박스, 표 머리행, 하단 강조 띠, 숫자 카드 |
| 선 회색 | `#DCDDDD` | `#DCDDDD` | `LINE` | 구분선, 표 가로선, 이미지 테두리 |
| 본문 회색 | `#767171` | `#767171` | `BODY` | 서술형 본문 |
| 흐린 회색 | `#7F7F7F` | `#7F7F7F` | `MUTED` | kicker, 캡션, 각주 |
| **핵심 강조** | 라임 `#D9FE55` | **teal-700 `#0F766E`** | `BRAND` | 형광펜·숫자 카드 강조·흐름도 짙은 칸 — 슬라이드당 **1곳** |
| 짙은 바탕 위 글씨 | (원본엔 없음) | teal-100 `#CCFBF1` | `BRAND_PALE` | teal 바탕 위 작은 글씨 |
| 도형 채움(중간) | 중간녹 `#C5E0B4` | teal-100 `#CCFBF1` | `GREEN_M` | 흐름도 중간 칸 |
| 도형 채움(옅은) | 연녹 `#E2F0D9` | teal-50 `#F0FDFA` | `GREEN_L` | 흐름도 옅은 칸 |
| 연결선 포인트 | 진녹 `#00B050` | teal-700 `#0F766E` | `BRAND` | 아주 드물게 |
| 화살표 회색 | `#A6A6A6` | `#A6A6A6` | (`arrow()` 내부) | 흐름도 화살표 |

- **왜 색만 바꾸나**: 원본은 «남의 회사 자료»다. 구조(작은 글씨 + 큰 여백 + 도식화)가 우리가 베낄 값이고,
  색은 우리 브랜드여야 한다. teal-700 은 `DESIGN.md` 에서 **영구 고정**된 브랜드 색이다.
- 강조 teal 은 **한 슬라이드에 한 곳**. 두 곳 이상 칠하면 원본 톤이 아니다(원본도 라임을 한 곳만 썼다).
- 위 「우리가 쓸 색」 칸 밖의 색(파랑·주황 등)은 금지.
- `LIME` 이라는 옛 상수명이 코드에 남아 있는데 **지금은 teal 을 가리키는 별칭**이다(원본 색을 담고 있지 않다). 새로 쓸 땐 `BRAND`.

## 3. 슬라이드 5종 (뼈대 — 모든 장은 이 중 하나에서 출발한다)

**A. 표지** — 흰 배경, 정중앙. 위에 작은 회색 영문 태그라인(11pt) → 아래 큰 검정 워드마크.

**B. 챕터 표지** — 전면 **검정**, 정중앙에 흰색 굵은 영문 28pt 한 줄만. (`Business background`, `So,`, `Plz,` 처럼 짧게)

**C. 서술형(한 문단으로 설득하는 장)** — 흰 배경, 전체 가운데 정렬 + 화면 세로 중앙.
굵은 한글 제목 24pt → 그 밑에 **짧은 가로선(폭 40pt)** → 본문 12pt 회색, **핵심어만 검정 굵게**.

**D. 내용형(표·도식이 들어가는 장)** — 좌상단부터:
kicker 9pt 회색(`Who` / `What` / `How` / `ABOUT US`) → 제목 24pt 검정 → 한 줄 부제 11pt.
본문은 **`#F2F2F2` 라운드 박스(모서리 반경 10pt)** 안에 넣는다.

**E. 표** — 기본형은 **세로선 없음**. 헤더행만 `#F2F2F2` 채움, 가로선 `#DCDDDD`, 좌측 정렬, 10~11pt.
표 위 소제목은 **굵게+밑줄**. 비교형(A vs B) 표만 얇은 검정 테두리 전체 + 가운데 정렬.

**+ 하단 강조 띠** (`B.band`) — 결론 문장은 `#F2F2F2` 밴드에 가운데 정렬 11pt, 앞에 `▶`.

## 4. 자주 틀리는 것

- ❌ 제목 40pt 이상으로 키우기 → 원본은 24pt 다.
- ❌ 색을 늘리기(파랑·주황 추가) → §2 「우리가 쓸 색」 칸 밖은 금지.
- ❌ 슬라이드를 꽉 채우기 → 빈칸이 이 톤의 절반이다.
- ❌ 강조색 여러 곳 칠하기 → 한 곳.
- ❌ **원본이 쓴 라임 `#D9FE55` 를 그대로 칠하기** → 구조만 따라 하고 색은 teal 로 (§2).
- ❌ `beyondk_style.py` 안 쓰고 python-pptx 코드를 새로 짜기 → §5.
- ❌ **`prs.save(경로)` 로 저장하기 → `B.save(prs, 경로)` 를 써라.**
  왜: `font.name` 은 `<a:latin>` «만» 건드린다. 한글은 `<a:ea>` 를 따라가고, 그게 비면
  테마의 `script="Hang"` 값(기본 **맑은 고딕**)으로 떨어진다. `B.save()` 가 둘 다 박는다.
  실측(2026-08-31, python-pptx 1.0.2): 고치기 전 = run 7개 중 `<a:ea>` **0개** + 테마 한글 **맑은 고딕**,
  고친 뒤 = `<a:ea>` **7개** + 테마 한글 **에스코어 드림**. 뽑은 파일은 다시 열리고 zip 도 멀쩡했다.
- ❌ 4:3 로 만들기 → 16:9 (13.333×7.5in) 고정.

## 5. 코드로 만든다 (실제 집행부)

```python
import sys; sys.path.insert(0, "scripts/ppt")
import beyondk_style as B

prs = B.deck()                                     # 960×540pt(16:9) 새 문서
B.cover(prs, "KICKER", ["제목 줄1", "제목 줄2"], "부제", "2026. 08. 27.")
B.chapter(prs, "Business background")              # 전면 검정 + 흰 글씨 한 줄
B.statement(prs, "제목", [("본문", False), ("강조 문장", True)], accent="한 줄 결론")
s = B.content(prs, "How", "제목", "부제")          # 좌상단 kicker/제목/부제까지 그려진 빈 장
prs.save("out.pptx")
```

**`s = B.content(...)` 로 받은 장 위에 얹는 부품** (5종 말고 이것들도 이미 있다 — 새로 짜지 마라):

| 부품 | 하는 일 |
|---|---|
| `B.table(s, rows, x, y, widths, ...)` | 세로선 없는 기본형 표. `bordered=True` 면 비교형(A vs B) |
| `B.stat(s, x, y, w, value, label, sub)` | **숫자 카드** — 큰 숫자 + 설명. 글 나열 대신 이걸 써라 |
| `B.step(...)` + `B.arrow(...)` | 흐름도 한 칸 + 화살표 |
| `B.picture(s, path, x, y, w=)` | 실화면 캡처 삽입(테두리 자동) |
| `B.panel(s, ...)` / `B.box(...)` | `#F2F2F2` 라운드 박스 / 임의 사각형 |
| `B.band(s, "▶ 결론")` | 하단 강조 띠 |
| `B.highlight(s, txt, x, y)` | teal 형광펜 |
| `B.caption` · `B.note` | 캡션 · 각주 |
| `B.rich(tf, [(글자, 글꼴, 색), ...])` | 한 줄 안에서 강조 섞기 |

- 실행 전 `pip install python-pptx` (검증본 1.0.2).
- **글꼴은 이름만 파일에 박힌다** — 리눅스/클라우드 세션에서 만들어도 되고, 열어 볼 PC 에만 에스코어 드림이 깔려 있으면 된다.
- 실제 사용 예시 = `scripts/ppt/khidi_midterm_deck.py` (430줄). 새 덱은 이걸 베껴서 시작하는 게 가장 빠르다.
- PDF 로 내보내기: `scripts/ppt/pptx_to_pdf.ps1` (PO PC 용) / 이 클라우드 상자에선 `soffice --headless --convert-to pdf`.
