# 번역 품질 — 원어민이 같은 실수를 두 번 잡지 않게

> **트리거:** 새 화면·새 문구 추가 / 「번역이 이상하대」 / 코디네이터 교정 요청 / 용어를 새로 정할 때
> **자동검사:** `npm run check:i18n-quality` (CI 매 신청서 자동, ru·kz 차단)
> **용어집(단일 SoR):** `src/lib/i18n/glossary.js`
> **만든 계기:** 2026-08-20 PO — *"한국어는 어느정도 맞춰줘도 외국어는 이상하대. 코디네이터분이 하나부터 열까지 텍스트 수정하고 있잖아."*

---

## 0. 먼저 — 「언어팩을 깔면 나아지나?」에 대한 답: 아니다

깔아서 해결되는 언어팩 같은 건 없다. 번역을 만드는 건 AI(`gemini-flash-latest`)고, 그 AI는
**러시아어·카자흐어 자체는 이미 잘한다.** 2026-08-20에 화면 문구 2003개를 원어민 관점으로 읽어본 결과,
문법·어감이 어색한 문장은 거의 없었다. 그런데도 코디네이터가 매번 고칠 게 나온 이유는 딴 데 있었다:

| 진짜 원인 | 실측 | 왜 AI 를 바꿔도 안 고쳐지나 |
|---|---|---|
| **같은 개념을 화면마다 다른 단어로** | 면력한방병원이 한 사이트에서 **5가지 이름**. 상담=консультация/приём, 문의=заявка/обращение/запрос, 환자(kz)=науқас/пациент | 문장 하나만 보면 **다 맞는 말**이다. AI 는 매번 «그때그때 자연스러운» 단어를 고르고, 사이트 전체를 볼 수 없다 |
| **원문의 사실이 번역에서 증발** | 지점 주소 4곳이 「구·동」까지만 남음, 유치업자 등록번호(kz) 통째 누락, 환자 교육자료의 «24시간 내 연락»·응급 증상 항목 누락 | 요약은 AI 가 잘하는 일이라 «스스로 판단해» 줄인다. 지시 없이는 안 멈춘다 |
| **카자흐어 자리에 러시아어** | 63건이 러시아어와 «글자까지 똑같음» | 카자흐어는 러시아어 차용어가 실제로 많아서, 모델도 사람도 「틀렸다」고 단정하기 애매하다 |
| **코디가 고칠 창구가 없음** | 어드민 번역 화면의 언어 탭이 ko·en·zh·ja **4개뿐** — 1차 타깃인 ru·kz 는 아예 못 고쳤다 | 도구 문제. 번역 품질과 무관하게 사람 손을 강제했다 |

→ **그래서 손댈 곳은 「번역기」가 아니라 ①용어집 ②기계 검사 ③코디가 직접 고칠 창구** 세 개다.
(상용 번역관리 도구 — Crowdin·Lokalise·Weblate — 를 붙이는 선택지도 있지만 월 비용이 들고,
그 도구들이 주는 핵심 기능이 결국 위 ①②③이다. 먼저 우리 것으로 만들고, 부족하면 그때 검토.)

## 0-1. ⚠️ 먼저 「번역이 어디에 사는지」부터 봐라 — 사전 파일 하나가 전부가 아니다

2026-08-20 첫 조사에서 **사전 파일(`dictionary.js`) 하나만 뒤지고 「원인 다 찾았다」고 보고했다가 PO 에게
«내가 듣기론 그 정도가 아니었던 거 같은데?» 로 되물렸다.** 실제 지형은 이렇다:

| 번역이 사는 곳 | 규모 | 누가 고치나 | 주의 |
|---|---|---|---|
| `src/lib/i18n/dictionary.js` | 2003키 × 21언어 | 개발 세션 | 여기만 보면 **화면에 실제로 뜨는 값과 다르다** |
| **`content_overrides` (DB)** | **262행** | **코디네이터가 백오피스에서 직접** | **화면에서는 이게 사전을 «덮는다»** |
| `src/lib/content/homeContent.js` | 홈 전체 | 개발 세션 | `home.*` 키의 폴백 기본값 |
| `src/lib/i18n/coordinator.js` | 658개 문자열 | 개발 세션 | 코디 포털 전용 사전(별도 파일) |
| **콘텐츠 파일**(`immuneTherapies`·`immuneCancerDetails`·`partnerHospitals`) | 211칸 × 6언어(치료법 41·5축 15·암종 98·FAQ 46·수술후 3·병원 8 — 화면이 그리는 칸만) | **코디가 콘텐츠 편집기에서 직접**(2026-09-06 편입 — 묶음 제목 「콘텐츠 · …」, 키 `therapy.*`·`itcrn.*`·`cancer.*`·`cancerFaq.*`·`care.*`·`hospital.*`) | 화면은 `getMergedContentFiles()` 사본을 그린다. 언어별 «문자열 배열»(specialties·highlights·focusPrograms)은 아직 편집기 밖 |
| 그 밖 코드 파일 | `doctorPhrases`·`immuneSite`·`visaGuide`·`medicalGlossary` 등 | 개발 세션 | 사전 검사가 **안 보는 곳** |
| `consultation_translations` (DB) | 3543행 | AI 실시간 통역 | 화면 문구가 아니라 통역 산출물 |
| `doc_glossary_terms` (DB) | **0행** | (설계만 있고 안 붙음) | 의료문서 번역의 «학습 용어집» — 코디 수정이 축적될 자리인데 비어 있다 |

→ **「번역이 이상하다」는 말을 들으면 이 표를 먼저 펴라.** 한 곳만 보고 원인을 단정하면
PO 가 실제로 듣는 불만의 절반도 못 덮는다.

## 0-2. 코디네이터 교정을 «코드로 되돌리는» 일 (가장 자주 새는 곳)

코디가 백오피스에서 고친 값은 **DB 에만 쌓이고 코드로 돌아오지 않았다.** 2026-08-20 실측:
교정 262건 중 **259건이 코드에 미반영**. 그 결과 —

- 사전에는 암종 선택지가 「Лёгкое」(폐)·「Грудь」(가슴)처럼 **암 이름이 아니라 장기 이름**으로 남아 있었다.
- override 가 안 걸리는 곳(앱·PDF·메일·AI 프롬프트·검색 노출 메타)에는 **여전히 옛 값**이 나갔다.
- 다음 세션이 사전을 기준으로 새 문구를 만들면 **고쳐진 적 없는 값에서 다시 출발**한다 → 코디가 또 고친다.

```bash
npm run check:i18n-backport   # 어긋난 건수만 본다 (파일 안 건드림 · 어긋나면 실패로 끝난다)
npm run i18n:backport         # 코디 값을 코드로 반영한다
npm run sweep -- --only=i18nback   # 상시 훑기에서 같은 것을 본다
```

- ⚠️ **이 검사는 자동 검사(CI)에 못 붙인다** — DB 를 직접 읽어야 해서 `service_role` 열쇠가 필요한데,
  그 열쇠를 자동 검사에 두는 것은 보안 규칙 위반이다. 그래서 **상시 훑기(`npm run sweep`)에 넣었다**
  (열쇠가 있는 PO 로컬에서 돈다). 열쇠가 없는 상자에서는 「통과」가 아니라 **「못 잼」**으로 뜬다 —
  검사가 빠졌는데 초록으로 보이는 것이 2026-08 야간검사 사고의 정확한 형태였기 때문이다.

- **코디(원어민) 값이 우선.** 다만 코디가 못 본 「사실」(글자수 제한·등록번호 등)이 코드 쪽에만 있으면
  그건 사람 판단이다 — 코디 문체에 사실만 얹어라(예: `Краткая заметка (по желанию, до 200 знаков)`).
- 자격증명이 없는 상자(클라우드 세션)에서는 이 명령이 **조용히 건너뛴다.** 그럴 땐 Supabase MCP 로
  `content_overrides` 를 읽어 손으로 대조해라 — 「안 돌아서 0건」과 「진짜 0건」은 다르다.

## 1. 새 문구를 추가할 때 (매번)

1. **한국어를 먼저 확정**한다. 원문이 흔들리면 6개 언어가 같이 흔들린다.
2. **용어집을 본다** — `src/lib/i18n/glossary.js`. 이미 정해진 단어가 있으면 **그대로 쓴다**.
   새 개념이면 용어집에 `proposed` 로 한 줄 추가하고 번역한다(확정은 코디네이터 몫).
3. 번역할 때 **원문의 숫자·기한·등록번호·주소·연락처를 하나도 빼지 마라.** 줄이고 싶으면
   한국어 원문을 먼저 줄이고 그다음 번역한다 — 번역 단계에서 요약하면 언어마다 다른 사실이 나간다.
4. `npm run check:i18n-quality` 를 돌린다. 빨간불이면 고치고 다시.
5. **화면으로 본다.** 검사는 「사실이 빠졌나」를 보지 「읽히나」를 못 본다.

## 2. 자동검사가 잡는 것 / 못 잡는 것

`scripts/check-i18n-quality.mjs` — `--selftest` 로 검출기 자체가 살아있는지 매번 먼저 확인한다.

| 잡는다 | 못 잡는다 (사람만 가능) |
|---|---|
| A. 원문의 숫자·등록번호·이메일·날짜가 번역에서 사라짐 | 문장이 어색한지, 존대 수위가 맞는지 |
| B. 카자흐어 값이 러시아어와 글자까지 동일 | 의료 용어가 그 나라 환자에게 실제로 통하는지 |
| C. 러시아어·카자흐어 자리에 키릴 0 (미번역) | 문화적으로 무례하거나 오해되는 표현 |
| D. 용어집 위반 (locked=차단, proposed=경고) | 카피가 설득력이 있는지 |
| E. `{name}`·`%s` 자리표 개수 불일치 | |
| F. 목록에서 「•」 항목이 통째로 빠짐 | |

- **지금 막는 언어는 ru·kz 뿐이다.** 첫날부터 전부 빨강이면 아무도 초록불을 안 믿기 때문 —
  그 언어를 0건으로 만든 뒤 `BLOCKING_LANGS` 에 넣어라.
  - ⚠️ **예외 하나: 「F. 항목 유실」은 언어를 가리지 않고 막는다.** 응급 증상·주의사항 목록에서 줄이
    통째로 빠지는 것은 환자 안전 문제라 「1차 타깃부터」로 미룰 수 없다.
    (2026-08-21 실측: 중국어 위암 운동 안내에서 **「식후 1시간 이내 격렬한 운동 금지」를 포함한
    주의사항 3줄이 통째로** 빠져 있었다. 일본어는 5개 안내에서 마지막 한 줄씩 잘려 있었다. 전부 채웠다.)
- ⚠️ **「en·zh·ja 에 34건 남아 있다」고 적었던 앞 판(2026-08-20)은 틀렸다.** 그 34건을 하나씩 열어보니
  **진짜 결함은 12건**이었고 나머지는 **검사기 자신의 오탐**이었다 — 영어·중국어·일본어 날짜 표기
  (`February 2026`·`2026年2月`)를 몰라 정상 번역을 「사실 유실」로 세고, 전화번호 예시 같은
  자리표시문을 원문과 대조하고 있었다. 진짜 12건은 고쳤고 오탐은 검출기를 고쳐 없앴다.
  **교훈: 검사가 뱉은 숫자를 문서에 단정형으로 옮기기 전에 그 목록을 실제로 열어봐라.**
- 오탐이 나오면 **검사를 끄지 말고 허용목록**(`LATIN_OK`·`KZ_RU_SAME_OK`·`TRANSLITERATED_PROPER`·
  `UNIT_CONVERTED_KEYS`)에 근거와 함께 넣어라.

## 3. 용어집 운영 — `proposed` 를 `locked` 로 올리는 게 이 문서의 목적

- `locked` = 확정. 어기면 CI 가 **막는다**. 사실·표준·브랜드 표기처럼 다툼의 여지가 없는 것만.
- `proposed` = 제안. **경고만.** 원어민이 확정해 주면 `locked` 로 올리고, 사전(dictionary.js)의 기존 값도 같이 정리한다.
- 확정이 필요한 건 「어느 단어가 맞나」가 아니라 「우리가 뭐라고 부르기로 하나」다 — **이건 코디네이터·PO 결정이지 개발 판단이 아니다.**

**코디네이터에게 물을 때**: `docs/i18n/용어확정_요청_코디네이터.md` 를 그대로 전달하면 된다
(무엇이 몇 군데서 어떻게 흔들리는지 숫자로 적혀 있어, 코디네이터는 «고르기만» 하면 된다).

**승격 절차**: 코디네이터가 단어를 골라 주면 → `status: "locked"` 로 바꾸고 → `avoid` 에 다른 표기를 넣고 →
`npm run check:i18n-quality` 로 위반 목록을 뽑아 → 사전 값을 전부 그 단어로 통일 → 커밋.

## 4. 코디네이터 교정을 되먹이는 길

| 무엇을 고치나 | 어디서 | 누가 |
|---|---|---|
| 병원·치료 정보(이름·설명·태그·진료과) | 어드민 → 병원/치료 관리 → 번역 패널 (**2026-08-20부터 ru·kz 탭 열림**) | 코디네이터가 직접 |
| 화면 고정 문구(버튼·안내·FAQ) | `src/lib/i18n/dictionary.js` — 코드라서 개발 세션을 거친다 | 코디 지적 → 세션이 반영 |

**화면 고정 문구를 고칠 때 지켜야 할 것**: 그 교정이 «한 문장 고침»으로 끝나면 같은 실수가 다음 화면에서 또 난다.
→ **고칠 때마다 「이게 용어 문제인가?」를 묻고, 맞으면 용어집에 넣어라.** 그래야 그 지적이 마지막이 된다.

## 4-1. 환자에게 «직접» 나가는 글 — 번역보다 앞서는 세 가지 (2026-09-09 PO 교정 5회)

문의 #330(반복 대량 비출혈) 회신을 쓰면서 PO 가 다섯 번 되돌렸다. 번역 품질이 아니라
**한국어 원문에서 이미 틀어져 있던 것**들이라 여기 남긴다. 러시아어로 옮기기 «전»에 이 셋을 본다.

**하나. 단정과 지시를 빼라 — 남의 병원을 나무라는 말이 된다.**

| 쓴 것 | PO 지적 | 고친 것 |
|---|---|---|
| 「원인이 아직 안 나온 이유는 이렇습니다」 | *«단정 짓지 말고 완곡하게. 실제 의료진도 이 자료만 보고 그렇게 얘기하지는 않겠다»* | 「저희는 보내주신 서류에 보이는 것만 말씀드릴 수 있습니다. 진찰하신 의사들은 더 많이 알고 계실 것이고, 저희는 그 기록을 보지 못했습니다」 |
| 「다음에 출혈하면 코를 막기 전에 내시경으로 봐 달라고 하세요」 | *«병원 가서 지혈한거 아닐까»* | 통째로 뺐다. **대량 출혈에 토혈까지 있으면 지혈이 먼저**고 그 처치는 옳았다. 우리는 코디네이터이지 그 환자의 주치의가 아니다 |
| 「현지에서 이 검사들 받고 오세요」 | *«이미 검사 다 받았는데 또 받으라면 열받지 않음?»* | 「한국에 오시면 세 검사를 한 병원에서 하루 이틀 안에 다 받으시고, 한 의사가 결과를 모아서 봅니다」 |

→ **주어를 우리 쪽으로 돌려라.** 「그쪽이 못 찾은 이유」가 아니라 **「우리 손에 없는 것」**,
「이렇게 하세요」가 아니라 **「이게 있으면 도움이 됩니다」**, 「가서 받아오세요」가 아니라
**「오시면 한 번에 받으실 수 있습니다」**.

**둘. 미루는 말을 쓰지 마라 — 아는 것은 그 자리에서 이름을 대라.**

「어떤 검사인지는 저희가 알려드리겠습니다」라고 썼더니 PO — *«어떤 검사인지 니가 알아? 애매한 표현은 빼라»*.
실제로 이미 알고 있었고 소견 초안에 세 개를 적어둔 상태였다. **「추후 안내」·「가급적」·「필요시」도 같은 부류.**

**셋. 자료를 달라고 할 땐 「받아도 되는 수준」이 아니라 「필요한 수준」을 말해라.**

「휴대폰 사진도 괜찮습니다」라고 썼더니 PO — *«그케 하니깐 니가 판독하기 어렵다매. 대충 찍어서 보내겠지»*.
실측: 이번에 온 **CT 필름 사진은 가로 1,058·1,107픽셀**이라 촬영일조차 못 읽었다(판독지 종이 사진은 읽혔다).

| 자료 | 이렇게 요청한다 |
|---|---|
| 종이 서류(판독지·검사결과·진료기록) | ①스캔본·PDF 가 가장 좋다 ②사진도 되지만 **「글자가 읽힐 만큼 선명하게」**, 밝은 곳·한 장에 한 페이지·반사 없이 ③**「흐리면 다시 부탁드려야 해서 그만큼 늦어집니다」**를 붙인다 |
| CT·MRI 영상 | **원본 파일**(병원이 주는 CD·USB = DICOM, 또는 병원 온라인 보관함 주소). 필름을 찍은 사진은 판독이 안 된다. **「원본을 구하기 어려우시면 알려주십시오」**로 막다른 길을 만들지 않는다 |

⚠️ **금지가 아니라 우선순위로 적어라.** 「찍지 마세요」는 원본을 못 구하는 사람에게 막다른 길이 된다.

## 5. 이 규칙이 생기기 전에 실제로 나갔던 것 (재발 판정 기준)

- 지점 주소 4곳: 한국어 `서울특별시 강서구 마곡중앙6로 93 (마곡동, 열린프라자) 6,7,10층` → 러시아어 `Магок, Кансо-гу, Сеул`.
  **환자가 병원을 찾아갈 수 없는 상태로 나가 있었다.**
- 카자흐어 FAQ: 외국인환자 유치업자 **등록번호가 통째로 누락**(법정 표기).
- 카자흐어 환자 교육자료: 「🟡 주의 (24시간 내 연락)」의 **시간이 사라지고**, 응급 증상 항목이 2~3개씩 빠짐.
  갑상선암 편에서는 **「38.5°C 이상 고열」이 응급 목록에서 통째로 빠져** 있었다.
- 알림 시간 표시가 러시아어·카자흐어에서 영어 약자(`d`/`h`/`m`/`s`).
- 카자흐어 달력의 토요일이 러시아어 약자 `Сб`(카자흐어는 сенбі → `Сн`).
- **암종 선택지가 장기 이름이었다** — ru 「Лёгкое」(폐)·「Грудь」(가슴)·「Толстая кишка」(대장).
  환자가 자기 암을 고르는 화면인데 「폐암」이 아니라 「폐」라고 적혀 있었다. 코디가 이미 DB 에서
  고쳐 뒀는데도 **코드는 몰랐다**(0-2 참조).
- 라틴 `AI` 가 키릴 문장에 박혀 있었다(ru 5곳·kz 13곳) — 러시아어는 `ИИ`, 카자흐어는 `ЖИ`.

같은 부류가 또 나오면 **검사가 못 잡은 새 유형**이라는 뜻이다 — 문장만 고치지 말고 검출기를 늘려라.
