1. **한 변이 2048px 를 넘으면 PO 폰에서 깨진다.** 가로·세로 **둘 다 2048px 미만**으로 렌더할 것.
   ⚠️ 함정은 「세로로 긴 몽타주」다 — 여러 장을 위아래로 이어 붙이면 조용히 넘어간다. **세로로 길면 4장씩 쪼개라.**
2. **눌러서 조작하는 위젯은 PO 폰에 아예 안 뜬다.** 로고·디자인 시안 비교를 위젯으로 띄웠더니 PO: *"안보인다고 한건 로고잖아"*.
   → 시안·비교는 **반드시 정적 이미지**(JPG/PNG)로 만들어 `SendUserFile(display:"render")`. **위젯을 결정용으로 쓰지 마라.**
   고르게 할 땐 `AskUserQuestion` 버튼(폰에서 정상 동작).
3. **편집해야 하는 산출물(발표자료 등)은 채팅 카드만 주지 말고 «쉬운 경로»에 복사하고 경로도 같이** 적어라 (PO: *"경로 달라"*).

## 🛑 원격 세션(Claude Code on the web)에서는 브라우저가 바깥으로 못 나간다 (2026-07-30 실측)

**웹·앱에서 띄운 원격 세션이면 브라우저로 외부 주소를 아예 못 연다.** 통신이 중계서버(프록시)를 타야 하는데 **그 중계서버가 브라우저 통신을 안 받는다.**

- 증상: `net::ERR_CONNECTION_RESET`. **우리 사이트만 그런 게 아니라 `https://example.com` 도 똑같이 실패**한다 → 이게 보이면 사이트 문제로 오해하지 말고 바로 포기하고 다른 길로 가라.
- `--proxy-server` 로 중계서버 주소를 알려줘도, QUIC 을 꺼도 동일. 인증서 문제가 아니다(인증서 오류였다면 `ERR_CERT_*` 가 뜬다).
- 🔎 **판별법:** `chromium --headless --proxy-server="$HTTPS_PROXY" --dump-dom https://example.com` 를 돌려 결과에 `neterror` 가 섞여 나오면 이 환경이다.

**대신 되는 것 / 안 되는 것**

| 확인하려는 것 | 원격 세션에서 |
|---|---|
| 번역 누락·제목·설명·구조화 표시·hreflang·상태코드 | ✅ **된다** — 주소 조회(`curl -H "Accept-Language: ru-RU,ru"`)로 서버가 그려 보낸 글자를 다 볼 수 있다 |
| 화면 배치 깨짐·글자 삐져나옴·색·스크린샷 | ❌ **안 된다** — PO 손이나 PC 세션 필요. 「못 봤다」고 명시해라 |
| 클릭이 필요한 흐름(입력·제출) | ❌ 안 된다 |

⚠️ **이걸 모르면 20분을 날린다.** 2026-07-30 에 Playwright 를 설치하고 중계서버 설정을 두 번 바꿔가며 18개 화면을 훑었는데 **전부 실패**였다. 계획 단계에서 갈라라 — 화면을 눈으로 봐야 하는 일은 이 환경에 배정하지 마라.

⚠️ **언어별 화면을 흉내낼 땐 IP 가 아니라 「브라우저 언어」다.** 우리 사이트는 접속자 IP 를 아예 안 본다(`proxy.ts:68` — `accept-language` 만 읽는다. IP 국가를 읽는 코드는 저장소 전체에 0곳). 즉 **VPN 으로 나라를 바꿔도 언어는 안 바뀐다.** 러·카 화면 확인은 `Accept-Language` 헤더(또는 브라우저 언어 설정)만 바꾸면 되고 **VPN 은 필요 없다.**

- 브라우저 조작은 `preview_start`(dev 서버) → `read_page`(구조·텍스트) → `javascript_tool`(계산된 스타일 등) 순으로.
  스크린샷은 `computer{action:"screenshot"}` — 다만 **텍스트·구조 확인은 `read_page` 가 더 빠르고 정확**하다.
- 시각 확인 필요 시 Vercel preview URL 사용자에게 제공.

## 로그인 뒤 화면 (2026-07-28 정정 — 이전 서술이 도구 현실보다 낡았다)

**옛 서술(원문 그대로 보존):**

> - **로그인 뒤 화면은 로컬에서 못 연다** (미들웨어 `proxy.ts` 가 세션 없으면 `/login` 으로 보냄).
>   백오피스·환자포털을 눈으로 봐야 하면 **Vercel preview URL 을 PO 에게 주고 확인받는다** — 로컬에서 본 척하지 말 것.

**실제:** 브라우저로 그냥 열면 못 보는 게 맞다(미들웨어 `proxy.ts` 가 세션 없으면 `/login` 으로 보냄). 하지만 **자동 검증(Playwright)에는 역할별 로그인 세션을 파일로 저장해 두는 장치가 이미 있다** — `e2e/auth.setup.ts` 가 역할당 1회만 로그인하고 `storageState` 로 쿠키를 저장한다.

- **세션 저장이 되는 역할(5개):** `patient` · `admin` · `coordinator` · `agency` · `clinic`
  — 각각 `E2E_TEST_USER_EMAIL` · `E2E_ADMIN_EMAIL` · `E2E_COORDINATOR_EMAIL` · `E2E_AGENCY_EMAIL` · `E2E_CLINIC_EMAIL` 이 설정된 경우에만. 미설정 역할은 스킵된다.
- **🕳 구멍: `hospital`(국내병원) 역할은 아예 목록에 없다.** 그래서 `/hospital/profile`·`/hospital/treatments` 는 **어떤 방법으로도 자동 확인이 안 된다.** 2026-07-28 핸드오프의 "계정 접근 불가로 못 봄" 이 바로 이것 — 계정을 몰라서가 아니라 **애초에 목록에 없어서**다.
- `E2E_*` 키는 `.env.example` 에도 없어서 새로 세팅하는 사람이 존재 자체를 모른다.

**그래서 지금 규칙:**
1. 백오피스 화면을 확인해야 하면 **먼저 해당 역할의 E2E 세션으로 여는 길이 있는지 본다**(위 5개면 있다).
2. 없으면(= `hospital`) **로컬에서 본 척하지 말고** Vercel preview URL 을 PO 에게 주고 확인받는다.
3. 어느 쪽도 못 했으면 **"직접 동작 검증 못 함"이라고 명시**한다.
