## ⚠️ 상시 루틴 — 오류는 기계가 잡는다 (PO가 화면에서 찾게 두지 말 것)

**왜:** 옛 모델 콘텐츠 잔재(옛 브랜드·이메일·일부 언어만 적힌 목록 등)를 PO가 스크린샷으로 하나씩 찾는 일이 반복됨. → 사람이 아니라 **자동 검사로 매번 차단**.

- **콘텐츠/브랜드 변경 시**: `npm run check:content` 통과 확인 (CI 매 PR 자동). 옛 브랜드/이메일 잔재·i18n 활성6 언어(ko·en·ru·kz·zh·ja) 키 누락이면 빌드 실패.
- **버그·누락 발견 시 (반응형 금지, 아래 4단계 필수)**:
  1. **반성문**: `docs/POSTMORTEMS.md`에 1건 기록 — 무슨 일 / 왜 못 잡았나(근본원인) / 어떻게 고쳤나 / 재발 방지. **쓰기 전에 과거 반성문에서 같은 부류를 먼저 검색**(grep 키워드) — 재발이면 제목에 **「🔁 #NN 부류 재발」**을 달고, 그때의 방지책이 왜 못 막았는지 1줄 + 그 가드의 보강까지 포함하라(재발률 = 기억 시스템 성적표, 2026-07-05 PO 승인).
  2. **유사 이슈 추가 스캔**: 같은 부류가 다른 데 더 없는지 전수 확인.
  3. **가드 룰 추가**: 가능하면 `scripts/check-content-consistency.mjs`에 **새 검사 룰을 추가**해 그 부류를 영구 차단.
  4. **보고**: 근본원인+방지책을 PO에게 보고.
- 새 i18n 검사 기준: 활성 언어는 **6개(ko·en·ru·kz·zh·ja)**. 언어 목록·"지원 언어" 류 카피는 항상 6개 다 포함(특히 핵심 타겟 **러시아어·카자흐어** 누락 주의).
- **주 1회 문서 건강검진(`/doc-health`, 2026-07-05 PO 승인)**: 살아있는 문서(핸드오프·KNOWN_ISSUES·취향·관문 등)끼리의 모순, 코드 현실과 어긋난 항목(#63 문서-현실 드리프트 부류), 죽은 파일 참조를 스캔해 교정. 세션 시작 훅이 마지막 검진 7일 경과 시 리마인드하며, 기록은 `docs/audit/DOC_HEALTH_LOG.md`. **낡은 문서 = 낡은 기억을 믿고 일하는 사고의 씨앗**이라 사람이 아니라 루틴이 잡는다.

## 🎯 「A 를 고쳤는데 파생된 B 가 고장난다」 — 고치기 «전»에 반경을 본다

> 2026-08-06 PO 질문(*"원천적으로 이런 일이 없게 할 수 없어?"*)에서 만든 것. 도구 = `npm run blast`.

**실측 근거**: 반성문 175건 중 「🔁 부류 재발」 40건+. 그중 상당수가 «내가 A 를 고치다 B 를 깬 것»이다.
`#106`(부품을 지우며 그 안의 응급전화 동선까지 삭제 — 한 달간 0개) · `#27`(favicon.svg 를 지웠는데
sw.js 가 계속 불러 앱 설치 배너 소멸) · `#140`(라벨 일괄수정이 문의폼 12칸을 한 줄씩 밀어냄).

**왜 기존 검사 30여 개로 안 막혔나**: 그것들은 전부 **«알려진 규칙» 목록**(금지 토큰·번역 누락·유령 컬럼)이다.
목록에 없는 새 파손은 원리상 못 본다. `#106` 기록의 문장이 핵심을 짚었다 —
> "grep 은 «이 부품을 누가 쓰나»에는 답하지만 «이 부품 «안»에 뭐가 살고 있었나»에는 답하지 않는다."
> "«이 라우트로 «들어오는» 링크가 있나»는 어느 가드도 안 봤다."

**그래서 뭘 하나** — 목록이 아니라 **관계**를 본다. 무엇이 깨질지는 몰라도 «어디까지 닿는지»는 안다.

| 축 | 무엇을 보나 | 막는 부류 |
|---|---|---|
| ⓪ 부품 연결 **밖** | **DB 표**를 바꾸면 그 표를 쓰는 코드 전부 / **환경변수** / 「이거 하나면 전 화면」인 파일 | `#94`·`#95`·`#103` (표·칸 부류 **14건**) |
| ① 들어오는 방향 | 내가 건드린 것을 **누가 쓰나** → 몇 다리 건너 어느 화면까지 닿나 | 파생 파손 일반 |
| ② 같이 사라진 것 | 지운 줄에 섞여 있던 **기능**(전화 링크·화면 이동·서버 호출·내놓은 함수) | `#106` |
| ③ 아직 부르는 곳 | 지운 **파일**·사라진 **화면 주소**를 글자로 아직 부르는 곳(부품 연결 밖 — 빌드·타입검사가 안 보는 자리) | `#27` · `#31`·`#107`·`#104` (404 부류 **11건**) |
| ④ 검사 공백 | 반경 안의 화면 중 **자동 검사가 없는 것** = 내 눈으로 봐야 하는 목록 | 「됐다」 오보 |

**⓪이 왜 따로인가**: `#94`·`#95` 는 **코드를 한 줄도 안 고치고** 표에 지키기 규칙만 하나 걸었는데
채팅 전송이 통째로 500 이 났다(화면엔 무증상). 코드 변경이 0 이면 부품 연결 그래프에는 씨앗이
아예 없다 — DB 경유가 유일한 길이다. 기존 `check:schema-refs`·`check:ghost-columns` 는
**「코드 → DB」** 방향(이 코드가 없는 칸을 쓰나)을 본다. ⓪은 **반대 방향**(DB 를 바꿨는데 어느 화면까지 가나)이다.

**어디에 붙어 있나 (넷 다 자동)**
1. **고치기 «전»** — 파일을 열 때 훅(`.claude/hooks/blast-radius-warn.mjs`)이 반경이 넓을 때만 한 번 알린다.
   ⚠️ 훅 등록은 **세션이 시작될 때** 읽힌다 — 등록한 그 세션에는 안 뜨고 **다음 세션부터** 뜬다.
   (만든 세션에서 「안 뜨네」로 고장 판정하지 마라. 손으로 확인하려면 `npm run blast`.)
2. **합치기 «전» — 지도** — 자동 검사가 실행 화면 요약에 반경 지도를 남긴다(비차단).
3. **합치기 «전» — 실행** — `npm run blast:verify` 가 **반경 안 화면의 여정 검사를 골라 실제로 돌린다**
   (자동검사에선 `Blast Radius E2E (PR)` 라는 **별도 잡**).
   왜 필요한가: 신청서에는 빠른 검사(`@smoke`) 24개만 돌고 전체 여정 검사는 본판에 합친 «뒤»에만 돈다.
   그런데 파생 파손은 정의상 «내가 안 열어본 화면»에서 나므로 빠른 검사 목록에 있을 이유가 없다 —
   **구조적으로 머지 후에야 발견되던 것**을 앞당긴다. 지금은 비차단(시간 상한 6개, 잘린 건 반드시 출력).
   한 주 돌려 헛경보 0 이면 차단으로 승격.
   ⚠️ **왜 별도 잡인가 (첫 판의 실수)**: 처음엔 빠른 검사 잡 «안»에 붙이고 「비차단」이라고 적었다.
   그런데 검사 설정은 자동검사 환경에서 서버를 재사용하지 않아(`reuseExistingServer: !CI`)
   dev 서버를 **한 번 더** 띄운다(부팅 상한만 240초). 그러면 잡 시간 상한을 넘기는데,
   **`continue-on-error` 는 «단계»만 덮지 «잡 시간초과»는 못 덮는다** — 「비차단」이라 적어놓고
   실제로는 멀쩡한 신청서를 빨간불로 만드는 구조였다. 떼어내니 빠른 검사와 **병렬**로 돌아
   총 시간도 안 늘고 진짜 비차단이 됐다.
4. **손으로** — `npm run blast` (기준 바꾸기 `--base`, 과거 커밋 되짚기 `--commit <sha>`).

**⚠️ 일부러 «차단하지» 않는다.** 이건 문지기가 아니라 지도다. 차단으로 만들면 회피하게 되고,
그 순간 「고친 것처럼 보이는데 안 고쳐진 상태」가 된다(`CLAUDE.md` 규칙 7-③). 정보는 판단을 바꾸지만
차단은 우회를 부른다. 대신 **④의 「검사 없는 화면」은 완료 보고의 «확인 못 한 것» 칸에 그대로 옮겨라**(규칙 14).

**이걸로도 «못» 잡는 것 (정직하게)** — 2차 확장으로 DB 표·환경변수·화면 주소·전역 파일까지 덮었지만
아직 남는다: **접근권한 규칙(RLS) 변경**, **동적 화면 주소**(`/consult/[id]` 처럼 값이 끼는 것 —
글자로 맞출 수가 없어 일부러 뺐다), **실행 중에 불러오는 부품**, **표의 «칸» 단위 변경**
(지금은 표 단위까지만 본다). 그 부류는 여전히 사람이 봐야 하고, 나면 위 4단계(반성문→전수 스캔→가드→보고)로 돌아온다.

**가드의 가드**: `scripts/__tests__/blast-radius.test.ts` 가 실제 과거 사고 커밋을 재현해 잡히는지 시험한다.
채택 전에 **변이 3종**(정규식 되돌리기·삭제파일 추적 되돌리기·중복제거 빼기)을 넣어 전부 빨간불이 켜지는 걸
확인했다 — 「통과하는 가드는 증거가 아니다」(`#106` 교훈).

## 🛑 감사를 «언제 그만 파나» — 「더 파면 또 나온다」의 답

> 2026-08-06 PO: *"또 더 파라고 하면 또 고칠거 나올거지?"* → 팠고, 나왔다.
> 다시: *"더 파라고 하면 또 고칠거 있다고 할거지?"* → **이건 조사 지시가 아니라 「끝이 있느냐」는 질문이다.**
> 답: **파면 계속 나온다. 그래서 「나오느냐」가 아니라 「고칠 값어치가 있느냐」로 멈춤을 정한다.**

그날 5라운드에서 나온 것들을 무게순으로 세우면 규칙이 저절로 보인다:

| 라운드 | 나온 것 | 안 고쳤으면 |
|---|---|---|
| 1~2차 | 기능이 아예 안 됨 (표만 바꿔도 화면까지 안 이어짐) | **사고가 남** |
| 3~4차 | 초록불인데 실은 안 본 것 (목록 잘림·판정 샘·시험이 건너뛰어짐) | **사고를 못 잡음** |
| 5차 | 없는 파일에 거짓 경보 | 좀 시끄러움 |

**계속 파라 — 단 아래 둘 중 하나에 걸릴 때만 «고쳐라».**
1. **실서비스가 고장나나** (사용자가 못 하게 되는 일이 생기나)
2. **잘못된 안심을 주나** (초록불인데 실은 안 봤나 / 「됐다」가 사실이 아니게 되나)

둘 다 아니면 **고치지 말고 「찾았고 안 고쳤다 + 왜」를 적어라.** 그게 정직한 멈춤이다.
자잘한 경보 문구·희귀한 경계값을 계속 고치는 건 **일하는 것처럼 보이지만 값어치가 없고**,
그 시간에 PO 는 「아직도 안 끝났나」를 본다.

⚠️ **거꾸로, 이 기준을 「그만 파도 된다」는 면허로 쓰지 마라.** 2번(잘못된 안심)이 특히
잘 새는데, 그건 증상이 «없어» 보이기 때문이다 — 초록불은 조용하다. 그날 5개 중 3개가 이 부류였고
**전부 내가 만든 것**이었다. 판정이 애매하면 판다.

📌 **그리고 순서: PO 가 묻기 «전»에 내가 판다.** 그날 5개 중 4개는 PO 의 되물음에서 나왔고
자발은 1개뿐이었다. 「다 됐다」고 말하기 전에 이 감사를 먼저 돌리고 **결과까지 붙여** 보고하라
(`CLAUDE.md` 실측·재검증 7번과 같은 몸통).

→ 원인은 성의가 아니라 **기준**이었다.

| 기준 | 결과 |
|---|---|
| `git rev-list origin/main..<작업본>` (커밋이 본판에 있나) | 스쿼시 머지 때문에 **190개 중 141개가 가짜 「미머지」** — 진짜 3건이 137건에 묻힌다 |
| **`gh pr list --state all`** (이 작업본으로 신청서를 올린 적이 있나) | 190 → 13 → **실제 3건** ✅ |

**기준이 틀리면 아무리 오래 봐도 같은 곳에서 막힌다.** 세는 일을 시작하기 전에 기준을 한 줄로 말하고 시작하라.
같은 결: 「추측으로 단정 금지, 실측으로」 · 「원인 지목 전 반증 검사」(`CLAUDE.md` 실측 절).

**「말로만 하지 말고 보여달라」** — PO 가 *"저장바 스티키 문제가 뭔데 말로만 하지 말고 좀 보여달라고"* 라고 직접 요구했다. 글로 「스티키가 안 듣는다」고 설명한 것을 PO 는 몸으로 못 느낀다. → **증상을 실서비스에서 그대로 재현해 스크린샷 + 실측값**(「문서 10,985px 중 버튼은 10,889px 지점」)을 보여줘라. 원인 설명은 그 다음이다.

## 경보·알림 설계를 「메일로 갑니다」로 끝내지 마라

PO 는 메일을 상시 보지 않는다. 2026-07-28 업타임 감시를 붙였을 때 PO 질문:
*"그럼 메일에서 맨날 확인해야 하는거임? 내가 메일 안보면 어케 함?"*

- 알림 채널을 정할 때 **PO 가 실제로 즉시 보는 매체(폰 푸시·메신저)** 까지 확인해야 「알림을 붙였다」가 성립한다.
- 요금 경계도 같이 실측해서 준다. (2026-07-28 실측 — UptimeRobot 무료 = 폰 앱 푸시·디스코드·구글챗 / 유료 = 텔레그램·슬랙·웹훅·MS팀즈)

## 곁다리로 발견한 것도 그 자리에서 닫아라 (취향 원장에서 이관 — 2026-08-06)

화면 검증 중 404 2건을 「곁다리, 범위 밖이라 손 안 댔다」고 적었더니 PO *"404은 뭔데 잡은 김에 해결해봐"*. 파보니 **내가 없는 주소를 찍어서 만든 가짜**였다.
→ 발견을 보고만 하고 넘기면 (a)진짜면 다음 턴에 다시 시킨다 (b)가짜면 허위 보고로 남는다. **발견 즉시 원인까지 확정하고 「진짜/가짜 + 고칠지 말지」로 끝내라.**

## 🔁 PO 가 「또 내가 확인해야 하냐」고 하면 = 자동화 지점이다 (2026-08-19)

PO *«또 내가 하나씩 눌러가면서 테스트해야겠니?»* 에 대한 답은 **«제가 다시 눌러볼게요»가 아니다.**
그 자리에서 여정 자동 클릭 검사를 만들었고, **그 검사가 곧바로 진짜 결함을 잡았다** —
첫 방문자는 쿠키 동의 띠에 「보내기」가 덮여 **접수를 못 할 수 있었다**(사람 눈으로는 한 달을 봐도 못 봤을 자리).

- **PO 가 「확인」을 반복 요구하는 지점 = 사람이 매번 하던 일** → 그걸 기계가 매번 하게 바꾼다.
- 만든 검사는 **일부러 깨뜨려 실제로 잡히는지**까지 보여라(안 깨지면 그건 검사가 아니라 장식이다).
- 검사가 실서비스에 무언가를 넣는다면(문의·파일·메일) **시험 표시·반송 방지·뒷정리**를 같이 설계해라.
