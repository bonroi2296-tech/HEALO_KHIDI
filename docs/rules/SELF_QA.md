## ⚠️ 출시 전 self-QA (PO가 일일이 테스트하지 않아도 되게 — 필수)

**"빌드 통과 ≠ 동작."** `next build`는 문법만 검사함. 출시(커밋) 전 아래를 직접 검증:

- **DB/데이터 기능**: 쿼리 짜기 전 RLS 정책 확인(`pg_policies`). `inquiries` 등 민감 테이블은 service_role 전용 → **브라우저 client 직접 쿼리 금지, 서버 API 경유**. 암호화 컬럼(`*_encrypted`, first_name 등)은 표시 전 복호화 필요.
- **데이터 흐름 추적**: 폼→API→DB→표시 전 경로를 실제로 따라가 확인 (Supabase MCP로 실데이터 조회, Vercel 런타임 로그 확인).
- **인증/권한**: 새 API는 `requireAdminAuth`/`requireConsultationAccess`. 권한은 `app_metadata.role` + `ADMIN_EMAIL_ALLOWLIST` 둘 다 고려.
- **사용자 화면**: 가능하면 배포 후 실제 클릭/조회로 확인. 못 하면 "직접 동작 검증 못 함"이라고 명시.
- **소프트 삭제 원칙**: 계정·기록은 하드 삭제 X (FK·기록 보존, 비활성/role 플래그 토글).
- 검증 못 한 부분은 **"검증 못 했음"이라고 솔직히 보고** — "됐어요" 남발 금지.

### ⭐ 실측·재검증이 기본값 (전문 — 요약은 `CLAUDE.md`)

- **⭐ 실측·재검증이 기본값 (PO 취향 10회+ 반복 확정 → 2026-07-15 고정규칙 승격)**: ①빌드·tsc·HTTP 200·404 안 남 = *화면이 그려지는지*일 뿐 **동작 아님** → 의미 있는 흐름은 실제 여정을 클릭/실호출/실DB로 검증. ②PO가 **"완벽해?/오픈 확정?/이상하다·개판이야"**라고 되물으면 안심시키지 말고 **그 자리에서 실측·감사·점수표(근거)로** 답하라(특히 내가 직전에 "다 됐다"고 한 직후일수록 방어 0·실측 100). ③**추측으로 단정·우기기 금지** — 화면 정체·테이블/컬럼 존재는 실제 파일·`information_schema`로 확인 후 말하고, 틀리면 빨리 인정. ④**남의 결과(AI 감사·에이전트·외부도구)뿐 아니라 내 과거 문서·1차 분석도 재질문받으면 그 자리에서 재현·재검증**하고 틀리면 문서 정정. (원문 10건 = `docs/PO_PREFERENCES.md` 「보관」 A그룹.)
  - ⑤ **원인 지목 전 반증 검사 (2026-07-21 추가 — 사실은 맞는데 결론이 틀리는 부류)**: "X가 원인이다"라고 말하기 **전에**, *X가 진짜 원인이면 무엇이 참이어야 하는가*를 1줄 적고 그걸 먼저 확인하라. 통과 못 하면 X는 원인이 아니다. **큰 숫자를 찾은 것 ≠ 원인을 찾은 것.** 특히 증상을 PO에게 확인하지도 않고 원인부터 찾아 나서는 것 금지(무슨 작업이·언제·얼마나 느린지부터).
    - 실패 사례(2026-07-21): 「세션시작 훅 96KB가 원인」→ *원인이면 첫 턴만 느려야 함*을 안 따져 오진(캐시 무시). 「클로드 창 10개가 원인」→ *창이 10개여야 함*을 안 따져 오진(실제 2개, Electron 헬퍼를 창으로 오인). **둘 다 이미 손에 있던 데이터로 반증 가능했고, PO가 되물어서야 잡혔다.**

- **⑥ 내가 만든 «말»은 내가 「됐다」고 못 한다 — 원어민·현장 사용자 검수가 남았으면 그렇게 적어라 (2026-07-29 PO 결정)**:
  어시가 러시아어·카자흐어 화면 문구를 수백 개 만들었을 때, 기계로 잴 수 있는 것(남은 한국어 0건·키가 값으로 새지 않음·화면 안 깨짐)은 실측으로 닫았지만 **「이 러시아어가 자연스러운가」는 잴 수 없다.**
  PO 판단: 그 검수는 **현지 직원(코디) 몫**이고, 어시는 «만들고 → 못 잰 부분을 못 쟀다고 적고 → 지적이 오면 코드로 고친다». → 번역·카피를 낼 때 **「기계로 확인한 것」과 「사람이 봐야 하는 것」을 갈라 보고**하고, 후자를 「완료」로 적지 마라.

- **⑦ PO 가 가져온 자료를 «README 요약»만 보고 판정하지 마라 — 그리고 「쓴다/안 쓴다」 이분법으로 답하지 마라 (2026-08-20)**:
  PO 가 한국어 말투 설정 저장소(`github.com/snflkd/fluent-korean`)를 가져와 *«이거 설치하면 도움이 되겠니?»* 라고 물었다. 나는 README 설명만 보고 **«우리 개조식 보고서 문체와 충돌한다»고 단정**했는데, 나중에 본문을 열어보니 **그 문서가 헤더와 목록을 예외로 명시**하고 있었다. 내 판정이 과장이었고 정정해야 했다.
  본문을 실제로 열어보니 지침 4개 중 **3개가 우리 훅에 없었고, 그중 하나는 PO 가 바로 그날 지적한 줄표(—) 문제와 정확히 같은 항목**이었다. 즉 자료는 값을 했는데 내 첫 판정이 그걸 가릴 뻔했다.
  → **①판정 전에 원문을 열어라**(요약은 그 저장소 저자가 무엇을 강조하고 싶었나이지 내용 전부가 아니다). **②답은 「채택/기각」 둘이 아니라 셋이다 — 알맹이만 뽑아 우리 자리로 옮기는 길이 대개 제일 낫다.** 이번엔 알맹이 3개는 말투 훅으로 옮기고, 원본은 다른 폴더 전용으로 돌려서 둘 다 살렸다.

## 돈·성과 숫자를 말하기 전에 — 「권위 있는 화면」에서 확인하라

> 2026-07-28 취향 원장에서 이관. 원문 경위는 `docs/PO_PREFERENCES.md` 「보관」.

**숫자를 단정하기 전에 「그 숫자를 가장 정확하게 아는 화면」을 열어라 — 요약 화면의 합계로 결론내지 마라.** 하루에 같은 부류로 두 번 틀렸다.

1. Vercel 사용량 화면 아래 합계 4줄을 계산해 *"이미 $0.30 초과됐다"* 고 보고 → PO *"어느 표에 0.3달러가 추가 됐다는거임? 뭔 소리야"* → **청구 설정 화면을 여니 「다음 청구 예정액 $20.00」, 초과 0원.** 사용량 화면의 두 숫자는 갱신 시점이 달라 앞섰다 뒤졌다 한다(같은 날 +$1.30 / −$0.30 관측).
2. 추정치 정확도를 *"오차 1% 안쪽"* 이라 발표 → **「빌드비 추정」을 「크레딧 총 소진액」과 비교한 오류**(같은 항목끼리 재니 ±10%). 그 문구가 어드민 설명서로 실서비스까지 나가 정정 배포까지 갔다.

→ **규칙: (a) 돈·성과 숫자는 요약 화면 말고 「권위 있는 화면」(청구서·원장)에서 확인하고 말한다 (b) 정확도를 주장할 땐 「무엇과 무엇을 비교했는지」 한 줄을 반드시 같이 적는다** — 그 한 줄만 적었어도 둘 다 스스로 잡혔다.
