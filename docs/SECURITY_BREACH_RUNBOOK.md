# 개인정보 침해(유출) 대응 런북

> 개인정보 유출·침해 의심 시 **이 순서대로**. GDPR Art.33-34(72시간) / 개인정보보호법 §34 통지·신고 의무 충족용.
> 최종 갱신: 2026-06-29. ⚠️ 변호사 검토 전 초안 — 실제 사고 시 법률 자문 병행.
> 책임자(DPO): 대표 · admin@healwith.co.kr · +82-10-4772-1075

## 0. 침해란? (무엇이 트리거)
개인정보의 **유출·분실·도난·위조·변조·훼손·무단접근**. 예:
- DB·백업·암호화키 노출, 잘못된 접근권한으로 타인 PII 열람
- 계정 탈취(관리자·코디), 피싱으로 자격증명 유출
- 처리자(Supabase·Vercel·Google·Resend·LiveKit) 측 사고 통보 수신
- 환자정보가 의도치 않게 외부(메일 오발송·로그·AI)로 노출

의심만으로도 1단계 시작. "확실치 않음"은 미루는 이유가 아니다.

## 1. 즉시 (발견 0~1시간) — 차단·보존
- [ ] **확산 차단**: 영향 계정 비활성/비번 강제 회전, 노출 키(`ENCRYPTION_KEY_V1` 등) 즉시 교체·회전, 취약 엔드포인트 차단.
- [ ] **증거 보존**: 관련 로그(`admin_audit_logs`, Vercel/Supabase 로그) 스냅샷. 덮어쓰지 말 것.
- [ ] **DPO 보고**: 대표에게 즉시. 사고 기록 시작(아래 §5 양식).

## 2. 평가 (1~24시간) — 범위·위험
- [ ] 무슨 데이터가(식별·민감·결제), 몇 명, 어느 정보주체(국가)
- [ ] 암호화 여부 — **암호화된 채 노출**이면 위험 경감(키는 안전한지 확인)
- [ ] 원인(내부 실수 / 외부 공격 / 처리자 사고)
- [ ] 위해 가능성(신원도용·의료정보 노출 등). 민감정보(건강)는 항상 고위험.

## 3. 통지·신고 (시한 엄수)
| 대상 | 시한 | 근거 | 비고 |
|---|---|---|---|
| **정보주체(환자)** | 지체 없이 | PIPA §34, GDPR Art.34 | 고위험 시 필수. 무슨 일·어떤 정보·대응·연락처 |
| **개인정보보호위원회(PIPC)** | 72시간 내 | PIPA §34, 시행령 | 1천명↑ 등 요건 시 신고 + KISA |
| **EU 감독기관** | 72시간 내 | GDPR Art.33 | EU 거주 정보주체 관련 시 |
| **거주국 당국** | 현지법 | 카자흐 94-V / 러시아 152-ФЗ | 해당 환자국 요건 확인 |
| **파트너(의료기관·UMIT 등)** | 계약상 | MOU/DPA | 공동 데이터 관련 시 |
| **처리자** | 즉시 | DPA | 우리 측 원인 시 협조 요청 |

> 72시간은 **인지 시점**부터. 전모를 몰라도 **부분 통지 후 보완** 가능. 늦는 것보다 부분이라도 제때.
