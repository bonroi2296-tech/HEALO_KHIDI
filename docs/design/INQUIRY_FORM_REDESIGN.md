## 0. 왜 바꾸나 — 지금 구조가 병원 요구와 안 맞는다

지금 폼은 **우리가 상상한 순서**(1단계 가볍게 → 2단계 자세히)로 짜여 있다.
그런데 실제 병목은 폼이 아니라 **병원 의뢰**다. 대학병원 두 곳이 요구하는 것과 대조하면:

| 병원이 요구 | 지금 폼에 있나 |
|---|---|
| 생년월일 | ❌ 없음 |
| 성별 | ❌ 없음 |
| 여권번호 · 여권 사본 | ❌ 없음 |
| 진단명(정식 병명) | ❌ 암종 9종 분류만 있음 |
| 주 호소 | ❌ 없음 (200자 «한 줄 메모»뿐) |
| 발병 시기 | ❌ 없음 |
| 현재까지 받은 검사·치료 | ❌ 없음 |
| 과거력 · 가족력 | ❌ 없음 |
| 복용 중인 약물 | ❌ 없음 |
| 현지 주치의 소견 | ❌ 없음 |
| 의뢰 목적 | ❌ 없음 |
| 장시간 비행 가능 여부 | ❌ 없음 |
| 내원 희망일 | △ `preferred_date` 칸은 DB에 있으나 폼엔 없음 |

**결론: 지금 폼으로 받은 문의는 병원에 그대로 못 보낸다.** 코디가 환자와 메일·왓츠앱을
여러 번 왕복하며 손으로 다시 모아야 하고, 그 왕복이 의뢰 지연의 실제 원인이다.
(문의 #60 세브란스 건, 이대 TATEPBAYEVA 건 모두 이 왕복을 거쳤다.)

## 1. 근거 자료 — 무엇을 보고 설계했나

1. **세브란스 병원 환자 의뢰서(한글).docx** — 양식 칸
2. **이화의료원 환자 진료의뢰서 Patient Request Form (ENG).docx** — 양식 칸
3. **세브란스 국제팀 안내 메일** — 제출물·형식·언어·의뢰 불가 조건·자료 체크리스트
4. **이대 국제의료사업팀 레나타 메일(2026-08-11)** — 이대 양식 사용 + 한국어/영문 번역 요구

### 1-1. 세브란스 양식 칸
환자 성명(성/이름) · 국적 · 생년월일 · 성별 · 연락처(Mobile/E-mail, 선택) ·
과거력(고혈압·결핵·당뇨·간염·알레르기·수술 여부) · 현재 진단명 · 주 호소 ·
현재 주치의 소견 · 검사 결과(첨부) · 현재 복용 약물 · 의뢰 목적

### 1-2. 이대 양식 칸
환자명 · 연락처 · 생년월일 · 성별 · 국적 · **여권번호** · 진단명 · 주 증상 ·
발병 시기 · 진단 시기 · 현재 시행한 검사와 치료 내용 · 과거력 · 가족력 ·
복용중인 약물 · 현지 의사 소견 · 코로나 백신 접종 여부(백신명/차수) ·
영상 및 혈액/병리 검사 자료 여부(유/무)

### 1-3. 메일에만 있는 요구 (양식엔 없지만 없으면 진행 불가)
- **해외환자유치업체 등록증** (우리 서류 — 폼 아님)
- **환자 여권 사본**
- **내원 희망일**
- 환자 의무기록
- 메일 제목 규칙: `[에이전시명] 환자이름/생년월일/진단명`
- 메일 1건 = 환자 1명 (제목·본문·첨부 모두 동일 환자)
- 언어: **영어 또는 한국어**. 러시아어 의무기록은 세브란스가 확인 불가 →
  «가능하시면 영어, 어려우시면 한국어로 모두 번역 후» (세브란스), 이대도 동일 요구
- 영상: DICOM. 대용량은 구글 드라이브/드롭박스 링크
- 첨부 형식: JPG · PDF · MS WORD (EXE 자동 차단)
- **영상 파일의 환자 이름/생년월일/성별이 의뢰서와 다르면 병원 시스템 등록 불가**
- 회신: 보통 3일, 5일 넘게 없으면 미수신으로 간주(이대) / 24시간 내 1차 회신(세브란스)

### 1-4. 자료 체크리스트 (세브란스가 «포함됐는지 확인해달라»고 명시)
- 진단 시점의 내시경 검사 결과지 / 내시경 사진 / 조직검사 결과
- 수술기록지
- 수술 전·후 모든 영상 파일(DICOM) 및 **번역된 판독지**
- 항암 치료 기록 (날짜 · 기간 · 약명 · 용량 · 횟수)
- 방사선 치료 기록 (총 Gy 포함)
- 최근 6개월 이내 혈액검사 결과
- 장시간 비행 가능한 컨디션인지 **주치의 확인**

### 1-5. 의뢰 불가 조건 (세브란스 명시)
정신질환 · 운동질환(파킨슨 등) · 확진된 류마티스 질환 · 임상유전질환 ·
중증환자(인공호흡기 · 사지마비 · 의식저하 등) · 결핵환자

## 2. 화면 설계 — 「한 장, 접이식 6묶음」

### 2-1. 구조

```
┌──────────────────────────────────────────────┐
│  환자 의뢰서                    [진행 8/14]  │  ← 위에 남은 필수칸 개수만
├──────────────────────────────────────────────┤
│ ▼ ① 환자 신원          (필수 6)      ✓ 완료 │  ← 접이식. 채워지면 접힘
│ ▶ ② 진단·현재 상태     (필수 4)             │
│ ▶ ③ 병력·약물          (필수 2)             │
│ ▶ ④ 의뢰 목적·일정     (필수 2)             │
│ ▶ ⑤ 자료 첨부          (권장 3)             │  ← 여기가 이번 개편의 핵심
│ ▶ ⑥ 동의              (필수 4)             │
├──────────────────────────────────────────────┤
│  [ 의뢰서 보내기 ]      마지막 저장 14:32   │  ← 제출 버튼은 딱 하나
└──────────────────────────────────────────────┘
```

**제출 버튼은 한 개.** PO 지시대로 «1단계 제출 → 2단계 제출» 두 번 누르는 구조를 없앤다.
묶음(①~⑥)은 제출 단위가 아니라 **눈으로 구분하는 칸막이**일 뿐 — 접었다 폈다 자유,
순서 무관, 위아래로 오가도 아무것도 안 잃는다.

### 2-2. 긴 폼의 유일한 진짜 위험 = 「쓰다 날림」 → 자동 임시저장
칸이 30개 가까이 되면 창을 닫거나 전화가 오면 다 날아간다. 그래서:
- 입력할 때마다 브라우저에 자동 저장(localStorage), 돌아오면 그대로 복구
- 「이어서 쓰기」 링크를 이메일로 발송(선택) — 자료를 병원에서 떼 와야 하는 사람용
  > ✏️ 2026-08-19 실측: 접수 뒤 주소(/claim)는 «진행 상황 + 자료 더 올리기 + 글 덧붙이기»까지다.
  > 남은 14칸을 그 화면에서 이어 채우는 기능은 **아직 없다** — 문구도 그만큼만 약속하도록 고쳤다.
  > 붙일지는 PO 판단(코디가 서류로 채우는 흐름이 실제 운영이라 굳이 필요한지부터).
- **이건 단계 나누기가 아니다.** 제출은 여전히 한 번, 화면도 한 장이다.

### 2-3. 대리 접수 모드
로그인 계정이 스태프·에이전시면 폼 머리에 «환자 ○○ 님 대신 작성 중» 띠를 띄우고
자동채움을 끈다(이미 `/api/inquiries/prefill` 에 `skip` 로직이 있다).
실제로 지금까지 들어온 문의는 대부분 대리 접수였다 — 이 모드가 기본에 가깝다.

## 3. 칸 전체 목록과 필수도

필수도는 **3층**이다. 「병원이 없으면 진행 못 한다고 명시한 것」만 🔴 로 올린다.

| 층 | 뜻 | 동작 |
|---|---|---|
| 🔴 필수 | 없으면 병원이 접수 자체를 안 받음 | 비면 제출 버튼 안 눌림 |
| 🟠 강력권장 | 없으면 의뢰가 «진행»은 되나 반드시 되물어옴 | 비면 경고 + «나중에 보내겠습니다» 를 눌러야 통과 |
| ⚪ 선택 | 있으면 좋음 | 그냥 비워도 됨 |

| 칸 | 필수도 | 출처 | 저장 |
|---|---|---|---|
| 성 (여권 영문 표기) | 🔴 | 세·이 | `encrypted_name` |
| 이름 (여권 영문 표기) | 🔴 | 세·이 | `encrypted_name` |
| 생년월일 | 🔴 | 세·이 | **신규** |
| 성별 | 🔴 | 세·이 | **신규** |
| 국적 | 🔴 | 세·이 | `nationality` (기존) |
| 여권번호 | 🔴 | 이 | **신규 · 암호화** |
| 이메일 | 🔴 | 세·이 | `encrypted_email` (기존) |

### ⑤ 자료 첨부 — 이번 개편의 핵심

PO 지시: *"영상이나 검사 자료도 거의 반 필수적으로 받아야 의뢰가 진행되고."*
→ **🟠 강력권장**으로 둔다. 완전 필수로 막으면 «자료를 병원에서 아직 못 뗀 사람» 이 아예
못 보내고 사라진다. 대신 비워두면 경고가 뜨고 «나중에 보내겠습니다» 를 눌러야 통과한다.

| 칸 | 필수도 | 형식 |
|---|---|---|
| 여권 사본 | 🟠 | JPG · PDF |
| 검사 결과지 (진단서 · 조직검사 · 혈액검사) | 🟠 | PDF · JPG · Word (200MB) |
| 영상 자료 (DICOM) — **파일 올리기 또는 링크 붙여넣기** | 🟠 | ZIP · RAR · .dcm / 구글드라이브·드롭박스 링크 |
| 판독지 · 수술기록지 · 항암/방사선 치료 기록 | ⚪ | PDF · JPG · Word |

> ✏️ **2026-08-18 갱신 — 링크 칸은 «상시»가 아니라 «막혔을 때만».**
> 8/13 에 상시 링크 칸을 뺐다(자료가 우리 밖으로 나가고 링크는 죽는다). 그러다 8/18 PO 결정:
> *«고민하지 말고 그냥 200MB까지만 받는다고 하고, 그 이상은 왓츠앱으로 직접 보내시거나 구글 드라이브·드롭박스 맹글어서 보내주세요 하자»*
> → 규칙은 자료 상자 밑에 «미리» 한 줄로 말하고, 링크 칸은 **200MB 를 넘어 실제로 막힌 순간에만** 뜬다(BigFileLink).
> 서버는 http(s) 만 통과시킨다(javascript: 등은 링크만 버림, 접수는 막지 않음). 아래 원문은 8/11 당시 생각이다.

~~**링크 칸을 반드시 둔다.**~~ 영상 CD는 수백 MB~수 GB 라 업로드 상한(200MB)을 넘는 일이 잦고,
세브란스도 «GOOGLE LINK 또는 dropbox link 를 이용해서» 라고 명시했다.

그리고 그 아래에 **세브란스 자료 체크리스트**를 그대로 띄운다 (체크만 하는 목록, 필수 아님):

```
□ 진단 시점 내시경 결과지 / 사진 / 조직검사 결과
□ 수술기록지
□ 수술 전·후 영상(DICOM) + 판독지
□ 항암 치료 기록 (날짜 · 기간 · 약명 · 용량 · 횟수)
□ 방사선 치료 기록 (총 Gy)
□ 최근 6개월 이내 혈액검사 결과
```
안 낸 항목이 무엇인지 환자·코디 양쪽이 한눈에 보게 하는 용도다.

법(PIPA) 요구라 뺄 수 없다. 문구·배치만 정리한다.

## 4. 폼 뒤에서 자동으로 되는 것 — 여기가 진짜 이득

폼을 길게 만드는 대가로, 지금 사람이 손으로 하던 것 4가지를 기계가 한다.

### 4-1. 병원별 의뢰서 자동 출력
폼 1회 입력 → **세브란스 양식 .docx** / **이대 양식 .docx** 를 칸에 맞춰 자동으로 채워 내려받기.
지금은 코디가 두 양식에 같은 내용을 두 번 옮겨 적는다.
(`src/lib/documents/` 에 문서 처리 기반이 이미 있다.)

### 4-2. 메일 제목 자동 생성
세브란스 규칙 `[에이전시명] 환자이름/생년월일/진단명` 을 폼 값으로 자동 조립:
```
[본로이] TATEPBAYEVA AIGERIM / 1967-08-31 / 상행결장의 악성 신생물(C18.2)
```

### 4-3. 러시아어 → 한국어·영어 번역
환자는 러시아어로 쓰고, 병원은 한국어·영어만 받는다(세브란스가 «러시아어는 확인 불가» 명시).
자유 서술 칸(주 호소 · 주치의 소견 · 과거력 · 검사·치료 내용 · 의뢰 목적)을 저장할 때
**원문 그대로 + 한/영 번역본**을 같이 보관한다. (`src/lib/documents/translateDoc.ts` 재사용)

### 4-4. 영상 신원 대조
올라온 DICOM 의 `PatientName` · `PatientBirthDate` · `PatientSex` 를 폼 입력값과 자동 대조.
다르면 코디 화면에 경고 — «영상의 이름이 의뢰서와 다름. 이대로 보내면 병원 등록 거부».
세브란스 10·11번이 명시한 반려 사유를 보내기 «전에» 잡는다.
(`src/lib/imaging/prepareStudy.ts` 재사용)

## 5. 데이터 저장 설계

**원칙: 기존 칸은 이름 변경·삭제 없음. 추가만.**
`inquiries` 를 KHIDI 성과 집계(`/admin/khidi/conversion`)가 읽는다 — 기존 칸을 건드리면
평가 숫자가 움직인다.

| 무엇 | 어디에 |
|---|---|
| 여권번호 | `inquiries` 새 칸 · **AES-256-GCM 암호화** (`*_encrypted`) |
| 생년월일 · 성별 | `inquiries` 새 칸 (생년월일도 PII → 암호화) |
| 진단명 · 주 호소 · 주치의 소견 · 과거력 · 약물 · 가족력 · 검사치료내용 · 의뢰목적 | `cancer_patient_intakes` 새 칸 · 전부 암호화 (민감 건강정보) |
| 번역본 | 같은 행에 `*_ko` / `*_en` 짝 칸 |
| 자료 체크리스트 · 영상 링크 · 비행 가능 여부 | `inquiries.intake_data` (jsonb — 칸 추가 없이 늘어남) |
| 첨부 파일 | `inquiries.attachments` (기존 jsonb) |

⚠️ **주의 2가지 (과거에 당한 것)**
1. 새 칸을 조회 목록(`select`)에 넣으면 그 칸이 아직 없는 DB 에서 **조회 전체가 죽는다** →
   화면이 통째로 빈다. 새 칸은 따로 읽고 오류를 무시한다.
2. 마이그레이션은 **추가만**(컬럼·인덱스). `DROP`·`DELETE` 없음.

## 9. 자료 목록의 한계 — 이걸로 「진단」이 되나? (2026-08-11 PO 질문)

**정직한 답: 나는 모른다. 의료 판단이다.** 다만 확실히 말할 수 있는 두 가지가 있다.

### 9-1. 지금 목록의 출처는 「대장암 한 건」이다
1-4절 체크리스트는 상행결장암(C18.2) 케이스 회신에서 그대로 나왔다.
내시경·조직검사·수술기록·항암·방사선·혈액검사 — **소화기암 진료 흐름**에 맞춰진 목록이다.
암종이 바뀌면 결정적인 자료가 달라질 수 있다. 예를 들어(**전부 미검증 가설**):

| 암종 | 이 목록에 없지만 필요할 수 있는 것 |
|---|---|
| 유방암 | 유방촬영술·유방초음파, 호르몬수용체·HER2 검사 |
| 폐암 | PET-CT, 유전자 변이 검사 |
| 간암 | 다중시기 조영 CT/MRI, 간기능 등급, 종양표지자 |
| 혈액암 | 골수검사, 유세포분석 |
| 갑상선암 | 초음파, 세침흡인 세포검사 |

🛑 **이 표를 코드에 넣지 마라.** 근거가 내 일반 지식뿐이고 협력 병원에 확인받지 않았다.
환자 화면에 「이게 필요합니다」로 뜨는 순간 **우리가 의학적 요구사항을 만들어낸 것**이 된다.
→ 화면에는 공통 목록만 두고, **「대학병원마다 요구가 다르며 추가 요청이 올 수 있다」**고 안내한다(구현 완료).

### 9-2. 그런데 애초에 이메일 의뢰는 「진단」 단계가 아니다
대학병원 국제팀 안내에 그대로 적혀 있다 —
「이메일 의뢰의 목적은 **의뢰하신 케이스의 진료 및 평가 검사가 가능한지**와 예상 치료에 대한 내용입니다.
치료에 대한 자세한 절차는 **실제 내원하여 진료 및 평가 검사 후 구체화** 됩니다.」

**즉 병원이 이 단계에서 하는 건 「받을 수 있나」 판정이지 진단이 아니다.**
그래서 처음부터 전부 받을 필요가 없다. 자료 묶음을 두 칸으로 나눈 근거가 이것이다.

| 언제 | 무엇 | 근거 |
|---|---|---|
| **지금 (의뢰 회신용)** | 진단서 · 검사 결과지 · 영상 | 「가능한지」 판정의 근거 |
| **내원 확정 후** | 여권번호 · 여권 사본 | 「여권 사본은 보내주시지 않더라도 의뢰 진행 가능. 다만 내원 확정시에는 꼭」 (원문) |
| **병원이 요청하면** | 케이스별 추가 자료 | 병원마다 다름 — 우리가 정리해 따로 요청 |

### 9-3. PO 손이 필요한 것
협력 병원(세브란스·이대)에 **「암종별로 추가로 필요한 자료가 있는지」**를 한 번 물어봐야
9-1 표가 사실이 되고 화면에 넣을 수 있다. 그 전에는 안 넣는다.

## 8. 만들 순서

1. **칸 정의 파일 하나** (`src/lib/inquiry/referralSchema.ts`) — 칸 이름·필수도·6개국어 라벨·검증 규칙을 한 곳에.
   화면·서버·의뢰서 출력이 전부 이 파일 하나를 본다.

3. **새 폼 화면** — 접이식 6묶음 + 자동 임시저장
4. **제출 주소 하나로 합침** + 서버 검증
5. **의뢰서 자동 출력**(세브란스·이대 .docx) + 메일 제목 생성
6. **번역·영상 신원 대조** 붙이기
7. 자동 동작시험 다시 쓰기 → 로컬 화면 확인 → 합치기 신청
