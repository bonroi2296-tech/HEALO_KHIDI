# 병렬 세션 플레이북 — 여러 작업 동시에, 안 엉키게

> PO가 "야 넌 이거, 너는 저거" 하고 여러 창에 동시에 시킬 때 안 꼬이게 하는 표준.
> 강제 규칙(세션이 자동으로 따름)은 **이 문서 하단** 「세션이 자동으로 따르는 강제 규칙」에 있음(2026-07-28 `CLAUDE.md` 에서 이관). 이 문서는 PO용 사용법.

## 왜 엉켰나 (원인)
여러 세션을 **같은 폴더**에서 돌려서. 한 폴더는 한 번에 브랜치 하나만 가능 → 두 세션이 서로 브랜치를 바꿔치기 + 2분 자동저장 훅이 섞인 걸 커밋 → 난리.

## 해결 = 세션마다 딴 폴더 (worktree)
같은 프로젝트인데 **폴더+브랜치를 따로** 떠서 작업. 폴더가 다르면 동시에 굴려도 절대 안 엉킴. 이게 프로가 한 컴퓨터에서 병렬 작업하는 표준.

## PO가 할 일 (이것뿐)
**영역 배분 한 줄** — "너=환자·코디, 너=에이전시." 영역만 안 겹치게. 나머지(격리·차선유지·정리)는 세션이 알아서.

### 작업 하나 시작하는 법 (2단계)
```bash
# 1) 격리 폴더 만들기 (한 줄)
bash scripts/new-session.sh agency
#    → C:/Users/user/Desktop/HEALO_worktrees/agency 폴더 + work/agency 브랜치 (origin/main 최신 기준)

# 2) 그 폴더에서 새 Claude 세션 열고:
#    "너 에이전시 백오피스 담당. 시작해."
```
끝. 세션이 알아서 격리 확인·영역 선언·중복 체크·끝나면 PR.

## 안 꼬이는 규칙 3개
1. **한 폴더 = 세션 하나.** 같은 폴더에 두 세션 절대 금지.
2. **영역 안 겹치게.** 같은 파일 만지는 일이면 동시 말고 **순서대로**.
3. **합칠 땐 하나씩** (PR→자동검사→머지). 하나 머지되면 나머지 세션은 최신 받아오기(pull).

## 영역 나누는 예시 (파일이 거의 안 겹침)
| 영역 | 주로 만지는 곳 | 폴더 이름 예 |
|---|---|---|
| 환자·코디 | `app/coordinator`, `app/patient`, `app/api/khidi/consultation` | `patient-coord` |
| 에이전시 백오피스 | `app/agency`, `app/api/agency`, `app/clinic` | `agency` |
| 알림·메일 | `src/lib/notifications`, `src/lib/email` | `notify` |
| 병원·치료 콘텐츠 | `app/hospitals`, `app/treatments`, `app/admin/hospitals` | `catalog` |

> ⚠️ 공용 파일(`CLAUDE.md`, `src/lib/i18n`, 전역 설정)은 여러 영역이 다 건드려서 충돌 잘 남 → 이런 건 한 번에 한 세션만, 또는 따로 처리.

## 끝나면 정리
```bash
git worktree remove "C:/Users/user/Desktop/HEALO_worktrees/agency"   # 머지 끝난 폴더 치우기
```

## 한계 (솔직히)
세션들끼리 **서로 실시간으로 못 본다.** 그래서 "누가 어느 영역" 배분은 PO 몫(10초). 만약 두 세션이 실수로 같은 파일을 고치면 → 합칠 때 **충돌(conflict)**로 잡히고, 그때 어느 쪽이 맞는지 고르면 됨(데이터 안 날아감). 폴더 격리 + 영역 배분이면 충돌은 거의 안 남.

## 🔴 실제로 난 사고: 「내 커밋이 남의 브랜치로 들어갔다」 (2026-07-27 저녁)

> 회수 경위: 이 기록은 `claude/app-registration-4sj2l7` 브랜치에만 있고 PR 이 없어 본판에 못 들어와 있었다. 브랜치 정리 중 발견해 옮긴다([#1058](https://github.com/bonroi2296-tech/HEALO_KHIDI/pull/1058) 과 같은 부류).

**무슨 일**: 그 세션이 **공용 메인 폴더(`HEALO_KHIDI`)에서 돌고 있었는데**, 다른 병렬 세션이 같은 폴더에서 브랜치를 바꿔버렸다. 그 결과 **내 커밋이 남의 브랜치 위에 얹혔다.** (같은 날 다른 세션에서도 «2분마다 도는 자동저장 훅이 남의 미커밋 변경까지 같이 커밋해 브랜치가 오염된» 사례가 따로 있었다 — **한 폴더 두 세션은 이런 식으로 깨진다.**)

**징후 (이걸로 알아챈다)**: 방금 고친 문서를 다시 열었는데 **내 편집이 없고 낡은 내용**이면, 파일이 안 고쳐진 게 아니라 **브랜치가 바뀐 것**이다. 「저장이 안 됐나?」로 오해하고 다시 편집하면 상황이 더 꼬인다.

**복구법**:
- 🚫 **남의 브랜치를 `rebase`·`reset` 하지 마라.** 그 세션이 동시에 작업 중이고 미커밋 변경까지 들고 있을 수 있다.
- ✅ `git worktree add <임시경로> <내브랜치>` 로 **내 브랜치를 딴 폴더에 펴고**, 거기서 내 커밋만 골라 옮긴다.

**예방**:
- 커밋 전에 `git rev-parse --abbrev-ref HEAD` 한 번 — 내 브랜치가 맞는지.
- 근본 해결은 `bash scripts/new-session.sh <영역>` 으로 **처음부터 자기 worktree 에서 시작**하는 것(이 문서 하단 강제 규칙 1번 「격리 먼저」).
- ⚠️ 상대경로로 파일을 쓰면 .NET/도구가 **다른 디렉터리로 해석**할 수 있다 — 워크트리를 섞어 쓸 땐 **절대경로만.**

# 세션이 자동으로 따르는 강제 규칙 (2026-07-28 `CLAUDE.md` 에서 이관 — 내용 변경 없음)

> 원래 `CLAUDE.md` 「⚠️ 병렬 세션 규칙」에 있던 전문 — 지금은 여기(`docs/PARALLEL_SESSIONS.md`)가 단일 SoR. `CLAUDE.md` 에는 트리거 한 줄만 남았다.

## ⚠️ 병렬 세션 규칙 — 여러 작업 동시 진행 시 안 엉키게 (필수)

> PO가 여러 영역을 동시에(다른 창에서) 시킬 때 세션끼리 안 꼬이게 하는 표준.
> 세션끼리는 서로 실시간으로 못 본다 → **영역 배분만 PO 몫**, 나머지(격리·충돌방지·정리)는 세션이 아래를 **자동으로** 따른다(PO가 말 안 해도).

1. **격리 먼저** — 의미 있는 작업이면 **공용 메인 폴더(`HEALO_KHIDI`)에서 작업 금지.** 자기 전용 worktree 폴더인지 확인하고(아니면 `bash scripts/new-session.sh <영역>` 안내 + "그 폴더에서 다시 열어달라"), 이미 worktree면 그대로 진행. 한 폴더에 두 세션 금지.
2. **영역 선언 + 중복 확인** — 시작 시 "이 세션 = [영역] 담당, 만질 파일/폴더 = X"를 한 줄로 밝힌다. 세션시작 훅 "열린 작업 목록"에 같은 영역/파일을 이미 하는 브랜치가 있으면 → 새로 시작 말고 PO에게 알림(겹치면 동시 금지 = 순서대로).
3. **차선 유지** — 자기 영역 밖 파일 X. 공용 파일(`CLAUDE.md`·i18n·전역 설정 등) 수정이 꼭 필요하면 PO에게 먼저 알림(충돌 위험 큰 지점).
4. **PR로 합침** — 끝나면 자기 브랜치 → PR. 남의 브랜치에 직접 머지 금지. 머지 후 다른 세션은 최신 pull/rebase.

**PO 워크플로(영역 배분만):** ① `bash scripts/new-session.sh <영역>` ② 출력된 폴더에서 새 세션 열고 "[영역] 담당, 시작" ③ 끝.

## 어시가 먼저 「일을 쪼개서 다른 세션에 떼주는」 것까지 제안하라

> 2026-07-28 취향 원장에서 이관. 원문 경위는 `docs/PO_PREFERENCES.md` 「보관」.

어시가 목록을 혼자 다 처리하려 하자 PO 가 **"니 혼자 다 할라 하지 말고 작업별로 워크트리 파고 다른 세션한테 일부 떼주면 좋잖아 좀 생각을 해라"**. 병렬 세션 규칙은 있지만 **PO 가 시키기 전에 어시가 먼저 배분안을 내라**는 게 이번 요구.

→ 할 일이 **3갈래 이상**이면 `bash scripts/new-session.sh <영역>` 으로 폴더를 파고 **각 세션에 붙여넣을 첫 지시문까지 만들어** 제시한다(실제로 그렇게 하자 PO가 그대로 진행했다).
