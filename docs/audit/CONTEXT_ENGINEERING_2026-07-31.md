## 1. 요약본이 빠뜨린 것 — 원문에만 있고, 그게 우리 급소다

요즘IT 요약은 정확하지만 4가지를 뺐다. 그중 2개가 우리한테 제일 아프다.

| # | 원문에만 있는 문장 | 왜 우리한테 중요한가 |
|---|---|---|
| ① | *"Keep your CLAUDE.md lightweight… and **spend most of the tokens on gotchas inside of the codebase**. Avoid stating 'the obvious' things Claude should know by looking at your file system or your repo."* | **우리 CLAUDE.md는 코드 함정이 11.5%뿐**이다(아래 실측). 나머지는 일하는 방식·말투. 원문 조언과 정반대 배분. |
| ② | *"Avoid making them overconstrained, **except in highly important areas**."* | **「덜어내라」에 예외가 명시돼 있다.** 우리 보안·돈·데이터 파괴 규칙은 그 예외에 해당 → 안 줄여도 된다. 요약본만 읽으면 이 안전판을 모른다. |
| ③ | *"a HTML mockup of a design will generally produce better results than a description of the design **or a screenshot**."* | 요약본은 「글보다 HTML」까지만 말했다. 원문은 **화면 사진(스크린샷)보다도 HTML이 낫다**고 한다. 우리는 `DESIGN.md`(글) + 화면 사진 — **원문이 지목한 열등한 두 방식을 둘 다** 쓰고 있다. |
| ④ | *"Rubrics allow Claude to verify your taste… by spinning up verifier agents with those rubrics."* | 우리 `completeness-audit` 스킬이 이미 `rubric.js`로 하고 있는 그것. **잘하고 있다는 확인.** |

## 4. 진짜 배울 점 5가지 — 그대로 따르면 안 되는 것 포함

### ① 「중복을 지워라」가 아니라 「한 곳을 정해라」다
원칙 ④를 곧이곧대로 적용해 매 턴 훅을 지우면, **우리가 훅을 만든 이유(2026-07-28: 세션 시작 1회로는 희석돼서 안 지켜짐)로 되돌아간다.**
훅 주석에 그 실패가 기록돼 있다. → **훅을 「한 곳」으로 인정하고, `CLAUDE.md`에서 7개 개념을 빼는 방향**이 맞다.
매 턴 비용은 그대로, `CLAUDE.md`에 여유(추정 1,500~2,000자)가 생긴다.
※ 실제 감소폭은 지워봐야 안다 — 추정치다.

### ② `CLAUDE.md`는 「일하는 방식」이 아니라 「이 코드에서 발 헛디디는 곳」을 적는 곳
원문의 조언대로면 지금 62.4%를 차지한 절차·말투는 대부분 `docs/rules/`나 훅으로 내려갈 수 있다.
**단, 무비판 적용 금지** — 앤트로픽 조언은 「코딩 에이전트가 코드를 잘 짜게」 관점이다.
PO 소통 방식은 코드 함정으로 옮길 수 없고, 옮기면 안 된다. 옮길 수 있는 건 **절차**(4,500자)지 말투가 아니다.

### ③ 「덜어내라」에는 원문이 예외를 박아뒀다 — 우리 보안 규칙은 그 예외다
*"except in highly important areas"*.
돈·데이터 파괴·개인정보·암호화 규칙은 **줄이는 대상이 아니다.**
요약본만 읽고 「다 덜어내자」로 가면 안전판을 뽑는 셈이 된다.

### ④ 화면 이야기는 글·사진이 아니라 **HTML 시안 파일**로 넘겨야 한다
원문이 명시적으로 「스크린샷보다 HTML이 낫다」고 한다.
우리는 이미 `docs/백오피스_계층재설계_시각화.html`, `docs/자체개발_가치환산_원페이저.html` 처럼 HTML을 쓰고 있다 — **방법은 있는데 디자인 지침에는 안 쓰고 있다.**
`DESIGN.md`의 「금지/권장」을 말로 적는 대신, **기본 톤이 적용된 실제 화면 파일을 참조로 지정**하는 게 원문 권고에 맞다.

### ⑤ (칼럼 2번꼭지) **에이전트에게 「하지 마라」고 적는 것과 「못 하게 막는 것」은 다르다**
허깅페이스 사건: 취약점 자체는 평범했고, 달라진 건 **규모와 속도**(4.5일, 17,600건 시도).
가장 공감받은 댓글 — *"에이전트가 실제로 어떤 행동까지 할 수 있는지는 덜 묻는다."*

우리 실측: **`.claude/settings.json`에 `permissions` 블록 자체가 없다**(hooks만 있음).
즉 「DB 삭제·컬럼 drop은 PO 확인」은 **문서에 적힌 약속일 뿐, 기계가 막는 문턱이 아니다.**
Supabase 연결로 `execute_sql`·`apply_migration`이 열려 있고, `auto-commit-push.sh`는 자동으로 밀어 올린다.
→ `CLAUDE.md` 「새 규칙은 기계가 잴 수 있으면 CI로 박아라」를 **우리 자신의 권한에도** 적용할 차례.

### 5-1. 문지기 훅 추가 — 「적힌 약속」을 「기계 문턱」으로

`.claude/hooks/guard-destructive.mjs` 신규 + `.claude/settings.json`에 `PreToolUse` 등록.
도구가 실제로 돌기 **직전에** 입력값을 읽고, 파괴적이면 **막는 게 아니라 확인창을 띄운다**(`permissionDecision: "ask"`).
정당한 작업은 승인 한 번이면 그대로 진행된다.

| 붙잡는 것 | 통과시키는 것 |
|---|---|
| `DROP TABLE/COLUMN/SCHEMA/…`, `ALTER … DROP` | `CREATE TABLE`·`ADD COLUMN`·`CREATE INDEX` (가역적 추가) |
| `TRUNCATE`, `DELETE FROM` | `SELECT`, `UPDATE`(소프트 삭제 포함) |
| 접근권한 규칙(RLS) 끄기, `REVOKE` | 문자열·주석 안에 들어간 `drop` 같은 단어 |
| Supabase 프로젝트 정지·복원, 작업본 삭제·초기화·반영 | — |
| `git push --force`, `rm -rf`, `git reset --hard`, `git clean -f`, `supabase db reset` | 보통 푸시, `--force-with-lease`, 빌드, **임시 폴더 안에서의 `rm -rf`** |

**시험 결과: 20개 중 20개 기대대로**(막아야 할 9개 전부 확인창, 통과해야 할 11개 전부 무개입).
훅이 깨지면 정상 작업을 막지 않고 **그냥 통과**하도록 만들었다(입력을 못 읽으면 조용히 exit 0).

  (중복 제거로 −1,091자, 대신 문지기 훅을 가리키는 안내 2줄을 더해 +175자.)

### 5-3. `DESIGN.md` → 실물 시안 참조 + **감사 중 나온 진짜 결함 1건**

`docs/design/기본톤_시안.html` 신설. 색·모서리·그림자·부품·숫자·상태 화면(빈/로딩/오류)·움직임을
**실제로 그려서** 보여준다. 각 견본에 쓸 Tailwind 클래스가 같이 적혀 있다. 브라우저로 열면 끝(서버 불필요).
`DESIGN.md` 는 「금지·의료·다국어 규칙」을 맡고, 시안은 「눈으로 봐야 아는 것」을 맡는다.

**🔴 그런데 시안을 만들다 `DESIGN.md` 자체의 결함이 나왔다 — 이게 이 작업의 진짜 소득이다.**

| | |
|---|---|
| 문서가 말하던 것 | `colors.primary: "teal-600"` |
| 실제 코드 | 배경 `bg-teal-700` **306회** vs `bg-teal-600` **24회** (12.75배)<br>글씨 `text-teal-700` **625회** vs `text-teal-600` **54회** (11.6배) |

**고침 3단**
1. `DESIGN.md` `primary` → `teal-700`(5.47:1), `primary_hover` → `teal-800`(7.58:1), `forbidden_primary: teal-600` 추가. 체크리스트 1번·변경 이력도 갱신.
2. **기계에 박음** — `check:content` 에 `[주색미달]` 가드 신설(`scripts/check-content-consistency.mjs`).
   `bg-teal-600`·`text-teal-600` 만 잡고 `border-teal-600` 은 통과시킨다(테두리 기준 3:1 을 3.74 로 넘김).
