**목적:** 사업 진행 중 발생한 요구사항·기능·범위 변경 이력 추적
**대상:** 사업계획서 대비 변경 사항 / 사용자 요구사항 변경 / 기술 스택 변경
**갱신:** 변경 발생 즉시
**감리·점검 시:** 본 대장 + 관련 커밋·PR 번호 매칭으로 사실 증빙
**최종 갱신:** 2026-09-06 (2026-08~09월분 **16건 등재** — 누적 54건. 직전 갱신 2026-07-25)

> **근거 유형 표기 규칙(2026-07-25 신설).** 각 변경의 「근거」에 확인 수단을 명시한다.
> `PR #NNN` = 저장소 형상 이력에서 직접 확인 / `문서` = 살아있는 설계·표준 문서의 변경 이력에서 확인.
> 2026-05~06월분은 저장소 이력이 압축(squash)되어 커밋 해시 대조가 불가하므로 문서 근거를 사용한다.
> **추정으로 채운 항목은 없으며, 확인되지 않은 사항은 등재하지 않는다.**
>
> **연계 산출물:** 본 대장의 변경들이 공고 6대 ICT 서비스 요구사항의 어느 항목을 충족하는지는

### CR-S-06. 해외 의뢰처 계층 분리 (해외 에이전시 ↔ 해외 의료기관)

- **사유:** 공고 6대 ICT 중 **사후관리 3종(④경과 f/u ⑤모니터링·상담·교육 ⑥재이용 예약상담)이 전부 임상행위**임을 확인. 검사·영상정보 취급과 건강상태 모니터링은 비의료 에이전시가 수행할 수 없으므로, 하나의 포털로 묶어 둔 기존 구조는 요구사항과 배치됨
- **구현:** 포털을 `/agency`(해외 에이전시 — 사전상담까지)와 `/clinic`(해외 의료기관 — 사후 경과 업로드까지)으로 분리. DB 테이블은 유지하고 `agencies.partner_type` 게이팅으로 화면만 분리(데이터 3건 규모에서 테이블 분리는 과잉으로 판단). URL↔유형 불일치 시 자동 이동
