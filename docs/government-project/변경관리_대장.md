# HEALO 변경관리 대장

**목적:** 사업 진행 중 발생한 요구사항·기능·범위 변경 이력 추적
**대상:** 사업계획서 대비 변경 사항 / 사용자 요구사항 변경 / 기술 스택 변경
**갱신:** 변경 발생 즉시
**감리·점검 시:** 본 대장 + 관련 커밋 해시 매칭으로 사실 증빙

---

## 1. 변경 분류

| 코드 | 분류 | 설명 | 승인 주체 |
|---|---|---|---|
| CR-S | 범위(Scope) | 기능 추가·삭제·축소 | PM |
| CR-T | 기술(Tech) | 라이브러리·인프라·모델 교체 | 개발 리드 |
| CR-D | 설계(Design) | UI/UX, 디자인 시스템 변경 | PM |
| CR-O | 운영(Operations) | 배포·백업·모니터링 정책 변경 | DevOps |
| CR-L | 법·정책(Legal) | 약관·개인정보처리방침 변경 | 법무 검토 |

**ID 규칙:** `CR-{분류}-{NN}` (예: `CR-S-01`)

## 2. 변경 이력

- **사유:** Gemini 2.5 Flash 무료 티어 2026-04-01 종료, 3 Flash 무료 표준 모델로 지정됨

- **검증:** 빌드 통과, 챗봇·번역 응답 품질 확인
- **커밋:** `8009e5f`
- **사후 영향:** 응답 품질 동등 또는 개선, 비용 변동 없음

### CR-T-02. 디자인 모드 시스템 도입 (LEGACY/PREMIUM 토글)

## 4. 변경 시 절차

1. **변경 요청 접수** (PM 또는 개발팀 식별)
2. **영향 분석** (코드 범위, 일정, 비용, 리스크)

4. **구현 + 커밋** (커밋 메시지에 CR ID 명시 권장)
5. **본 대장 갱신** (CR-NN 신규 행 추가)
6. **검증** (빌드·테스트·사용자 피드백)
7. **사후 평가** (영향·교훈 기록)
