# 배포 후 5분 점검

배포 직후 아래 순서로 확인하면 **인증·RAG·병원 API·시술 스키마**가 정상인지 빠르게 점검할 수 있습니다.

---

## 1. 확인할 URL (순서대로)

| 순서 | URL / 방법 | 목적 |
|------|------------|------|
| 1 | `GET /api/admin/whoami` | 어드민 인증(쿠키/Bearer) 정상 여부 |
| 2 | `GET /api/admin/observability/rag/health?window=24h` | RAG health·zero_rate·rpc_failed |
| 3 | `GET /api/admin/hospitals` | 병원 목록 API (관리자 인증 필요) |
| 4 | `GET /api/admin/hospitals/offers-schema` | 시술 실패 로그용 DB 컬럼 존재 여부 (선택) |

- **1·2·3·4**: 브라우저에서 어드민 로그인 후 접속하거나, 동일 도메인에서 쿠키 포함 요청.
- **RAG 검색만 공개**: `POST /api/rag/search` body `{"query":"테스트","lang":"ko"}` → 200, `ok: true` 확인.

---

## 2. 정상 기준

- **whoami**: 200, `isAdmin: true` (또는 개발 시 debug 정보).
- **health**: `ok: true`, `total_requests` 등 존재. `zero_rate`·`rpc_fail_rate` 확인.
- **hospitals**: 200, `ok: true`, `hospitals` 배열 (길이 0이어도 정상).
- **offers-schema**: 200, `ok: true`, `offersFailureLogEnabled: true` 이면 시술 실패 로그 DB 저장 가능. `false`면 마이그레이션 미적용(기능은 동작).

## 3. 이상 시 조치

| 현상 | 조치 |
|------|------|
| **홈/카드 안 나옴, 콘솔에 `supabaseClient` / `reading 'key'` 에러** | Vercel에 **클라이언트용** Supabase env 설정 필수. 아래 "5. Vercel 환경 변수" 참고. |
| **"Could not find the table 'public.hospital_offer_jobs'"** | Supabase SQL Editor에서 `migrations/20260226_hospital_offer_jobs.sql` 내용 실행. |
| **whoami 403** | Vercel `ADMIN_EMAIL_ALLOWLIST`, Supabase URL·anon key, 쿠키 전달 확인. |
| **health 403/500** | whoami 먼저 확인. RAG 관련 env·Supabase RPC 확인. |
| **hospitals 403/500** | whoami·Supabase env 확인. |
| **offers-schema 200 but offersFailureLogEnabled: false** | 선택. 시술 실패 로그 저장을 쓰려면 `migrations/20260226_offers_auto_fail_log.sql` 실행. |

## 5. Vercel 환경 변수 (필수)

로컬에서는 카드가 나오는데 **배포 URL에서만** 카드가 안 나오고 콘솔에 `Cannot read properties of undefined (reading 'key')` / `supabaseClient` 에러가 나면, **Vercel에 Supabase 환경 변수가 없거나 비어 있는 상태**입니다.

1. [Vercel Dashboard](https://vercel.com) → 해당 프로젝트(**healo-demo** 등) 선택  
2. **Settings** → **Environment Variables**  
3. 아래 변수를 **Production**(및 필요 시 Preview)에 추가  
   - `NEXT_PUBLIC_SUPABASE_URL` = Supabase 프로젝트 URL (예: `https://xxxx.supabase.co`)  
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY` = Supabase **anon public** key  
4. 저장 후 **Deployments** → 최신 배포에서 **Redeploy** (환경 변수 반영을 위해 재배포 필요)

로컬 `.env` / `.env.local`에 있는 값과 **동일한 Supabase 프로젝트**의 URL·anon key를 넣으면 됩니다.
