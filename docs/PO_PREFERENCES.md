# PO 취향·선호 누적 원장 (PO Preference Ledger)

> **이건 뭔가:** CLAUDE.md의 *고정 규칙*(말투·보안·빌드)과 **별개로**, 세션 중에 PO 지시·반응에서 **그때그때 묻어나온 취향·선호·성향**을 누적 기록하는 곳. 코드만 봐선 안 보이고, 고정 규칙으로 박기엔 아직 유동적인 것들.
>
> **누가 채우나:** `/handoff` 스킬이 세션 종료 시 **이번 대화를 분석**해, 새로 드러난 PO 취향을 아래 「활성 취향」에 1건씩 추가/갱신(중복 금지·날짜 절대표기). 세션 시작 시 `session-orient.sh` 훅이 「활성 취향」을 **자동으로 컨텍스트에 띄움** → 다음 세션이 안 읽어도 PO 성향을 안 어김.
>
> **고정 규칙으로 승격:** 어떤 취향이 3회 이상 반복·확정되면 CLAUDE.md(또는 훅)의 고정 규칙으로 올리고 여기선 "→ CLAUDE.md 승격"으로 표시.
>
> **군살 방지:** 「활성 취향」은 항상 짧게(훅이 매번 띄우므로). 더 이상 유효하지 않거나 고정 규칙으로 승격된 항목은 「보관(히스토리)」로 내린다.

- **(2026-06-18) "일단 됐다" = 그 트랙 종료**: PO가 "일단 됐다/됐어"라고 하면 그 주제는 더 파지 말 것(예: Remote Control 싱크).
- **(2026-06-18) 결과물·시각 우선**: 긴 설명보다 URL·배포·스크린샷·동작 확인을 원함.
- **(2026-06-18) ⭐ 질문 찔끔찔끔 금지(백문백답 싫어함)**: 결정지점·선택지가 있으면 **한 번에 다 펼치고 추천까지** 제시하라. 한 턴에 질문 하나씩 떨궈 PO가 끌어내게 만들지 마라("이런 옵션 있는 걸 왜 내가 끝없이 물어야 아냐"). 기본은 **추천안으로 바로 실행**하고, 정말 PO만 정할 수 있는 것만 묻되 그것도 한 방에 모아서.
- **(2026-06-19) 참고 ≠ 베끼기**: 경쟁 서비스(줌·구글미트 등)를 참고하라는 지시는 "UI를 베껴와"가 아니라 **"그걸 기준 삼아 우리 서비스의 퀄리티를 높여라"**의 뜻. 레이아웃 모방 말고 우리 맥락(의료·외국인 암환자)에서 진짜 부족한 품질 포인트를 도출할 것.
- **(2026-06-19) 큰 개선은 "싹 다" + 테스트 산출물까지**: 도출한 개선 항목을 부분만 하지 말고 **전부 구현·배포**하고, PO가 **나중에 비동기로** 직접 눌러볼 **테스트 링크/데이터까지 만들어** 둘 것(PO가 즉시 테스트 못 하는 경우 많음 — "지금 바로 테스트는 못해").
- **(2026-06-19) ⭐ 핸드오프는 강제 말고 PO 트리거 + 과부하 시 어시스턴트가 먼저 물어보기**: 종료 문지기 강제차단 OFF(`handoff-gate.sh` ENFORCE=0). 핸드오프는 (a) PO가 "핸드오프/오늘 끝" 할 때, 또는 (b) **어시스턴트가 세션 과부하를 감지하면 "이번 세션 무거워졌는데 핸드오프하고 새 세션 갈까요?"라고 먼저 제안 → PO 동의 시**. 커밋 개수로 자동 강제 금지. **과부하 판단 — 주 기준=②(PO 선택 2026-06-19)**: ②**맥락 포화**가 핵심 트리거 — 대화가 길어져 시스템이 내용을 요약(summarization)하기 시작하거나, 내가 이미 한 걸 까먹고 다시 읽는 조짐이 보이면(=효율 저하 신호) 제안한다. 단 끊는 *순간*은 가능하면 ①자연스러운 끊김점(작업 완결·배포·검증 직후, 중간엔 안 끊음)에 맞춤. ③큰 작업 2~3개 연달아·④주제 전환은 보조 신호. (정확한 토큰·시간 수치는 못 봄 → 이 정황들로 판단.)
- **(2026-06-19) ⭐ 명백한 "기본기"는 지적 전에 알아서 챙겨라**: PO가 하나하나 짚어야 하는 걸 가장 싫어함("내가 하나하나 다 지적하면서 설명해줘야 해?"). 특히 **기성 화상툴(줌·미트)의 표준 동작은 기본값으로 간주** — 발화자 자동 메인(스피커뷰)·화면공유 자동 크게·**언어 선택 시 전체 UI가 그 언어로 전환**·적정 화질 등. 기능을 만들 때 "사용자가 당연히 기대할 표준 동작"을 먼저 점검하고 넣어라(반쪽 구현 후 PO가 빠진 걸 찾게 하지 말 것).
- **(2026-06-19) 품질·상태는 점수표(축별 N/100)로 보여주면 잘 통함 + before→after 기대**: 큰 평가/감리는 축별 점수로 정량화해 제시하면 PO가 바로 이해함. 단 **"진단 점수=수리 전 사진"임을 명확히** 하고(수리해도 자동 재측정 아님), 수리 후엔 **올라간 점수(추정)를 before→after로** 보여줄 것. PO는 점수가 실제로 움직이길 기대함("수리했는데 왜 점수 그대로?").
- **(2026-06-19) ⭐ 시키기 전에 "이런 거 요렇게 할까요?"라고 먼저 제안하라**: PO가 일일이 지시해야 하는 걸 싫어함("내가 얘기 안 해도 알아서 제안을 해야지"). 다음 단계·개선·자동화·빠진 산출물이 보이면 PO가 요청하기 전에 **선제적으로 제안**할 것. (예: 핸드오프 시 다음 세션 첫 프롬프트까지 자동 정리 → 이건 핸드오프 7번 섹션으로 영구 반영함.)
- **(2026-06-19) 저위험 PR은 CI 초록이면 어시스턴트가 머지·배포까지**: PO가 #85·#86·#87 모두 "CI 초록되면 바로 머지" 승인 → 명백히 저위험(타입·테스트·smoke 통과)인 PR은 PO가 일일이 머지버튼 안 눌러도 어시스턴트가 머지·배포 진행. 단 보안민감·대규모·되돌리기 어려운 변경은 여전히 PO 확인 후. 새 브랜치가 필요하면 그때 권한만 한 번 받기.
