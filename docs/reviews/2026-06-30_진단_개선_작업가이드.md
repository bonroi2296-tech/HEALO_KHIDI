## 3. 앞으로 작업 방향성 (방법론 — 매 세션 지켜라)

이번 세션에서 확인·체득한 작업 원칙. 보고서 기반 개선이든 신규 작업이든 공통.

**가. 검증 (이번에 사고로 배움)**
- **`tsc --noEmit`로 타입검증 필수.** `next build --webpack`은 타입에러를 **놓친 적 있다**(#509가 그렇게 머지돼 main 빌드를 깸). "빌드 통과 ≠ 타입 안전 ≠ 동작."
- **실DB로 확인**(Supabase MCP). 인상 말고 데이터.
- **발견은 "검증 먼저, 조치 나중".** 보고서 HIGH 1개가 허위경보였다(미들웨어). 함부로 고치면 중복·오류.
- 못 한 검증은 **"못 했다"고 정직히**. "됐어요" 금지.

**나. PR·배포 운영 (이번에 한도 태움)**
- **PR을 잘게 남발하지 말 것 — 모아서.** Vercel 무료 플랜은 **일일 빌드 한도**가 있어, 하루 PR 8개+ 돌리면 한도 초과(24h 배포 정지)된다. 관련 변경은 **한 PR로 묶어라.** (메모리 `feedback_local_first_testing` 재확인.)
- **도메인별 worktree 격리**(`scripts/new-session.sh <영역>`) — 공용 main 폴더에서 작업 금지. node_modules는 정션으로 연결, 정리 시 `rmdir`로 링크만 제거(원본 보호).
- **자동머지 범위**: 저위험 백엔드(타입·테스트·보안위생·검사스크립트)는 CI 초록 시 자동머지 OK. **단 ⓐ공개 UI/플로우 ⓑ평가 제출문서 ⓒ돈 ⓓ되돌리기 어려움(데이터삭제·DROP)은 PO 검토 후.**
- **머지 전 Vercel 프리뷰가 실제 빌드되는지 확인**(이번엔 프리뷰 ERROR를 안 보고 자동머지함).

**다. 8/27 우선순위**
- **코드는 거의 다 됐다.** 점수 가르는 건 **실데이터·증빙·사업비 집행 = PO 운영 몫.** 세션은 "안전·정직 인프라"(테스트분리·가드·회귀잠금·증빙 자동화)에 집중하고, 실적은 PO가 운영으로.
- 작업이 8/27 KPI(유치·상담·만족도)·증빙·정성(ICT·양한방)과 어떻게 연결되는지 항상 짚어라.

**라. PO 협업**
- PO는 **비개발자 1인**. 용어는 쉽게 풀되 원어 병기. 결과물·시각 우선.
- **결정 필요한 건 묶어서 `AskUserQuestion` 버튼**으로(평문 질문·\u 이스케이프 금지 — 한글 그대로).
- 답이 명백하면 묻지 말고 추천안으로 실행. 멈춰 세우는 건 ①돈 ②되돌리기 어려움뿐.

**마. 헌법(안 변함)**: `DESIGN.md`(Legacy 톤·"AI 느낌" 금지)·보안핵심규칙·`check:content`·소프트삭제.
