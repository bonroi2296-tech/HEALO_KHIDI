## 2. 왜 했나 — 재설계 전의 문제 3가지

1. **팔로우 불가 (PO 최대 페인)** — 어드민에 로그인해도 "지금 무슨 일이 벌어지는지" 알 수 없었다. 코디 전용 화면 4종(견적·비자·증상알림·문구편집)은 어드민 메뉴에 아예 없었고, 변경사항을 한자리에서 보는 화면도 없었다.
2. **권한 경계가 비일관** — 같은 환자 여정인데 케이스·전환·만족도는 코디 허용, 협진의뢰·리드는 어드민 전용. "왜 이건 되고 저건 안 되나"가 설명 불가능한 상태.
3. **죽은 화면이 메뉴를 채움** — 실DB 0행인 기능(플레이북·크롤·Import 등)이 메뉴 상단을 차지해, 진짜 쓰는 화면이 묻혔다.

> ⚠️ 재설계 중 **중요한 교정**: "에이전시·클리닉 포털은 빈 껍데기"라는 기존 인식은 **틀렸다**. 실측 결과 케이스 추적·환자 의뢰 폼·코디 메신저·견적 열람·경과 업로드(클리닉 전용)·자동번역이 **다 동작 중**이었다. "정체"의 실체는 기능 부재가 아니라 **개선이 코디·어드민에만 쏠렸던 것**.

## 3. 계층 지도 — 누가 어디로 들어와 무엇을 보나

계정은 **7계층**, 그중 **백오피스를 가진 건 5계층**이다. (환자는 `/patient` 앱, 게스트는 상담방만.)

| # | 계층 | 진입 | 화면 수 | 인증 가드 | 권한 저장소 |
|---|---|---|---|---|---|
| 1 | 비회원(게스트) | 초대링크 | 상담방 1 | `resolveConsultationActor` (X-Guest-Token) | 계정 없음(토큰) |
| 2 | 환자 | `/patient` | 환자앱 | 로그인 | 기본값(role 없음) |
| 3 | **코디네이터** | `/coordinator` | **13** | `requirePortalAuth({staffOnly})` | `app_metadata.role=coordinator` |
| 4 | **관리자** | `/admin` | **40+** | `requireAdminAuth` | `app_metadata.role=admin` + `ADMIN_EMAIL_ALLOWLIST` |
| 5 | **국내 의료기관** | `/hospital` | **4** (2개 플래그 OFF) | `checkHospitalAuth` | `hospital_users` 테이블 |
| 6 | **해외 에이전시** | `/agency` | 1 (공유 PartnerPortal) | `checkAgencyAuth` | `agency_users` + `partner_type='agency'` |
| 7 | **해외 의료기관** | `/clinic` | 1 (동일 PartnerPortal) | `checkAgencyAuth` (+`requirePartnerType`) | `agency_users` + `partner_type='medical_institution'` |

**의사는 계정 계층이 아니다** — 줌처럼 초대링크로 상담방에만 참여한다(2026-06-24 8계층→7계층).

**6·7이 한 인프라를 쓰는 이유**: 하는 일이 같다(한국으로 환자 의뢰 + 진행 추적). 별도 테이블·포털을 만들지 않고 `partner_type` **한 컬럼**으로만 구분 → 동기화 문제를 애초에 안 만든다.

### 발견된 구멍 4개와 처리

| 구멍 | 내용 | 처리 |
|---|---|---|
| **A. 코디 접근 불일치** | 같은 여정인데 referrals·leads만 admin 전용 | ✅ **수리** — `requirePortalAuth({staffOnly})`로 통일 (`app/api/admin/leads/*`, khidi/referrals) |
| **B. 콘텐츠 API가 rate limit·감사로그 우회** | 커스텀 requireStaff 사용 — 유일한 쓰기 경로에 리밋 없음 | ✅ **수리** — 표준 가드 + rate limit |
| **C. 상담 초대토큰 발급 권한 확대** | 모든 스태프가 담당 아닌 상담방 토큰 발급 가능 | ⛔ **조이지 않음(의도적)** — 과거에 걸었다가 담당 미지정 상담에서 코디가 자기 링크도 못 뽑는 실버그로 푼 것. 재조이면 재발 → 대신 **감사로그(`CREATE_CONSULTATION_INVITE`)로 추적성** 확보 |
| **D. agency↔clinic 가드 미분기** | partner_type 분기가 경과 업로드 1곳뿐 — "의료기관만" 데이터 추가 시 조용히 둘 다 통과할 구조 | ✅ **수리** — `requirePartnerType()` 게이트 헬퍼 신설 (`src/lib/auth/checkAgencyAuth.ts`) |

**양호 확인(실측)**: 공개 POST 전수 rate limit 있음 · `disabled` 킬스위치 전 계층 정합(어느 계층 계정에 찍혀도 전 포털 즉시 잠김).

## 10-1. 2026-08-25 — 「계층마다 따로 만들어 안 맞는다」 정리 (PO 지시)

PO: *"계층별로 따로따로 기능 구현을 따로 하다보니 일치하지가 않아."* 다섯 포털(어드민·코디·병원·해외 파트너·환자)을
같은 잣대로 대조한 결과와 조치.

### 무엇이 어긋나 있었나 (코드 실측)

| 공통 부품 | 어긋난 실태 |
|---|---|
| 문 앞 권한 확인 | **세 벌**(AdminGateClient 140줄 · StaffPortalGate 135줄 · HospitalGateClient 147줄 = 422줄). 하는 일은 같은데 어드민만 한국어 고정, 재시도 규칙이 셋 다 달랐다 |
| 서버 단계 확인 | `/agency`·`/clinic` 만 **아예 없었다**(나머지 넷은 proxy 에서 로그인 확인) |
| 브랜드 색 | 코디 사이드바만 파랑 — `DESIGN.md` 는 teal 하나로 못 박혀 있다 |
| 폰 알림 안내 | 어드민·코디에만 있고 병원엔 없었다(같은 스태프인데 한쪽만) |
| 병원 진료의뢰 상태 | 같은 표(`hospital_leads`)를 **두 화면이 다르게 불렀다** — sent 발송됨/전송됨 · rejected 거부됨/거절 · expired 만료됨/만료, 색도 달랐다 |

### 조치

1. **문지기 한 벌** — `app/_components/PortalGate.jsx` 신설, 세 벌 삭제(422줄 → 1벌). 계층별로 다른 건
   «확인 창구 주소 + 판정 함수»뿐. 병원 계정의 병원 id·이름은 `usePortalContext()` 로 꺼낸다.
   부수 효과: **어드민 거절 화면이 6개 언어가 됐다**(그전엔 한국어만).
2. **`/agency`·`/clinic` 서버 단계 확인 추가** — 미로그인이면 로그인 화면으로(나머지 넷과 동일).
   ⚠️ 자료가 새고 있던 게 아니다 — 조회 창구는 `checkAgencyAuth` 로 이미 막혀 있었다. **길안내가 없었던 것.**
   같이: `robots.js` 의 크롤러 차단 목록에도 둘을 넣었다(`/hospital`·`/coordinator` 만 있었다).
3. **코디 사이드바 파랑 → teal** (어드민·병원과 같은 값).
4. **병원 화면에 폰 알림 안내 추가.**
5. **병원 진료의뢰 상태 사전 한 벌** — `src/lib/leads/leadStatus.js`. 어드민·병원 두 화면이 같이 읽는다.
   ⚠️ 이건 «환자 여정 단계»(`src/lib/khidi/caseStatus`)와 **다른 것**이라 합치지 않았다 —
   여기는 「병원이 의뢰서를 봤나·답했나」, 저기는 「환자가 어느 단계인가」. 뜻이 다르다.
   검사: `src/lib/leads/leadStatus.test.ts` 가 서버 허용값(z.enum)과 사전을 대조한다.

### 일부러 «안» 한 것

| 안 한 것 | 왜 |
|---|---|
| 좌측 메뉴 껍데기 한 벌로 합치기 | 넷이 진짜로 다르다 — 어드민은 그룹+접힘, 병원은 평평한 4줄, 코디는 평평한 14줄, 환자는 하단 탭. 하나로 합치면 «설정으로 모양을 만드는 부품»이 되어 지금보다 읽기 어려워진다. **겉이 같아 보이는 것과 같은 부품인 것은 다르다.** |
| 환자 화면 사용설명서 | 환자에게 나가는 문구를 6개 언어로 내가 지어내야 한다. 카피는 PO 가 리드하는 영역이라 문구를 받은 뒤에 붙인다. |
| 환자·파트너 화면 폰 알림 안내 | 환자 앞에 알림 허용 배너를 띄우는 건 제품 판단이다(스태프 화면과 성격이 다르다). PO 지시 대기. |
| 「불편 접수함」 전 계층 확대 | 코디 전용으로 설계된 화면(`staff_requests`)이라 외부 파트너·환자에게 열려면 권한·스코프 설계가 따로 필요하다. |
