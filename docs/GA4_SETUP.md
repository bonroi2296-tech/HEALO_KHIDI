# GA4 설정 — PO가 콘솔에서 할 일 + 왜 전문가가 필요 없는가

> **한 줄**: 어려운 부분(코드·태그·이벤트 설계·동의·검증)은 전부 코드에 박아뒀다.
> 남은 건 GA 화면에서 **클릭 몇 번**이고, 아래 순서대로만 하면 된다.
>
> 마지막 갱신 2026-07-28 · 코드 SoR = `src/lib/ga.ts`

---

## 0. GA4 는 **무엇을 위한 도구인가** (2026-07-28 PO 방향 확정)

> **GA4 = 우리 서비스를 개선하기 위한 도구다. 정부과제 보고용이 아니다.**
> PO 지시(2026-07-28): *"ga4랑 이번 사업은 별개야. 우리 서비스를 개선하기 위해서지,
> khidi 사업에 너무 얽매이지 마라."*

그러니 GA 를 볼 때 던질 질문은 **「보고서에 몇 건이라 쓰지」**가 아니라 이런 것들이다:

- 사람들이 **어디서 오나** — 구글 검색? 얀덱스? 직접 입력? 어느 링크?
- **어느 화면을 보고** 문의까지 가나 — 병원 상세? 암종 상세? 비용 계산기?
- **어디서 포기하나** — 폼 1단계? 2단계? 메신저 고르다가?
- **어느 언어권**이 실제로 전환되나 — 러시아어 화면이 잘 되나, 카자흐어가 잘 되나?
- **앱과 웹 중 어디가** 더 잘 되나?

전부 **「무엇을 고쳐야 하나」로 이어지는 질문**이다. 그게 GA 를 다는 이유다.

### 곁다리로 알아둘 것 — GA 숫자는 «적게 센다»

GA4 는 **구조적으로 실제보다 적게 센다.**
- 쿠키 배너에서 **「필수만」을 고른 사람은 통째로 안 잡힌다** (동의해야만 추적).
- 러시아·카자흐 사용자는 **광고차단기·추적방지 브라우저 사용률이 높다** → 또 빠진다.
- 인앱 브라우저(왓츠앱·텔레그램에서 열기)에서도 자주 유실된다.

**그래서 GA 는 「비율·경향」을 보는 도구다.** 「러시아어 방문자가 카자흐어보다 2배 더
문의로 이어진다」 같은 **비교**는 믿을 만하다. 반면 **절대 건수**는 항상 실제보다 작다 —
정확한 건수가 필요하면 우리 데이터베이스(DB)를 보면 된다. 그건 하나도 안 샌다.

즉 **DB = 「정확히 몇 건인가」 / GA = 「왜 그렇게 됐나·뭘 고쳐야 하나」.** 역할이 다르다.
이 구분만 지키면 GA 에 큰 돈이나 전문가를 쓸 이유가 없다.

## 1. 지금 바로 해야 할 것 (5분, 순서대로)

GA4 접속 → 왼쪽 아래 **⚙️ 관리(Admin)** 클릭.

### ① 데이터 보존 기간 늘리기 ⚠️ **제일 급함**

`관리 → 데이터 표시 → 데이터 보관(Data retention)`
→ **「사용자 및 이벤트 데이터 보관」을 `14개월`로** 바꾸고 저장.

**왜 급한가**: GA4 **기본값이 2개월**이다. 그냥 두면 **「작년 이맘때랑 비교」·「지난 분기 대비」가
영영 불가능하다** — 서비스가 나아지고 있는지 판단하려면 비교할 과거가 있어야 하는데,
2개월치로는 계절성도 못 본다. **지난 것은 되살릴 수 없으니 오늘 바꿔야 오늘부터 쌓인다.**

### ② 전환(핵심 이벤트)으로 표시 — 3개

`관리 → 이벤트(Events)` 목록에서 아래 3개를 찾아 오른쪽 **「핵심 이벤트로 표시」 스위치를 켠다.**

| 이벤트 이름 | 무슨 뜻 |
|---|---|
| `inquiry_submitted` | **문의가 실제로 저장됨** (← 가장 중요) |
| `inquiry_detail_submitted` | 상세 정보까지 끝까지 입력함 |
| `inquiry_messenger_click` | 왓츠앱·텔레그램 등 사람 상담으로 넘어감 |

> 목록에 안 보이면 아직 그 이벤트가 한 번도 안 일어난 것이다.
> **3번(디버그 검증)으로 직접 한 번 발생시키면** 목록에 나타난다.

### ③ 맞춤 측정기준 등록 — 4개

`관리 → 맞춤 정의(Custom definitions) → 맞춤 측정기준 만들기`

4번 반복한다. 매번 **범위(Scope)는 「이벤트」**로 두고:

| 측정기준 이름 (아무거나) | 이벤트 매개변수 | 이게 있어야 볼 수 있는 것 |
|---|---|---|
| 플랫폼 | `platform` | **앱에서 왔나 웹에서 왔나** (스토어 앱은 웹사이트를 그대로 띄우는 구조라 이거 없으면 구분 불가) |
| 언어 | `lang` | 러시아어 화면이 전환이 잘 되나, 카자흐어가 잘 되나 |
| 암종 | `cancer_type` | 어느 암 문의가 많은가 |
| 국적 | `nationality` | 카자흐/러시아/우즈벡 중 어디가 실제로 오나 |
| 몇번째메시지 | `message_index` | AI 상담에서 **몇 마디 만에 그만두나** (2마디면 첫 답이 별로라는 뜻) |
| 평가 | `rating` | AI 답변 좋아요/싫어요 |
| 바꾼언어 | `to` | 어느 언어로 갈아탔나 (= 그 사람이 쓰던 언어 번역이 부족했다) |

⚠️ **등록 안 하면 데이터는 들어오는데 보고서에 안 뜬다.** (버려지는 건 아니고, 등록한 날부터 보인다.)

## 2. 진짜 되는지 **직접 확인하는 법** (이게 핵심)

분석은 **틀려도 화면이 멀쩡해서** 눈으로는 절대 검증이 안 된다.
그래서 실서비스에서 직접 볼 수 있는 통로를 만들어뒀다.

1. 휴대폰이나 PC 브라우저에서 이 주소를 연다:
   ```
   https://healwith.co.kr/?ga_debug=1
   ```
2. 쿠키 배너에서 **「전체 동의」**를 누른다. (필수만 누르면 추적이 안 된다 — 정상 동작)
3. GA4 → `관리 → DebugView` 를 연다.
4. 그 상태로 사이트를 돌아다니고 **문의 폼을 실제로 넣어본다.**
5. DebugView 에 **몇 초 안에** `page_view`, `inquiry_choose_channel`, `inquiry_submitted` … 가 그대로 뜬다.

뜨면 끝난 거다. 안 뜨면 그 화면을 캡처해서 알려주면 된다.

> `?ga_debug=1` 은 **그 탭에서만** 켜진다. 일반 방문자에겐 아무 영향 없다. 끄려면 `?ga_debug=0`.

## 3. 코드에 이미 박혀 있는 것 (형이 신경 쓸 필요 없음)

| 항목 | 상태 | 비고 |
|---|---|---|
| 태그 설치 · 측정ID | ✅ | `src/lib/ga.ts` 의 `GA_ID` 가 단일 기준(환경변수 아님) |
| 쿠키 동의 게이트 | ✅ | 「전체 동의」 전에는 스크립트조차 안 불러온다 |
| 관리자 화면 제외 | ✅ | `/admin` 은 추적 안 함 |
| 성능(첫 화면 안 느려지게) | ✅ | 첫 클릭·스크롤 뒤에 늦게 로드 |
| 화면 이동 집계(SPA) | ✅ | GA4 권장 방식(`page_view` 이벤트 + 전체 주소 명시) |
| **직원 트래픽 제외** | ✅ | 운영자·코디·병원 계정으로 로그인하면 **추적 자체를 끈다**. GA 콘솔의 IP 필터는 재택·모바일이면 안 걸려서, IP 대신 «로그인 역할»로 판단 |
| **기기 간 같은 사람 연결** | ✅ | 로그인 계정 id(무작위 UUID)만 전송. **이름·이메일·전화는 절대 안 보냄** |
| 앱/웹 구분 | ✅ | 모든 이벤트에 `platform` 자동 첨부 |
| 이벤트 이름 오타 방지 | ✅ | `GA_EVENTS` 카탈로그 + 자동 검사(CI)가 문자열 직접 입력을 막음 |
| 수집 주소 차단 방지 | ✅ | 보안 헤더(CSP)에 GA·얀덱스 주소 등록 + 자동 검사가 지속 감시 |
| 디버그 검증 | ✅ | `?ga_debug=1` (위 2번) |

## 3-1. 지금 재고 있는 것 — **「무엇을 고칠까」로 이어지는 질문별**

| 알고 싶은 것 | 보는 이벤트 |
|---|---|
| **AI 상담이 쓸모 있나?** | `chat_started`(열긴 하나) → `chat_message_sent`의 `message_index`(몇 마디 만에 그만두나) → `chat_feedback`(도움 됐나) → `chat_request_human`(AI가 못 푼 비율) |
| **어느 화면이 문의로 이어지나?** | `view_hospital` / `view_treatment` / `cost_estimated` → `inquiry_submitted` |
| **어디서 포기하나?** | `inquiry_step1_attempted` vs `inquiry_submitted` (= 서버 실패율) / `inquiry_dropoff`의 `phase` |
| **어느 번역을 먼저 손볼까?** | `language_changed`의 `from`→`to`. **`ru`→`en`이 많으면 러시아어 번역이 부족하다는 뜻**(핵심 시장인데 영어로 도망가는 것) |
| **비용 화면이 쓸모 있나?** | `cost_estimated` (그냥 들렀다 나간 사람과 실제로 조작해본 사람 구분) |
| **앱이 웹보다 잘 되나?** | 아무 이벤트 + `platform` 쪼개기 |
| **사람 상담(메신저)이 폼보다 잘 되나?** | `inquiry_choose_channel`의 `channel` → `inquiry_messenger_click` vs `inquiry_submitted` |

## 4. 일부러 **안 한** 것 (알고 넘어간 것)

- **구글 태그 관리자(GTM)** — 안 쓴다. 태그를 코드에 직접 박는 편이 우리처럼 개발자가 코드를 관리하는 구조에선 더 안전하고 빠르다. GTM 은 「개발자 없이 마케터가 태그를 붙이는」 도구인데 우리는 그 상황이 아니다.
- **구글 애즈(광고) 연동** — 광고를 안 돌리고 있으니 의미 없다. 시작하면 그때 붙인다(`AnalyticsWrapper.jsx` 에 자리 표시해둠).
- **동의 모드(Consent Mode v2)** — 아래 5번 참고. **PO 결정 대기.**
- **얀덱스 메트리카(Yandex Metrica)** — 코드와 보안 헤더는 준비돼 있고, 카운터 ID(`NEXT_PUBLIC_YANDEX_METRICA_ID`)만 넣으면 바로 돈다. 러시아·CIS 가 핵심 시장이라 **켤 가치가 있다**(러시아에선 구글보다 얀덱스 검색이 크다).

## 5. PO 결정이 필요한 것 — 동의 모드(Consent Mode v2)

**지금 방식**: 「전체 동의」를 안 누르면 **구글에 아무것도 안 보낸다.** 가장 보수적이고 가장 안전하다.
대신 **「필수만」을 고른 사람은 통계에서 통째로 사라진다.**

**동의 모드로 바꾸면**: 동의를 안 해도 **쿠키 없는 익명 신호**를 보내고, 구글이 그걸로
빠진 사람 수를 **추정**해준다. 유럽 기준으로 합법이며 요즘 업계 표준이다.
대신 **「동의 안 한 사람의 흔적도 구글로 간다」**는 점이 지금과 달라진다.

| | 지금 (로드 차단) | 동의 모드 v2 |
|---|---|---|
| 개인정보 관점 | **가장 보수적** | 합법이나 익명 신호는 전송 |
| 숫자 정확도 | 동의자만 = 과소집계 | 추정 보정 |
| 유럽(EEA) 방문자 | 사실상 안 잡힘 | 잡힘 |

우리 주 시장은 러시아·카자흐(유럽 아님)라 **효과가 제한적**이고, 의료 서비스라
개인정보에 보수적인 편이 신뢰에 유리하다는 판단도 가능하다. → **PO가 정할 것.**

## 6. 재발 방지 (개발 쪽)

- 반성문 **#145** — GA 수집 주소가 보안 헤더에 막혀 조용히 유실되던 건 + 문의 「성공」 이벤트가 서버 실패까지 성공으로 세던 건.
- 자동 검사(CI)에 **[분석누락] 룰**: ①보안 헤더 필수 주소 대조 ②이벤트 이름 문자열 직접 입력 금지.
- 새 이벤트를 추가할 땐 **반드시 `src/lib/ga.ts` 의 `GA_EVENTS` 에 먼저 넣고 상수로 부를 것.**
  (GA4 는 이름이 한 글자만 달라도 **다른 이벤트로 조용히 쌓고 아무도 안 알려준다.**)
