## 0. GA4 는 **무엇을 위한 도구인가** (2026-07-28 PO 방향 확정)

> **GA4 = 우리 서비스를 개선하기 위한 도구다. 정부과제 보고용이 아니다.**
> PO 지시(2026-07-28): *"ga4랑 이번 사업은 별개야. 우리 서비스를 개선하기 위해서지,
> khidi 사업에 너무 얽매이지 마라."*

그러니 GA 를 볼 때 던질 질문은 **「보고서에 몇 건이라 쓰지」**가 아니라 이런 것들이다:

- 사람들이 **어디서 오나** — 구글 검색? 얀덱스? 직접 입력? 어느 링크?
- **어느 화면을 보고** 문의까지 가나 — 병원 상세? 암종 상세? 비용 계산기?
- **어디서 포기하나** — 폼 1단계? 2단계? 메신저 고르다가?
- **어느 언어권**이 실제로 전환되나 — 러시아어 화면이 잘 되나, 카자흐어가 잘 되나?
- **앱과 웹 중 어디가** 더 잘 되나?

전부 **「무엇을 고쳐야 하나」로 이어지는 질문**이다. 그게 GA 를 다는 이유다.

### 곁다리로 알아둘 것 — GA 숫자는 «적게 센다»

GA4 는 **구조적으로 실제보다 적게 센다.**
- 쿠키 배너에서 **「필수만」을 고른 사람은 통째로 안 잡힌다** (동의해야만 추적).
- 러시아·카자흐 사용자는 **광고차단기·추적방지 브라우저 사용률이 높다** → 또 빠진다.
- 인앱 브라우저(왓츠앱·텔레그램에서 열기)에서도 자주 유실된다.

**그래서 GA 는 「비율·경향」을 보는 도구다.** 「러시아어 방문자가 카자흐어보다 2배 더
문의로 이어진다」 같은 **비교**는 믿을 만하다. 반면 **절대 건수**는 항상 실제보다 작다 —
정확한 건수가 필요하면 우리 데이터베이스(DB)를 보면 된다. 그건 하나도 안 샌다.

즉 **DB = 「정확히 몇 건인가」 / GA = 「왜 그렇게 됐나·뭘 고쳐야 하나」.** 역할이 다르다.
이 구분만 지키면 GA 에 큰 돈이나 전문가를 쓸 이유가 없다.

| 이벤트 이름 | 무슨 뜻 | 상태 |
|---|---|---|
| `inquiry_submitted` | **문의가 실제로 저장됨** (← 가장 중요) | ⏳ 목록 반영 대기 |
| `inquiry_detail_submitted` | 상세 정보까지 끝까지 입력함 | ⏳ 목록 반영 대기 |
| `inquiry_messenger_click` | 왓츠앱·텔레그램 등 사람 상담으로 넘어감 | ✅ 표시 완료 |

> 🧨 **여기서 시간을 잡아먹는 함정 (2026-07-30 실측)**: 별표는 **「지난 28일 안에 실제로 일어난 이벤트」에만** 달 수 있다.
> 목록에 없으면 새로 만들 방법이 없다 — 「이벤트 만들기」는 다른 기능이고, 이름을 직접 타이핑하는 칸은 없다.
> 그래서 2026-07-30 에 **실제로 문의 폼을 한 번 넣어 두 이벤트를 발생시켰다**(테스트 이메일 `@test.com` →

> 「최근 활동」 목록에는 몇 시간~다음날까지 안 나타난다** → 별표는 그때 다시 와서 누르면 된다.

### ③ 맞춤 측정기준 등록 — 7개 ✅ 완료

`관리 → 속성 설정 → 데이터 표시 → **맞춤 정의** → 「맞춤 측정기준 만들기」`

**7번** 반복한다. 매번 **범위(Scope)는 「이벤트」**(기본값 그대로)로 두고:

| 측정기준 이름 (아무거나) | 이벤트 매개변수 | 이게 있어야 볼 수 있는 것 |
|---|---|---|
| 플랫폼 | `platform` | **앱에서 왔나 웹에서 왔나** (스토어 앱은 웹사이트를 그대로 띄우는 구조라 이거 없으면 구분 불가) |
| 언어 | `lang` | 러시아어 화면이 전환이 잘 되나, 카자흐어가 잘 되나 |
| 암종 | `cancer_type` | 어느 암 문의가 많은가 |
| 국적 | `nationality` | 카자흐/러시아/우즈벡 중 어디가 실제로 오나 |
| 몇번째메시지 | `message_index` | AI 상담을 **몇 마디에서 멈추나** (⚠️ 짧다 = 나쁘다가 **아니다** — §7-0 참고) |
| 평가 | `rating` | AI 답변 좋아요/싫어요 |
| 바꾼언어 | `to` | 어느 언어로 갈아탔나 (= 그 사람이 쓰던 언어 번역이 부족했다) |

⚠️ **등록 안 하면 데이터는 들어오는데 보고서에 안 뜬다.** (버려지는 건 아니고, 등록한 날부터 보인다.)

> 💡 **실측 팁**: 「이벤트 매개변수」 칸은 **목록에서 고르는 것 + 직접 타이핑 둘 다 된다.** 아직 한 번도
> 안 들어온 매개변수(예: `nationality`)도 그냥 타이핑하면 저장된다. 목록에 뜨면 = 이미 데이터가 들어온 것.

## 2. 진짜 되는지 **직접 확인하는 법** (이게 핵심)

분석은 **틀려도 화면이 멀쩡해서** 눈으로는 절대 검증이 안 된다.
그래서 실서비스에서 직접 볼 수 있는 통로를 만들어뒀다.

1. 휴대폰이나 PC 브라우저에서 이 주소를 연다:
   ```
   https://healwith.co.kr/?ga_debug=1
   ```
2. 아래 쿠키 배너에서 **「모두 허용」**을 누른다. (실제 화면의 버튼 글자다 — 옆의 **「필수만 허용」**을
   누르면 추적이 안 된다. 그게 정상 동작이다.)
3. 화면 **왼쪽 아래에 자가진단 상자**가 뜬다. 개발자도구 열 필요 없다.
   판정 줄이 전부 ✅ 면 제목이 초록색 **「GA 정상 — 들어가고 있음」** 으로 바뀐다.

   | 줄 | ❌ 면 뜻 / 할 일 |
   |---|---|
   | 측정 ID | 코드에 ID가 없음 = 개발 쪽 문제 |
   | 쿠키 동의 | 「모두 허용」을 안 눌렀다 → 누르면 된다 |
   | 실서비스 모드 | 개발 서버로 보고 있다 (개발에선 원래 안 보냄) |
   | 관리자 경로 | `/admin` 은 일부러 제외 → 일반 화면에서 봐라 |
   | gtag.js | 구글 스크립트가 안 내려옴. **2.5초 뒤 자동으로 한 번 재시도**한다. 실측상 1위 원인은 **광고차단기**(아래) |
   | 화면 조회 전달 | 아직이면 잠깐 기다려라 (스크립트가 늦게 내려오는 중). ✅ 라도 **「대기줄에 실렸다」는 뜻**이지 도착했다는 뜻은 아니다 |
   | 수집 주소 | ❌ 면 **광고차단기·DNS 가 수집 주소를 막고 있다** → 이 기기에선 아무것도 GA 에 도착하지 않는다 |
   | 직원 계정 | 직원으로 로그인 중 = **일부러 추적을 끈 것**. 로그아웃하고 봐라 |

   > 맨 아래 「우리 이벤트 N건」은 **참고용이고 판정에 안 쓴다.** 첫 화면만 보고 나가면
   > **0건이 정상**이다 — 랜딩(첫 진입) 조회는 우리 코드가 아니라 **gtag.js 가 스스로 보낸다.**
   > (⚠️ 처음엔 이 건수를 합격 조건에 넣었었다. 그러면 **잘 되는 상태를 「실패」로 표시**한다 —
   >  자가진단이 거짓말을 하는 셈이라 별도 검토에서 잡혀 고쳤다.)

4. 그 상태로 사이트를 돌아다니고 **문의 폼을 실제로 넣어본다.**
5. GA4 → `관리 → DebugView` 에 **몇 초 안에** `page_view`, `inquiry_choose_channel`, `inquiry_submitted` … 가 그대로 뜬다.

> `?ga_debug=1` 은 **그 탭에서만** 켜진다. 일반 방문자에겐 아무 영향 없다. 끄려면 `?ga_debug=0`.

게다가 그걸 아는 방법이 「개발자도구 콘솔 읽기」뿐이라 PO 가 스크린샷을 찍어 물어봐야 했다.

그래서 두 가지를 고쳤다.

- **판정을 화면에 띄운다** (위 자가진단 상자) — DevTools 없이 한 번 보면 끝.
- **로드 실패 시 2.5초 뒤 한 번 재시도한다.** 실패하는 동안에도 이벤트는 `dataLayer` 에
  쌓여만 있으므로, 뒤늦게 스크립트가 내려오면 **놓친 것까지 살아난다.**
  (전에는 구글이 한 번 튕기면 그 세션이 통째로 측정 0 이었다 — 광고비가 들어가는
  트래픽에서 이건 그대로 «성과가 없네»로 오독된다.)

### 🚨 2-1. 그 500 의 정체 — **PO PC 의 광고차단기(AdGuard)였다** (2026-07-30 오후, 재현 성공)

어제는 «구글 일시 오류 아니면 브라우저 확장»이라는 **가설**로 남겨뒀다. 오늘 PO 크롬으로 같은
주소를 열어 응답 «본문»까지 읽어보니 답이 그대로 적혀 있었다:

```
status 500 · content-length 24 · 본문:  /* Blocked by AdGuard */
```

같은 순간 **브라우저 밖**(PowerShell)에서 같은 주소를 받으면 **200 · 490KB 정상**이다.
즉 구글도 우리 코드도 결백하고, 막는 건 **이 PC 에 깔린 AdGuard for Windows 7.22.9**다.

**그리고 더 큰 것이 같이 나왔다 — 수집 주소가 DNS 에서 통째로 막혀 있다.**

| 주소 | 이 PC 에서 조회한 결과 | 무슨 뜻 |
|---|---|---|
| `www.google-analytics.com` | **0.0.0.0** | GA 로 보내는 데이터가 **아예 안 나간다** |
| `region1.google-analytics.com` | **0.0.0.0** | 지역 수집기도 막힘 |
| `analytics.google.com` | **0.0.0.0** | **GA4 콘솔 화면 자체가 안 열린다** |
| `stats.g.doubleclick.net` | **0.0.0.0** | 구글 광고 쪽 신호도 막힘 |
| `www.googletagmanager.com` | 정상 IP | 주소는 살아 있는데 **파일을 AdGuard 가 500 으로 바꿔친다** |

근거 파일(사람이 열어볼 수 있다): `C:\ProgramData\Adguard\DnsFilters\…\dns_filter_1.txt` 안에
`||analytics.google.com^` · `||google-analytics.com^` 이 그대로 들어 있다. DNS-over-HTTPS 로
우회 조회하면 진짜 IP 가 나온다 → **막는 주체가 이 PC 안에 있다는 반증까지 통과.**

⚠️ **어제 적어둔 판별법(「확장 없는 시크릿창」)은 틀린 안내였다.** AdGuard 는 브라우저 확장이
아니라 **윈도 프로그램**이라 시크릿창도 똑같이 막는다. 올바른 판별법은 아래 셋 중 하나다.

| 방법 | 언제 쓰나 |
|---|---|
| AdGuard 를 **잠시 끄기**(트레이 아이콘 → 보호 일시 중지) | 지금 당장 확인할 때. 끝나면 다시 켜라 |
| AdGuard **예외 목록**에 `analytics.google.com`·`google-analytics.com` 추가 | GA 콘솔·보고서를 계속 봐야 하니 **이건 사실상 필수** |
| **다른 기기·회선**(폰의 모바일 데이터 등)에서 열기 | 우리 PC 를 안 건드리고 확인하고 싶을 때 |

> 💡 **차단이 나쁜 것만은 아니다** — PO PC 의 방문이 GA 에 안 잡히는 건 「직원 트래픽 제외」와
> 같은 효과다(우리는 그걸 코드로도 하고 있다). **문제가 되는 건 딱 두 가지**: ①PO 가 **GA 콘솔을
> 못 연다** ②**측정이 고장난 것처럼 보여 헛수고를 한다**(어제 실제로 그랬다).

> 🧷 **이번에 배운 진단 순서** (다음에 다른 사이트에서 또 만난다):
> ①응답 «상태 코드»가 아니라 **본문을 읽어라** — 차단 프로그램은 대개 거기에 이름을 남긴다.
> ②**브라우저 안 / 브라우저 밖**에서 같은 주소를 각각 받아봐라 — 갈리면 원인은 브라우저 구간(확장·차단기)이다.
> ③**주소 조회(DNS)를 따로 재라** — `0.0.0.0` 이면 프로그램·회선 차단이다.

## 5. PO 결정이 필요한 것 — 동의 모드(Consent Mode v2)

**지금 방식**: 「전체 동의」를 안 누르면 **구글에 아무것도 안 보낸다.** 가장 보수적이고 가장 안전하다.
대신 **「필수만」을 고른 사람은 통계에서 통째로 사라진다.**

**동의 모드로 바꾸면**: 동의를 안 해도 **쿠키 없는 익명 신호**를 보내고, 구글이 그걸로
빠진 사람 수를 **추정**해준다. 유럽 기준으로 합법이며 요즘 업계 표준이다.
대신 **「동의 안 한 사람의 흔적도 구글로 간다」**는 점이 지금과 달라진다.

| | 지금 (로드 차단) | 동의 모드 v2 |
|---|---|---|
| 개인정보 관점 | **가장 보수적** | 합법이나 익명 신호는 전송 |
| 숫자 정확도 | 동의자만 = 과소집계 | 추정 보정 |
| 유럽(EEA) 방문자 | 사실상 안 잡힘 | 잡힘 |

우리 주 시장은 러시아·카자흐(유럽 아님)라 **효과가 제한적**이고, 의료 서비스라
개인정보에 보수적인 편이 신뢰에 유리하다는 판단도 가능하다. → **PO가 정할 것.**

## 7. 데이터가 쌓인 뒤 — **어떻게 분석하나** (PO 질문 2026-07-28)

> 분석해야 하니? 지금 니가 설정한 건 추측이고 절대가 아니잖아"* → **맞는 지적이다.**

### 7-0. 먼저 인정할 것 — **내가 심어둔 해석은 «가설»이지 «사실»이 아니다**

이벤트를 만들 때 나는 «이 숫자가 크면 이런 뜻일 것이다»를 가정했다. **그 가정은 틀릴 수 있다.**
같은 숫자가 정반대 두 가지를 뜻할 수 있는 경우가 실제로 있다:

| 숫자 | 내가 가정한 뜻 | **정반대 해석(이것도 가능)** |
|---|---|---|
| AI 상담을 **2마디에서 멈춤** | 첫 답이 시원찮아서 포기했다 | **한 번에 답을 얻어서 더 물을 게 없었다** (= 성공) |
| `ru` → `en` 언어 전환 | 러시아어 번역이 부족하다 | 원래 영어가 더 편한 사람인데 접속 위치 때문에 러시아어로 열렸다 |
| 비용 계산기 조작 적음 | 화면이 쓸모없다 | 첫 화면에서 바로 답을 봐서 만질 필요가 없었다 |
| 문의 폼 이탈 많음 | 폼이 불편하다 | 애초에 살 마음이 없는 방문자(광고 유입)가 많았다 |

**그래서 숫자만 보고 고치면 안 된다.** 숫자는 **「어디를 볼지」**를 알려주는 손전등이지,
**「무엇이 문제인지」**를 말해주지 않는다. 아래 순서가 그 간극을 메우는 방법이다.

---

### 7-1. 처음 2~4주는 **판단 금지** — 기준선만 쌓아라

표본이 적으면 **무엇이든 그럴듯해 보인다.** 전환 20건일 때
「러시아어가 카자흐어보다 2배 잘 된다」는 **동전을 20번 던져도 나오는 차이**다.

**대략의 눈금(정확한 통계가 아니라 실전 감각):**

| 비교하려는 각 칸의 전환 건수 | 할 수 있는 말 |
|---|---|
| ~30건 미만 | **「아직 모른다」가 정답.** 어떤 결론도 내지 마라 |
| 30~100건 | 「어? 다른 것 같은데」 — **가설로만** 쓰고 더 모아라 |
| 100건 이상 | 꽤 믿을 만하다. 단 **2배쯤 차이**나야 의미 있다(10% 차이는 여전히 우연) |

⚠️ 우리처럼 트래픽이 이제 시작인 서비스에서 **첫 달에 대시보드를 보고 뭘 고치는 건
거의 항상 손해**다. 그 시기엔 **§2 의 DebugView 로 「제대로 들어오나」만 확인**하면 된다.

### 7-2. **한 번에 질문 하나만**

대시보드를 훑지 마라. 화면이 많아서 뭐든 눈에 띄고, 눈에 띈 걸 원인이라 착각하게 된다.
**이번 주에 답할 질문 하나**를 종이에 적고 그것만 본다. 예:

> *"광고로 온 사람이 검색으로 온 사람보다 문의를 덜 하나?"*

### 7-3. 절대 숫자 말고 **깔때기에서 가장 크게 새는 칸 하나**

```
방문 → 문의 화면(inquiry_channel_view) → 방식 선택(inquiry_choose_channel)
     → 폼 시작(inquiry_step1_started) → 전송 시도(inquiry_step1_attempted)
     → ✅ 저장 성공(inquiry_submitted)
```

각 칸에서 **다음 칸으로 몇 %가 넘어가는지**만 보고, **제일 크게 새는 칸 하나**를 고른다.
여러 칸을 동시에 고치면 **뭐가 효과였는지 영영 모른다.**

> 💡 `inquiry_step1_blocked` 가 크면 그건 **거의 확실한** 신호다 —
> 「보내려고 눌렀는데 우리가 막았다」는 해석의 여지가 별로 없다. **여기부터 고쳐라.**

### 7-4. **비교로만** 판단하라 (절대값은 못 믿는다)

GA 는 구조적으로 적게 센다(§0). 그러니 「문의 37건」이라는 **절대값은 의미 없다.**
대신 **같은 조건끼리의 비교**는 믿을 만하다 — 빠지는 비율이 양쪽에 비슷하게 걸리니까.

- 러시아어 vs 카자흐어 vs 영어 (`lang`)
- 앱 vs 웹 (`platform`)
- 광고 A vs 광고 B (아래 7-6)
- **이번 달 vs 지난달** (← 그래서 데이터 보존 14개월이 중요하다)

### 7-5. ⭐ 숫자로 **가설**을 세우고, **사람에게 확인**하라 (이게 제일 중요)

**GA 는 「어디서」를 알려주고, 「왜」는 절대 말해주지 않는다.**

우리에겐 큰 장점이 있다 — **실제 사람이 있다.** 코디(아셀), 문의를 넣은 환자,
메신저로 대화한 사람. **5명한테 직접 물어보는 게 방문자 100명 데이터보다 낫다.**

```
① GA 에서 이상한 칸을 찾는다        → "폼 2단계에서 절반이 나간다"
② 「왜 그럴까」 가설을 2~3개 적는다   → 파일 올리기가 어렵나? / 질문이 많나? / 급하지 않나?
③ 실제 사람에게 물어본다            → 아셀에게 "환자들이 서류 올릴 때 뭐라고 하냐"
④ 답을 듣고 하나만 고친다
⑤ 2~4주 뒤 같은 칸을 다시 본다
```

③ 없이 ①→④ 로 건너뛰는 게 **가장 흔한 실패**다. 그게 「추측으로 고치기」다.

### 7-6. 📢 광고를 돌린다면 — **링크에 꼬리표를 붙여야** 한다

⚠️ **이걸 안 하면 「어느 광고가 문의를 만들었나」를 영영 못 본다.** 광고 클릭이 전부
「직접 방문」이나 「출처 불명」으로 뭉뚱그려진다.

광고에 넣는 주소 뒤에 이렇게 붙인다:

```
https://healwith.co.kr/?utm_source=yandex&utm_medium=cpc&utm_campaign=ru_lung_2608
```

| 꼬리표 | 뜻 | 예 |
|---|---|---|
| `utm_source` | 어디에 낸 광고인가 | `yandex` · `google` · `instagram` · `telegram` |
| `utm_medium` | 광고 종류 | `cpc`(클릭당 과금) · `banner` · `email` |
| `utm_campaign` | 어느 광고인가 (내가 구분할 이름) | `ru_lung_2608` · `kz_stomach_2608` |

> ✅ **우리 사이트가 이 꼬리표를 지켜주는지 실측 확인함(2026-07-28)** — 옛 주소(`/intake`·`/consult/start` 등)로
> 들어와도 꼬리표가 살아남는다. **원래는 버려지고 있었고**(반성문 #149) 그때 고쳤다.
> 자동 검사가 계속 감시하므로 앞으로 새 리다이렉트가 이걸 깨뜨리면 CI 가 막는다.

**규칙 하나**: 이름을 **한 번 정하면 절대 바꾸지 마라.** `yandex` 와 `Yandex` 를 섞어 쓰면
GA 는 **다른 출처 2개**로 센다(이벤트 이름 오타와 똑같은 부류다).

그리고 **광고를 켠 직후 전환율이 떨어져 보이는 건 정상이다** — 관심이 옅은 사람이
많이 들어오니까 비율은 내려간다. **비율 말고 「문의 건수」가 늘었는지**를 봐라.

### 7-7. 바꿨으면 **전/후를 같은 자로** 재라

무언가 고친 날짜를 **적어두고**, 그 앞 2~4주 vs 뒤 2~4주를 같은 지표로 비교한다.
날짜를 안 적으면 나중에 「좋아진 것 같은데 뭐 때문이지?」로 끝난다.

> 📌 우리는 이미 기록 습관이 있다 — 고친 날은 `docs/PROJECT_CONTEXT.md` 핸드오프에 남는다.
> **분석할 때 그 문서를 같이 펴라.** 「7월 28일에 폼 손봄」 같은 줄이 곧 비교 기준선이다.

### 흔한 함정 (이걸로 여러 번 헛짚는다)

| 함정 | 왜 틀리나 |
|---|---|
| **적은 표본으로 결론** | 20건짜리 차이는 대부분 우연이다 (§7-1) |
| **절대 건수를 진짜라고 믿음** | GA 는 항상 적게 센다. 정확한 건수는 **DB** 를 봐라 |
| **같이 움직였다 = 원인이다** | 비 오는 날 우산이 팔린다고 우산이 비를 부르는 게 아니다 |
| **요일·시간 무시** | 주말·명절·라마단 등으로 크게 흔들린다. **최소 «주» 단위**로 봐라 |
| **한 번에 여러 개 고침** | 뭐가 효과였는지 영영 모른다 |
| **좋은 숫자만 봄** | 「우리가 잘하고 있다」를 확인하러 가면 반드시 그런 숫자를 찾아낸다 |

### 언제 「전문가」가 필요해지나 (지금은 아니다)

- 광고비가 **월 수백만원** 단위로 커져서 「어느 광고에 얼마 더 넣을지」가 돈이 될 때
- 방문자가 충분해서 **A/B 테스트**(두 화면을 반씩 보여주고 비교)를 돌릴 수 있을 때

그 전까지는 **§7-5(사람에게 물어보기)가 어떤 분석보다 정확하다.**

## 8. ⭐ **광고를 켜기 전 체크리스트** — 이 작업의 진짜 목적 (2026-07-29 PO 확인)

> **PO 지시(2026-07-29)**: *"지금 하고 있는 거 결국은 우리 힐위드 광고 오픈했을 때 셋팅 잘하기
> 위해서 연습삼아 하는 거 알지? 연습이라고 대충하라는 얘기는 아니고, **처음 하는 거니까 잘 기록하고
> 다음에 힐위드에도 잘 붙여야 해.**"*
>
> 그래서 이 절은 **「이번에 뭘 고쳤나」가 아니라 「다음에 광고 켤 때 무슨 순서로 하나」**로 적는다.
> 위 §0~§7 이 «지금 상태 설명서»라면, 여기는 **«다음 번 실행 절차»**다.

### 왜 순서가 중요한가 — **측정이 광고보다 먼저다**

광고를 먼저 켜고 측정을 나중에 붙이면, **그 사이 쓴 돈은 영영 출처를 모른다.** 소급이 안 된다.
2026-07-28 에 실제로 그랬다 — 광고를 이미 돌리는 중에 «옛 주소로 들어온 클릭의 출처가 통째로
증발하고 있던 것»을 발견했고, **이미 나간 클릭은 되살릴 수 없었다**(반성문 #149).

---

### 🔢 광고 켜기 전 (순서대로)

#### 1단계. 측정이 «실제로» 도는지 눈으로 확인 — 가장 먼저

- `사이트주소/?ga_debug=1` 로 열고 쿠키 **「모두 허용」** → 왼쪽 아래 **자가진단 상자가 초록색 제목**인지 본다 (§2)
- 그다음 GA4 `관리 → DebugView` 에서 **이벤트가 뜨는 걸 사람이 직접 봐야 한다.** 코드·검사가 다 초록이어도 이걸 보기 전엔 「됐다」가 아니다.
- ⚠️ **이유**: 분석은 «틀려도 화면이 멀쩡»하다. 빌드 통과·404 없음·사용자 불편 0인데 **숫자만 조용히 틀린다.**
- ⚠️ **한 번 봤다고 끝이 아니다.** 2026-07-30 에 gtag.js 가 **500 으로 튕기는** 걸 실제로 봤다.
  즉 「어제 됐음」이 「오늘도 됨」을 보장하지 않는다 → 광고를 켠 뒤에도 **가끔 이 상자로 다시 확인**하고,
  코드에는 **실패 시 자동 재시도**를 넣어둔다(§2 참고). 다른 사이트에 옮길 때도 이 둘을 같이 옮겨라.
- 🚧 **0단계로 올려야 할 것 — 검사하는 기기에 광고차단기가 깔려 있으면 무슨 짓을 해도 ❌ 다.**
  그 500 의 정체가 **PO PC 의 AdGuard** 였다(§2-1, 재현 확정). 시크릿창으로는 안 걸러진다.
  **검증은 「차단기 없는 기기·회선」에서 하거나, 차단기를 잠시 끄고 해라.** 이걸 모르고 «측정이
  고장났다»고 판단하면 **멀쩡한 코드를 하루 종일 뒤진다**(실제로 반나절 썼다).

#### 2단계. GA4 콘솔 3가지 (5분)

| 할 일 | 왜 |
|---|---|
| **데이터 보존 → 14개월** | 기본이 **2개월**. 그냥 두면 「지난 분기 대비」가 영영 불가능. **지난 건 소급 불가라 늦을수록 손해** |
| **전환(핵심 이벤트) 표시** | 표시 안 하면 「어느 광고가 성과를 냈나」 보고서가 안 만들어진다 |
| **맞춤 측정기준 등록** | 등록 «전» 기간의 값은 보고서에서 **영영 못 본다** |

#### 3단계. 광고 링크 규칙을 «먼저» 정한다

```
사이트주소/?utm_source=yandex&utm_medium=cpc&utm_campaign=ru_lung_2608
```

- **이름을 한 번 정하면 절대 바꾸지 마라** — `yandex` 와 `Yandex` 를 섞으면 GA 는 **다른 출처 2개**로 센다.
  (이벤트 이름 오타와 같은 부류: 기계는 안 알려주고 숫자만 갈라진다.)
- **광고 소재를 만들기 전에** 이름 규칙을 정해서 적어둘 것. 나중에 바꾸면 앞뒤 데이터가 안 이어진다.

#### 4단계. 🧨 **링크가 꼬리표를 «지키는지» 실제로 재본다** (이번에 크게 데인 곳)

```bash
curl -sS -o /dev/null -w "%{redirect_url}\n" "https://사이트/옛주소?utm_source=test"
```

- 결과에 **`utm_source=test` 가 남아 있어야 한다.** 사라지면 그 경로로 들어온 광고비는 추적 불가.
- **우리가 실제로 버리고 있었다** — 옛 주소(`/intake`·`/consult/start` 등) **7곳**. 화면은 멀쩡히 떠서 아무도 몰랐다.
- 이제 자동 검사(`check:content` 의 `[출처유실]` 룰)가 막지만, **다른 사이트(예: Probelle)에는 그 가드가 없다** → 새로 붙일 땐 반드시 이 `curl` 을 돌려볼 것.
- **광고 링크는 되도록 «옛 주소」가 아니라 최종 주소를 직접 가리켜라** — 거쳐가는 단계가 없으면 샐 곳도 없다.

#### 4-1단계. 🩺 **계측기 자체가 가끔 죽는다는 걸 전제로 깔아라** (2026-07-30 실측)

- gtag.js 가 **500 으로 튕기는 걸 실제로 봤다.** 화면은 멀쩡했고 사용자 불편은 0 이었다 = 아무도 모른다.
- 그래서 새 사이트에 붙일 때 **반드시 같이 옮길 두 가지**:
  1. **로드 실패 시 재시도 1회** (`app/AnalyticsWrapper.jsx`). 실패 중 이벤트는 `dataLayer` 에 쌓여
     있으므로 뒤늦게 내려와도 **살아난다** — 재시도가 실제로 데이터를 되찾아 준다.
  2. **화면에 뜨는 자가진단 표시** (`app/GaDebugBadge.jsx`). 확인을 사람의 「개발자도구 읽기」에
     맡기면, 실패인데도 화면이 멀쩡해서 **통과로 착각한다**(실제로 그랬다 — 반성문 #161).

#### 5단계. 🛑 광고 계정을 GA 와 연결할 때 — **정책 위반 조심**

- **건강 상태(질환명) 기반으로 「잠재고객」을 만들지 마라.** 구글·얀덱스 광고 정책상 금지 → **계정 정지 위험.**
- 우리 이벤트엔 `cancer_type`(암종)이 들어간다. **전환 측정 목적의 연결은 괜찮지만, 그 값으로 리타게팅 대상을 만들면 안 된다.**
- 리타게팅이 필요하면 **행동 기준**으로: 「문의 폼을 열었다가 안 낸 사람」 — 질환명이 안 들어가면 문제없다.

### ▶ 광고를 켠 뒤 — **판단하기 전에 알아둘 것**

| 함정 | 진실 |
|---|---|
| 「전환율이 떨어졌다」 | **정상이다.** 관심 옅은 유입이 늘어 분모가 커진다 → **비율 말고 「건수」**를 봐라 |
| 「GA 숫자가 광고 플랫폼보다 적다」 | **정상이다.** 동의 안 한 사람·광고차단기로 구조적 과소집계 → **정확한 건수는 DB 를 봐라** |
| 「메신저 광고가 성과가 나쁘다」 | **불리하게 나온다.** 앱 안 브라우저는 저장소가 격리돼 추적이 자주 끊긴다. 하필 러·CIS 가 메신저 비중 최상위 |
| 「일주일 해봤는데 A가 B보다 낫다」 | **표본이 작으면 우연이다.** 각 칸에 전환 30건 미만이면 「아직 모른다」가 정답 (§7-1) |

**고칠 땐 한 번에 하나만**, 그리고 **바꾼 날짜를 적어라**(§7-7). 안 그러면 뭐가 효과였는지 영영 모른다.

### 📌 다른 사이트에 이 설정을 옮길 때 (예: Probelle 쇼핑몰)

이 문서는 **HEALO(직접 만든 사이트)** 기준이다. 남의 플랫폼(카페24·아임웹 등)은 다음이 다르다:

| | HEALO (직접 개발) | 카페24 등 (남의 플랫폼) |
|---|---|---|
| 태그 넣는 곳 | 코드(`src/lib/ga.ts`) | 관리자 화면 또는 태그 관리자 |
| 이벤트 만들기 | 코드로 직접 | **`dataLayer` 를 스킨에 심어야** 한다 |
| 쇼핑몰 전용 | 해당 없음 | **매출·장바구니·결제**를 재야 값어치가 난다 |
| 가드(자동 검사) | ✅ 있음 | ❌ **없다** — 4단계 `curl` 확인을 사람이 해야 |

⚠️ **쇼핑몰은 「문의」가 아니라 「매출」이 목표**라, 위 3단계까지는 같고 **결제 완료 화면에서 금액이 잡히는지**가 전부를 가른다. 거기가 안 되면 나머지는 곁다리다.

## 6. 재발 방지 (개발 쪽)

- 반성문 **#145** — GA 수집 주소가 보안 헤더에 막혀 조용히 유실되던 건 + 문의 「성공」 이벤트가 서버 실패까지 성공으로 세던 건.
- 자동 검사(CI)에 **[분석누락] 룰**: ①보안 헤더 필수 주소 대조 ②이벤트 이름 문자열 직접 입력 금지.
- 새 이벤트를 추가할 땐 **반드시 `src/lib/ga.ts` 의 `GA_EVENTS` 에 먼저 넣고 상수로 부를 것.**
  (GA4 는 이름이 한 글자만 달라도 **다른 이벤트로 조용히 쌓고 아무도 안 알려준다.**)
