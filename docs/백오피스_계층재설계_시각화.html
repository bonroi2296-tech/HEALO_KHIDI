01

왜 했나 — 재설계 전의 문제 셋

화면이 부족한 게 아니라, 화면끼리 연결이 없었다.

문제 1 · PO 최대 페인

팔로우가 안 됐다

어드민에 로그인해도 지금 무슨 일이 벌어지는지 알 수 없었다. 코디 전용 화면 4종(견적·비자·증상알림·문구편집)은 어드민 메뉴에 아예 없었고, 변경사항을 한자리에서 보는 화면도 없었다.

문제 2 · 권한

경계가 설명 불가능했다

같은 환자 여정인데 케이스·전환·만족도는 코디가 되고, 협진의뢰·리드는 어드민 전용. “왜 이건 되고 저건 안 되나”에 답할 수 없는 상태였다.

문제 3 · 메뉴

죽은 화면이 자리를 차지했다

실DB 0행인 기능(플레이북·크롤·Import 등)이 메뉴 상단을 점유해, 매일 쓰는 화면이 그 밑에 묻혔다.

재설계 중 중요한 교정. “에이전시·클리닉 포털은 빈 껍데기”라는 기존 인식은 틀렸다. 실측해보니 케이스 추적·환자 의뢰 폼·코디 메신저·견적 열람·경과 업로드(클리닉 전용)·자동번역이 전부 동작 중이었다. ‘정체’의 실체는 기능 부재가 아니라 개선이 코디·어드민에만 쏠렸던 것이다.
02

계층 지도 — 포함 관계로 다시 그림

계정은 7계층, 그중 백오피스를 가진 건 5계층이다. 핵심은 나열이 아니라 포함 관계 — 어드민이 코디를 품고, 파트너 3계층은 같은 테이블을 API 게이트 너머에서 본인 몫만 본다.

스태프 — 포함 관계 (어드민 ⊃ 코디)

원칙 1 · 상위집합

관리자 /admin

화면 40+ · requireAdminAuth · app_metadata.role=admin + ADMIN_EMAIL_ALLOWLIST

통합 대시보드 🆕 KHIDI 리포트 상담·문의 9 파트너·회원 7 콘텐츠 3 AI 품질 6 시스템 4

코디네이터 /coordinator

🆕 표시 4개 = 코디에만 있던 화면. 5단계에서 화면을 새로 만들지 않고 어드민 메뉴에 링크만 연결했다(스태프 게이트가 어드민을 통과시킴).

백오피스 밖 환자 — /patient 6개 언어 환자앱 비회원(게스트) — 초대링크 토큰으로 상담방만 의사 — 계정 없음, 줌처럼 링크로 상담방 참여
6번과 7번이 한 인프라를 쓰는 이유. 해외 에이전시와 해외 의료기관은 하는 일이 같다 — 한국으로 환자를 의뢰하고 그 환자의 진행을 추적한다. 그래서 포털·테이블을 새로 만들지 않고 partner_type 한 컬럼으로만 구분한다. 화면은 라벨만 바뀐다.

재설계 원칙 4개

1 · 어드민 = 통합 콘솔

모든 계층 화면의 상위집합. 코디 전용 4종도 어드민 메뉴에서 열린다.

2 · 코디 = 실무 화면

admin 페이지를 직접 re-export하는 방식이 표준. 화면 따로 만들기(drift)는 신규 금지.

3 · 파트너 = 외부 뷰

테이블 공용 + API 게이트로만 분리. 계층별 사본 테이블 금지.

4 · 설명서는 같은 PR에

기능이 바뀌면 src/lib/manuals도 같은 PR에서 고치고 날짜를 올린다.

발견된 구멍 4개와 처리 — 하나는 일부러 안 고쳤다

구멍내용처리
A 코디 접근 불일치 — 같은 여정인데 referrals·leads만 admin 전용 ✅ 수리 — requirePortalAuth({ staffOnly })로 통일
B 콘텐츠 API가 rate limit·감사로그 우회 — 커스텀 가드를 써서, 유일한 문구 쓰기 경로에 제한이 없었다 ✅ 수리 — 표준 가드 + rate limit 적용
C 상담 초대토큰 발급 범위 — 모든 스태프가 담당 아닌 상담방의 게스트 토큰을 발급할 수 있다 ⛔ 일부러 조이지 않음. 과거에 걸었다가 담당 미지정 상담에서 코디가 자기 링크도 못 뽑는 실버그로 푼 것 — 재조이면 재발한다. 대신 발급 감사로그(CREATE_CONSULTATION_INVITE)로 추적성 확보
D 에이전시↔클리닉 가드 미분기 — partner_type 분기가 경과 업로드 1곳뿐이라, “의료기관만” 데이터를 추가하면 조용히 둘 다 통과할 구조였다 ✅ 수리 — requirePartnerType() 게이트 헬퍼 신설
양호 확인(실측). 공개 POST는 전수 rate limit 적용됨. disabled 킬스위치는 어느 계층 계정에 찍히든 전 포털에서 즉시 잠긴다(계층별 is_active는 1차 방어로 유지).

최근 활동 피드

모든 역할의 변경사항이 시간순 타임라인으로 — 문구 수정, 새 문의, 상담 생성, 협진 의뢰, 병원 리드. “코디·에이전시가 뭘 했는지”를 따라가는 화면이 여기다.

PII는 나가지 않는다

/api/admin/dashboard/overview 는 requireAdminAuth 뒤에서 건수·상태·키만 반환한다. 환자 개인정보는 응답에 담지 않는다.

새 테이블 0개

피드 소스는 감사로그가 아니라 도메인 테이블 직접(content_change_log·inquiries·consultation_sessions·cotreatment_referrals·hospital_leads). 그래서 라벨이 코드 용어가 아니라 사람 말이 된다.
