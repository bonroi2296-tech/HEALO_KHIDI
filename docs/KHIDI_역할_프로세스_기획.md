### 기존 8계층 대비 핵심 변경 3가지

1. **의사 계층 제거** — 의사는 케이스를 상시 관리하는 사람이 아니라 **예약된 화상상담 때만 참여**한다. 별도 로그인 계정·전용 포털(`/doctor`) 불필요. 의사는 ① 코디가 상담을 잡으면 **초대링크로 상담방(`/consultation/[id]`) 참여**(게스트식, 이미 구현) 또는 ② 병원 계정 안에서 본인 상담 일정 확인. → "의사"는 계정이 아니라 **병원 소속 참여자**로 존재. 원격협진(KHIDI 핵심) 기능은 유지, 구조만 단순화.
2. **해외 에이전시 ↔ 해외 의료기관 분리** — 기존엔 한 포털(`/agency`)에서 `partner_type` 라벨로만 구분. 그러나 **관여 단계가 다르다**(사후관리는 임상이라 비의료 에이전시 불가) → 별도 역할·포털로 분리. 분리하면 `/agency`엔 진짜 에이전시만 남아 **이름도 정확**해진다.
3. **해외 의료기관 = 입력(업로드) 권한** — 단순 조회가 아니라 **현지에서 경과·검사결과·영상을 업로드**해야 "지속성 있는 사후관리 체계"가 돈다(공고 ICT ④경과 f/u 정의 그대로). 환자도 본인 경과 업로드 가능.

## 4. 6대 ICT × 역할 매핑 (평가 직결 — "권한이 공고 서비스에 1:1")

| ICT 서비스 | 주관 역할 |
|---|---|
| ① 병원안내·매칭 | 코디 + AI/Human 챗 + 해외 의뢰처(의뢰) |
| ② 진료의뢰·상담 | 국내병원(의사) + 환자 + 코디 |
| ③ 예약상담 | 코디 + 국내병원 |
| ④ 경과 f/u | 국내병원(의사) + **해외 의료기관·환자(경과 업로드)** |
| ⑤ 모니터링·상담·교육 | 국내병원(의사) + 해외 의료기관 + 코디 |
| ⑥ 재이용 예약상담 | 코디 + 국내병원 (+해외 의료기관) |

> 평가 스토리: 사업화 성공가능성(35점·최대)과 연결 — 해외 의료기관의 사후 경과 업로드 → **재이용·재방문(ICT ⑥)** → 반복 매출. 역할 분리가 곧 지속 가능한 수익 구조.

## 5. URL·언어 방향

### URL (역할이 그대로 보이게, 국가코드 없음)

- `/hospital` ← 기존 `/partner` 리네임 (의사 흡수). 옛 `/partner`는 **리다이렉트**로 안 깨지게.
- `/agency` — 해외 에이전시 (이름 그대로, 분리로 정확해짐)
- `/clinic` — 해외 의료기관 (신규 분리)
- `/doctor` — **제거** (의사는 상담방 참여자)
- `/coordinator` · `/admin` · `/patient` · `/consultation/[id]` — 유지

> ❌ 국가코드(`hospital/kh` 등)·URL 로케일 prefix는 **안 쓴다.** 포털은 로그인벽 뒤라 SEO 무관 + 복잡도·링크깨짐 위험(2026-06-17 결정 `PLAN_URL_LOCALE.md` 유지). "kh"가 한국병원인지 카자흐인지 애매한 문제도 회피.

### 언어 (URL 아닌 계정 기준)

- 포털 기본언어 = **계정/역할별 자동** + 스위처. 국내(병원·코디·관리자)=한국어, 해외(에이전시·의료기관)=러·영, 환자=본인 언어.
- **선결 작업**: 해외 포털(`/agency`·`/clinic`) UI 번역(러·영) — 현재 `/agency`만 일부 번역됨, 국내 포털은 한국어 하드코딩이라 그대로 OK. (`PLAN_URL_LOCALE.md`의 "해외 협력사 포털 UI 번역" 별개 트랙 = 이것)

세부 권한은 **프로세스를 실제로 1바퀴 돌려본 뒤** 확정한다(PO 방침 — 안 돌려보고 박으면 반쪽 위험). 지금은 원칙만:

- 소프트삭제(하드삭제 금지) / 권한은 `app_metadata.role`·`hospital_users`·`agency_users` 기준(`user_metadata` 금지)

- 단계 변경 시 `case_status_history` 기록 + 연관 역할 **역방향 반영** (CASE_LIFECYCLE_MAP §3 "반쪽 금지" 체크리스트)

## 7. 기존 코드 영향 (마이그레이션 — 별도 작업, 지금 아님)

- `ACCOUNT_TIERS.md` 8계층 → 본 4그룹으로 재정의
- `/doctor` 라우트·`role=doctor` 제거 (의사 → 병원 소속 참여자 / 상담 초대링크)
- `/partner` → `/hospital` 리네임 + 리다이렉트
- `/agency` 포털을 `/agency`(에이전시) + `/clinic`(해외 의료기관)로 분리. `agency_users`/`agencies.partner_type` 구조 재검토 — 사후관리 업로드 권한은 `medical_institution`만
- 해외 의료기관·환자용 **경과 업로드 기능**(검사결과·영상 전송·저장) 신설 — 공고 ICT ④ 충족. **업로드 채널 = 전부(앱·웹·메신저)** (PO 확정 2026-06-22)
  - ✅ **1차 구현(2026-06-22)**: 해외 의료기관(`partner_type='medical_institution'`) 경과 업로드 — `progress_records` 테이블(prod 적용) + `/api/khidi/progress`(업로드/조회, 본인 케이스 권한경계) + 에이전시 포털 패널(6개 언어). 업로드 시 `case_status_history`에 경과 이벤트를 남겨 코디·에이전시 타임라인에 반영(닫힌 고리, `case_status` 불변→KPI영향0). **다음 증분**: 환자 본인 업로드(inquiry↔patient 링크), 메신저 채널, 코디 전용 검토 화면.
- 각 포털 기본언어 로직 + 해외 포털(`/agency`·`/clinic`) 러·영 번역
- **데이터 처리**: 에이전시/의료기관은 **DB 테이블 그대로 두고 화면만 분리**(`partner_type` 게이팅 — `/agency` vs `/clinic`). 테이블 분리는 안 함(현 데이터 테스트 3건, 과함). (PO 확정 2026-06-22)
