### 구조

```

    ↓
/api/inquiries/intake (DB 저장)
    ↓
✅ 저장 성공
    ↓

    ↓
SMS/알림톡 발송
```

```typescript
// ✅ 알림 실패해도 메인 로직 영향 없음
sendAdminNotification({...}).catch((err) => {
  console.error('Admin notification failed (ignored):', err);
});

// 문의 저장은 이미 성공 상태
return Response.json({ ok: true });
```

## 🔒 2. 관리자 세션 만료 정책

### 목적
- 관리자 세션이 영구 유지되지 않게
- 보안 강화 (방치된 세션 자동 만료)

### 정책

| 정책 | 기본값 | 설명 |
|------|--------|------|
| **Idle Timeout** | 60분 | 마지막 활동 후 60분 경과 시 만료 |
| **Absolute Timeout** | 7일 | 로그인 후 최대 7일 경과 시 만료 |

### 동작

```
관리자 로그인
    ↓
세션 초기화 (쿠키 설정)
- admin_login_time: 로그인 시각
- admin_last_activity: 마지막 활동
    ↓
관리자 페이지 접근 시
    ↓
Middleware 세션 검증
    ↓
만료 확인:
- Idle: 60분 넘었나?
- Absolute: 7일 넘었나?
    ↓
만료되면 → /login으로 리다이렉트
유효하면 → last_activity 갱신
```

### 적용 경로

```
/admin/**     → 세션 체크 ✅
/ops/**       → 세션 체크 ✅
/login        → 제외 (무한 리다이렉트 방지)
/api/**       → 제외 (API는 별도 인증)
```

## 🎯 사용 시나리오

### 시나리오 1: 새 문의 접수

```
1. 사용자가 Step2 제출
   ↓
2. /api/inquiries/intake
   - inquiries 테이블에 저장 ✅
   ↓

   - SMS 발송 시도
   ↓
4. 성공:
   - inquiry_events: admin_notified
   - 관리자 휴대폰에 알림 도착 📱

   - inquiry_events: admin_notify_failed
   - 로그 기록
   - 문의 저장은 성공 유지 ✅
```

---

### 시나리오 2: 관리자 세션 만료

#### Idle Timeout (60분 경과)

```
1. 관리자 로그인 (14:00)
   ↓
2. 대시보드 작업 (14:30)
   - last_activity 갱신 (14:30)
   ↓
3. 점심 식사 (1시간 방치)
   ↓
4. 돌아와서 페이지 새로고침 (15:40)
   - Middleware 체크:
     - Idle: 15:40 - 14:30 = 70분 > 60분 ❌
   - 자동 로그아웃
   - /login으로 리다이렉트
   - 메시지: "세션 만료 (비활동)"
```

#### Absolute Timeout (7일 경과)

```
1. 관리자 로그인 (1월 1일)
   ↓
2. 매일 활동 (last_activity 계속 갱신)
   ↓
3. 1월 9일 (8일 경과)
   - Middleware 체크:
     - Absolute: 8일 > 7일 ❌
   - 자동 로그아웃
   - /login으로 리다이렉트
   - 메시지: "세션 만료 (최대 기간)"
```

## 🔍 모니터링

### 알림 성공률 확인

```sql
-- 최근 24시간 알림 통계
SELECT 
  event_type,
  COUNT(*) as count
FROM inquiry_events
WHERE event_type IN ('admin_notified', 'admin_notify_failed')
  AND created_at > NOW() - INTERVAL '24 hours'
GROUP BY event_type;
```

**결과**:
```
event_type            | count
----------------------|-------
admin_notified        | 45
admin_notify_failed   | 2
```

**성공률**: 45 / (45 + 2) = **95.7%**

---

### 실패 원인 분석

```sql
SELECT 
  event_data->>'provider' as provider,
  event_data->>'error' as error,
  COUNT(*) as count
FROM inquiry_events
WHERE event_type = 'admin_notify_failed'
  AND created_at > NOW() - INTERVAL '7 days'
GROUP BY provider, error
ORDER BY count DESC;
```

```typescript
// ❌ 잘못됨
```

- 동일 inquiry_id: 1분당 1회만
- 전체: 1분당 N건 (환경변수)

#### 3. Fail-safe
```typescript
// ❌ 잘못됨 (알림 실패 시 메인 로직 막힘)
await sendAdminNotification({...});
return Response.json({ ok: true });

// ✅ 올바름 (알림 실패해도 메인 로직 영향 없음)
sendAdminNotification({...}).catch(() => {});
return Response.json({ ok: true });
```
