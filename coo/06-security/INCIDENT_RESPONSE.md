# 보안 사고 대응 절차 (Incident Response Plan)

> HEALO 플랫폼 보안 사고 발생 시 대응 매뉴얼

## 법적 의무

- **개인정보보호법 제34조**: 개인정보 유출 시 **72시간 이내** 정보주체 및 개인정보보호위원회에 신고 의무
- **정보통신망법 제27조의3**: 1,000명 이상의 개인정보 유출 시 한국인터넷진흥원(KISA)에도 신고
- 위반 시 **5년 이하 징역 또는 5,000만원 이하 벌금**

---

## 대응 단계 (5단계)

### 1단계: 탐지 (Detection)

- [ ] 이상 징후 최초 인지 시점 기록 (날짜, 시간, 발견자)
- [ ] 이상 징후 유형 분류
  - 비정상 로그인 시도
  - 대량 데이터 조회/다운로드
  - 서버 리소스 이상 사용
  - 외부 신고 접수
- [ ] Sentry 알림 / Supabase 로그 확인
- [ ] 영향 범위 초기 평가 (영향받은 사용자 수, 데이터 유형)

### 2단계: 차단 (Containment)

- [ ] 공격 경로 차단
  - 의심 IP 차단 (Vercel / Supabase 설정)
  - 침해된 API 키 즉시 무효화 및 재발급
  - 영향받은 사용자 세션 강제 만료
- [ ] Supabase RLS(Row Level Security) 정책 긴급 강화
- [ ] 필요 시 서비스 일시 중단 결정 (영향도 대비 판단)
- [ ] 관련 환경변수 즉시 교체 (.env.local 업데이트)

### 3단계: 증거 보존 (Evidence Preservation)

- [ ] 서버 로그 전체 백업 (Vercel Functions 로그)
- [ ] Supabase 감사 로그 (audit log) 내보내기
- [ ] Sentry 이벤트 로그 스냅샷 저장
- [ ] 관련 DB 테이블 스냅샷 생성
- [ ] 타임라인 문서 작성 (발생 → 탐지 → 현재까지)
- [ ] 스크린샷 및 증거 자료 별도 폴더에 보관

### 4단계: 신고 (Notification)

#### 72시간 이내 필수 조치:

- [ ] **개인정보보호위원회** 신고 (https://www.pipc.go.kr)
  - 유출 경위, 유출 항목, 시점, 대응 조치 포함
- [ ] **한국인터넷진흥원(KISA)** 신고 (1,000명 이상 시)
  - 전화: 118 / 온라인: https://www.boho.or.kr
- [ ] **정보주체(이용자) 통지**
  - 이메일 또는 앱 내 공지
  - 통지 내용: 유출 항목, 시점, 대응 조치, 피해 최소화 방법, 담당자 연락처
- [ ] 필요 시 수사기관 신고 (사이버수사대)

#### 신고 내용 필수 포함 사항:
1. 유출된 개인정보 항목
2. 유출 시점 및 경위
3. 이용자가 취할 수 있는 조치
4. 회사의 대응 조치
5. 담당부서 및 연락처

### 5단계: 복구 (Recovery)

- [ ] 취약점 근본 원인 수정 (코드 패치)
- [ ] 보안 설정 강화 적용
  - API 키 전체 교체
  - DB 접근 권한 재검토
  - RLS 정책 재검증
- [ ] 영향받은 사용자 비밀번호 강제 재설정 (필요 시)
- [ ] 서비스 정상화 확인 및 모니터링 강화 (최소 30일)
- [ ] **사후 분석 보고서 (Post-Mortem)** 작성
  - 사고 원인, 대응 과정, 개선 사항 포함
- [ ] 재발 방지 대책 수립 및 적용
